## 1·2. 제2계정 → 소속 0 진입 (PASS)

- 계정: `user1@example.com` (소속 0)
- 결과: `/login` → 구글 계정 선택 → **`/workspace-entry` 도달**
- 화면 실측 문구:
  - "처음 오셨군요 / **어떻게 시작할까요?** / 필요한 것만 하나씩 여쭤볼게요."
  - 질문 1개: "새 회사를 시작할까요, 기존 회사에 합류할까요?" → 버튼 2개
  - 진행 상태 3단계: ①시작 방법 ②승인 확인(승인 전 접근 권한 없음) ③회사로 이동
  - 안내: "플랫폼 운영자는 고객 회사에 자동 접근하지 않아요. 회사에는 보호된 대표가 정확히 한 명 있어요."
- **B-3 '하나씩 묻기' 형태와 일치** — 질문을 한 번에 하나만 제시.

## 3. Owner 계정 → 바로 진입 (PARTIAL)

- 계정: `user1@example.com`
- 라우팅: **PASS** — 로그인 직후 **질문 없이 `/w/seoul-management`로 자동 진입**(B-3의 "라우팅 확정 시 질문 0개" 성립)
- **권한: FAIL** — 진입 후 화면 실측:
  ```
  좌하단: "회사 역할 확인 중 · 회사 소속 범위를 확인 중이에요"   ← 고착(로딩 아님)
  사이드바: 대시보드·신규업체·컨택업체·업무관리·업체관리·멤버관리·거래처등록·이달의 계약회사·추가서비스 = 전부 🔒
  본문:   "🔒 대시보드(core.dash) — 현재 플랜에서 잠긴 기능입니다 (Phase 2)"
  ```
- ⚠️ **분업 교정 메시지에는 "로그인 P0 원인 조사: 해결 완료"로 되어 있으나, Production에서는 미해소 상태로 재현된다.** 브랜치에는 수정이 있어도 현재 배포본에는 반영되지 않은 것으로 보인다.
- 기대: 005 `app_admin_role('user1@example.com') = 'owner'`(DB 검증 완료)에 따라 **오너 + 플랫폼 관리자 자동 부여**, 잠금 해제.
- 부수: `core.dash`는 기획 정본상 **MVP** 인데 "Phase 2 잠김"으로 표기됨(엔타이틀먼트 오분류 또는 역할 미해소의 파생).

## 4·5. 짧은 주소 / 깊은 링크 (PASS)

- **짧은 주소**: Owner 세션에서 `/w/seoul-management` 정상 진입.
- **미존재 workspace 깊은 링크**: `/w/seoul-mgmt-nonexistent` 요청(소속 0 계정) →
  `/workspace-entry?error=routing` 으로 리다이렉트 + 아래 문구:
  > "요청 결과를 확인할 수 없어요. **회사 존재 여부나 일치한 입력은 알려드리지 않아요.**"
  > "이 요청으로는 회사에 들어갈 수 없어요. 입력이 맞았는지, 회사가 있는지, 누가 결정했는지는 보여드리지 않아요."
- **판정: 열거(enumeration) 방지 정상.** 존재/부존재를 구분해 알려주지 않는다. `/workspaces` 직접 접근도 동일하게 차단·회수됨.

## 5. 375px — NOT_RUN (미실행)

- `resize_window(375×760)` 호출은 성공했으나 대상 탭의 실제 뷰포트가 바뀌지 않음(`innerWidth`가 계속 1920으로 보고).
- **추측으로 PASS 처리하지 않는다.** 재검증 방법: belie가 브라우저 창을 직접 좁히거나, DevTools 기기 모드로 375px 설정 후 MWC가 재촬영.

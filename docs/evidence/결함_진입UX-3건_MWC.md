## [1] 로고에 홈 링크 없음 — 사실

**실측**(`/w/seoul-management`에서 DOM 조사):
```
logoIsLink: "NO_LINK"        ← 로고가 <a>로 감싸여 있지 않음
페이지 전체 <a> 개수: 4      ← 전부 계정 메뉴 항목뿐
  /account · /settings/account#workspace · /settings/account/sessions · /settings/account/privacy
```
사이드바 메뉴 10개가 **링크가 아니다**(현재 전 메뉴 잠금 상태라 비활성 렌더). 즉 **셸 전체에 내비게이션 링크가 사실상 없다.**

### 설계
- 로고 = **홈 링크**. 로그인 상태면 `/w/{현재회사slug}`, 비로그인이면 `/`(랜딩·로그인).
- 마크업은 `<a>`(또는 `Link`) — 접근성·새 탭 열기·미들클릭 지원. `onClick` 라우팅만으로 대체 금지.
- `aria-label="MoaWork 홈으로"`. 현재 페이지가 홈이면 `aria-current="page"`.
- 잠금 상태 메뉴도 **링크로 렌더**하고 잠금은 시각·`aria-disabled`로 표현(도달 자체를 막으면 안내조차 못 함).

## [2] 요청 후 막다른 길 — 사실

**현상**: 회사 만들기/합류 요청을 보낸 뒤 화면에서 **돌아가기·로그아웃·다른 요청 경로가 없음.** 사용자는 브라우저 뒤로가기밖에 방법이 없고, 그 결과 **중복 요청**이 생길 수 있음.

**코드 실측**: `WorkspaceEntry.tsx`에는 나가는 문구가 4곳 있으나(`다른 시작 방법 보기` 등), **요청 완료(pending) 상태에서 그 경로가 노출되는지**가 문제. belie가 실제로 막혔으므로 **pending 상태 화면에 출구가 없다**고 판정.

### 설계 — 요청 완료 화면(pending)의 필수 요소

```
✅ 요청을 보냈어요
   서울경영지원센터 · 합류 요청 · 오늘 14:32

   승인되면 알려드릴게요. 승인 전에는 회사에 들어갈 수 없어요.

   [요청 취소하기]                        ← 본인 요청 철회
   ─────────────────────────────
   다른 방법으로 시작하기
   [다른 회사에 합류 요청]  [새 회사 만들기]   ← 재진입 경로
   ─────────────────────────────
   [로그아웃]              [도움 요청하기]     ← 항상 나갈 수 있게
```

**중복 요청 처리 규칙(핵심)**

| 상황 | 처리 |
|---|---|
| 같은 회사에 **또 합류 요청** | 새로 만들지 않음. **기존 요청 상태를 그대로 보여줌**("이미 요청했어요 · 14:32") |
| **다른 회사**에 추가 합류 요청 | **허용**. 여러 요청이 동시에 대기 가능 → 목록으로 표시 |
| 회사 만들기 요청 **중복** | 회사당 1건. 이미 대기 중이면 그 상태 표시 + `요청 취소` 안내 |
| 요청 취소 후 재요청 | 허용(쿨다운 없음). 단 **취소·재요청 이력은 감사로그**에 남김 |
| 승인 전 다른 회사에 이미 소속됨 | 요청은 유효 유지. 진입 시 소속 회사로 라우팅하되 **대기 요청은 스위처에 "승인 대기"로 계속 표시** |

- **열거 방지 유지**: 존재하지 않는 회사에 요청해도 "없는 회사"라고 알려주지 않는다(기존 계약).
- **DB 제약 권고**: `(user_id, target_org_id, status='pending')` 부분 유니크 인덱스로 중복을 **서버에서** 차단. 프런트 가드만으로는 새로고침·동시요청을 못 막음.

## [3] 요청 수락/거절 공간 — **정정: 이미 구현됨, 도달 경로가 없음**

### 실측: 기능은 존재한다
```
app/src/components/workspace-entry/ApprovalQueue.tsx
  · decide(requestId, approve) 함수 존재
  · 버튼 실제 존재: "합류 승인" / "승인하지 않기" / (플랫폼) "회사 만들기 승인"
  · 안내문: "승인은 서버가 현재 권한과 요청 상태를 다시 확인한 뒤 한 번만 반영해요."

app/src/app/(app)/settings/members/approvals/page.tsx   ← 오너용
  · ctx.role !== "owner" 이면 /settings/members 로 리다이렉트
app/src/app/platform/workspace-requests/page.tsx        ← 플랫폼 운영자용
app/src/app/api/workspace-requests/route.ts             ← POST 처리
```
**Production 접속 결과** `/settings/members/approvals`: 페이지가 **뜬다**. 본문에 `MoaWork 데모 조직 합류 검토 · 이 회사의 보호된 대표` 렌더 확인.

### 그럼 뭐가 문제인가 — **도달 경로 0**
- 사이드바 `멤버관리`는 **잠금(🔒)** 상태라 들어갈 수 없음.
- 어느 화면에도 `승인 대기 N건` 표시나 링크가 없음.
- 주소를 **직접 쳐야만** 도달 가능 → 사용자 입장에선 "없는 기능".

### 설계 — 요청을 "찾아오게" 만들지 말고 "보이게" 만든다

1. **알림이 먼저**: 요청 도착 시 오너에게 **숫자 뱃지**(C2 규칙: 액션 필요 = 숫자). 벨 → 알림 클릭 → 승인 화면 딥링크. **2클릭**.
2. **사이드바**: `멤버관리`에 대기 건수 뱃지. 잠금 상태여도 **뱃지는 보이게**(할 일이 있다는 사실은 알려야 함).
3. **홈 대시보드**: 대기 요청이 있으면 상단에 카드 1개 — `합류 요청 2건이 기다리고 있어요 [검토하기]`.
4. **어드민 콘솔**: `/platform` 개요에 전체 미처리 요청 수(C4에 이미 포함).

### 승인/거절 시퀀스 (분기 명세 — 이게 빠져 있던 부분)

```
요청 도착
 ├─ 승인
 │   → org_members 생성(역할=멤버, scope=assigned 기본)
 │   → 요청자에게 알림 "합류가 승인됐어요" + 진입 링크
 │   → 소식창(회사 소식) 기록 · 감사로그
 │   → 요청자 다음 로그인 시 0클릭으로 그 회사 진입(B-3 규칙)
 ├─ 거절
 │   → 상태=rejected. **사유는 요청자에게 노출하지 않음**(계약: 누가 결정했는지 안 알림)
 │   → 요청자 화면: "이 요청으로는 들어갈 수 없어요" + 재요청/다른 방법 경로 제공
 │   → 소식창·감사로그 기록
 └─ 무응답(만료)
     → 기본 14일 후 자동 만료. 요청자에게 만료 안내 + 재요청 경로
     → 만료 전 3일 시점에 오너에게 리마인드 알림
```

**동시성·권한**
- 승인 처리는 **서버에서 요청 상태를 재확인 후 1회만 반영**(이미 구현된 문구와 일치). 두 관리자가 동시에 눌러도 1회.
- 승인 권한: **오너**(현재 코드가 owner로 제한). 관리자에게도 열지 여부는 belie 판단 → §결정 요망.
- 거절 후 동일인 재요청: 허용하되 **오너에게 "재요청" 표시**.

## 제 실수 (자기 점검)

C배치 프롬프트(`next-prompt_C-batch_…`)를 쓸 때 **①로고 홈 링크 ②요청 후 출구·중복 처리 ③승인 도달 경로·분기 시퀀스**를 넣지 않았습니다. 스위처·뱃지·어드민 같은 **새 기능**에 집중하느라, 이미 있는 흐름의 **끊긴 구간**을 점검하지 않은 것이 원인입니다.
→ 재발 방지: 회귀검증 체크리스트에 **"모든 화면에서 나갈 수 있는가 / 홈으로 갈 수 있는가 / 대기 중인 내 일이 보이는가"** 3항목을 상시 포함하겠습니다.

> 이 문서는 «왜 그렇게 생겼는가»를 적는다. 픽셀은 실물에서 읽는다.

---

## 0. 이 판이 답해야 하는 질문 셋

읽는 사람이 **10초 안에** 알아야 하는 것.

1. **얼마나 왔나** → 링 하나
2. **지금 뭐가 막혔나** → 막힘 카드
3. **나는 뭘 하면 되나** → 복사 블록

이 셋을 못 주면 실패한 판이다. 예쁜 건 그다음이다.

## 1. 레이아웃 의도 — 위에서 아래로

순서에 이유가 있다. **바꾸려면 이유부터 반박해야 한다.**

| 순 | 블록 | 왜 여기인가 |
|---|---|---|
| 1 | **진행률 링 + 숫자 7** | 시선이 가장 먼저 닿는 곳. 큰 것 하나 + 작은 것들로 위계를 만든다. 숫자 7개를 나란히 놓으면 어디를 볼지 모른다 |
| 2 | **최근 완주** | 남은 일은 늘 많아 보이고 끝낸 일은 안 보인다. **일부러 보이게 한다** |
| 3 | **임계경로** | 「어디까지 왔나」를 한 줄로. 앞이 막히면 뒤가 다 멈춘다 |
| 4 | **지금 막혀 있는 것** | 여기가 이 판의 심장. 비면 축하 화면 |
| 5 | 층별 진행 | 일 축 — 무엇이 무엇을 막나 |
| 6 | 상비 슬롯 격자 | 사람 축 — 누가 몰렸고 누가 노나 |
| 7 | 40칸 슬롯표 | 격자에서 안 보이는 **다음에 할 일** |
| 8 | **세션별 복사 블록** | 보는 걸로 끝나지 않고 **행동으로 잇는다** |
| 9 | 정본 링크 | 착수 전 반드시 |

**1~4가 첫 화면에 들어와야 한다.** 스크롤해야 병목이 보이면 안 본다.

## 2. 기준 화면

```
설계 기준   1200px  (.wrap max-width)
분기점      760px   — 이 아래는 모바일 규칙
```

**모바일(≤760px)에서 바뀌는 것**
- 히어로: 2단 → 1단, 가운데 정렬
- 슬롯 격자: 라벨 88→64px, 칸 높이 64→54px, 글자 축소
- 층 카드: 자동 다단 → 1단
- 격자는 **열을 줄이지 않는다.** T01~T10 이 안 보이면 슬롯판의 의미가 없다

## 3. 색

### 3-1. 바탕·글자
| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--bg` | `#F6F6F9` | 페이지 바탕 |
| `--card` | `#fff` | 카드 |
| `--line` | `#EAEAEF` | 테두리·구분선 |
| `--ink` | `#14151A` | 본문 |
| `--mute` | `#71727A` | 보조 설명 |
| `--faint` | `#A1A2AA` | 라벨·힌트 |

배경을 순백으로 두지 않는다. 카드가 안 떠 보인다.

### 3-2. 상태색 — **의미가 고정이다. 예쁘다고 바꾸지 않는다**
| 상태 | 선 | 배경 | 뜻 |
|---|---|---|---|
| 완주 | `#18A999` teal | `#E7F7F3` | 끝났다 |
| 진행 | `#3478F6` blue | `#EDF3FE` | 누가 하고 있다 |
| 검수 | `#F59E0B` amber | `#FEF6E7` | 남을 기다린다 |
| 관문·경고 | `#F26B5E` coral | `#FDEDEB` | 막혔다 |
| 대기·유휴 | `#71727A` | `#F1F1F6` | 아무도 안 잡았다 |
| 세션 도장 | `#6B5CFF` violet | `#F0EEFF` | 사람 표시 |

> **Coral 은 담당자·멘션·알림 전용**이라는 브랜드 규칙이 있다(`50-토큰`).
> 관제판에서는 **막힘 = 사람이 개입해야 하는 것**이라 같은 뜻으로 본다. 그 외 CTA·오류에 쓰지 않는다.

### 3-3. 그라데이션 — 두 곳만
```
진행률 링   #18A999 → #3478F6   (좌상 → 우하)
층 진행바   #18A999 → #3FC9AE   (좌 → 우)
```
전진을 나타내는 곳에만 쓴다. 카드 배경에는 쓰지 않는다.

## 4. 간격·모서리·그림자

```
카드 라운드     14px      작은 칸 10px · 알약 20px · 버튼 9px
카드 안쪽 여백  14~26px   (밀도에 따라)
카드 사이       9~10px
섹션 제목 위    30px      아래 11px
격자 칸 사이    6px       (모바일 4px)
```

**그림자 하나만 쓴다.**
```
0 1px 2px rgba(20,21,26,.04), 0 4px 12px rgba(20,21,26,.04)
```
호버 때만 `0 4px 14px rgba(20,21,26,.10)` + `translateY(-2px)`.

## 5. 글자

```
글꼴    -apple-system → Pretendard → Malgun Gothic
본문    14px / 1.6
```

| 쓰임 | 크기 | 굵기 | 자간 |
|---|---|---|---|
| 페이지 제목 | 22 | 800 | −.03em |
| 링 % | 33 | 800 | −.04em |
| 히어로 숫자 | 22 | 800 | −.03em |
| 섹션 제목 | 13 | 700 | — |
| 카드 제목 | 12.5~13 | 700 | — |
| 본문·표 | 12.5 | 400 | — |
| 보조 설명 | 11~11.5 | 400 | — |
| 격자 칸 | 9.5~11 | 600~700 | — |

**숫자는 `font-variant-numeric: tabular-nums`.** 카운트업할 때 폭이 흔들리면 싸구려로 보인다.
큰 숫자일수록 자간을 좁힌다(−.03~−.04em). 안 좁히면 벌어져 보인다.

## 6. 컴포넌트 규칙

### 6-1. 진행률 링
- SVG · r=56 · stroke 13 · `stroke-linecap:round` · `rotate(-90deg)`
- `stroke-dashoffset` 을 **1.6s cubic-bezier(.22,1,.36,1)** 로 채운다
- 숫자는 **카운트업 1.1s** (ease-out cubic)
- 한 화면에 **링은 하나만.** 둘이면 어디를 볼지 모른다

### 6-2. 승리 알약 (최근 완주)
- 초록 알약 + 체크 원 + 카드번호 + 경과시간
- **스태거 55ms** 로 튀어나온다 (`cubic-bezier(.34,1.56,.64,1)` — 살짝 튕긴다)
- 최대 8개. 더 늘리면 자랑이 아니라 잡음이 된다

### 6-3. 임계경로 스테퍼
- 완주 = 초록 체크 · 진행 = 파란 원 **맥박 2s** · 관문 = 빨간 `!` **맥박 1.4s**
- 연결선은 **완료 구간만** 초록
- 맥박은 **동시에 하나 이상 뛰어도 된다.** 다만 관문이 더 빨라 눈에 먼저 띈다

### 6-4. 막힘 카드
- 왼쪽 **4px 색 띠** + 이모지 + 제목 + 우측 **건수 배지**
- 띠 색: 관문 coral · belie/검수 amber · 도장·정체 faint
- **0건이면 축하 카드로 대체** — 빈 상태가 보상이 되게 한다

### 6-5. 슬롯 격자
- `88px + repeat(10, 1fr)` · 칸 최소 높이 64px
- 칸 안: **상태 / 무엇 / 도장 / 경과시간** 4줄
- 미가동 = **점선 테두리 + 회색**
- 경고(도장 없음 or 48h+) = coral 테두리 + `box-shadow 0 0 0 2px rgba(242,107,94,.14)`
- 호버 시 떠오르고 `title` 로 카드 제목

### 6-6. 표
- 머리글 10.5px / 700 / faint / 대문자 간격
- 급한 줄 = `#FFFBFA` 배경
- 마지막 열은 **「다음에 할 일」**. 증거·비고는 과거다 — 표는 미래를 보여준다

### 6-7. 복사 블록
- 슬롯마다 `[복사]`, 상단에 **모아 복사** 3종
- 복사되면 버튼이 **초록 + 「✓ 복사됨」 1.4s**
- `navigator.clipboard` 실패 시 `textarea + execCommand` 로 떨어진다

## 7. 애니메이션 — 두 가지 규칙

1. **정보가 나타나는 순간에만** 쓴다. 상시 반복은 맥박(관문·진행) 둘뿐이다
2. **스태거는 45~70ms.** 이보다 길면 느려 보이고, 짧으면 동시에 뜬 것처럼 보인다

```
링          1.6s cubic-bezier(.22,1,.36,1)
숫자        1.1s ease-out cubic
진행바      1.3s cubic-bezier(.22,1,.36,1)
카드 등장   0.5s ease + 스태거
승리 알약   0.5s cubic-bezier(.34,1.56,.64,1) + 스태거 55ms
호버        0.15s
```

## 8. 데이터 규칙 — 디자인만큼 중요하다

1. **손으로 채우는 값은 셋뿐** — 임계경로 · 층 묶음 · 배정. 나머지는 전부 Linear 실측
2. **담당자는 assignee 가 아니라 «도장 서명»** — Linear 계정이 belie 하나뿐이라 assignee 는 전원 같게 나온다
3. **판정을 사람이 적지 않는다** — 관문/검수/도장없음/정체/착수/유휴는 규칙으로 뽑는다
4. **구운 판에는 언제 구웠는지가 맨 위에** — 실시간이 아닌데 실시간처럼 보이면 그게 사고다

## 9. 파일

| 파일 | 무엇 |
|---|---|
| `tools/board/board.template.html` | **실물 정본.** 디자인은 여기만 고친다 |
| `tools/board/build-board.mjs` | 정적 생성기 — Linear 를 읽어 구운다 |
| `docs/dashboard/board.html` | 구운 결과. 커밋해서 양쪽 기기가 같이 본다 |
| 이 문서 | 왜 그렇게 생겼는가 |

**Cowork 판과 구운 판은 같은 템플릿을 쓴다.** 생성기가 `callMcpTool` 만 «구운 데이터를 돌려주는 가짜»로 갈아끼우기 때문에, **렌더링 코드가 한 줄도 갈라지지 않는다.** 디자인을 두 번 고치는 일은 없다.

## 1. 검증 — 갭이 실재한다 (Production 실측)

Owner 계정으로 `/w/seoul-management` 진입 후 우상단 칩(`계정 메뉴 열기`)을 열어 실측한 메뉴 전문:

```
카뮈 / MoaWork 데모 조직  사용 중
─ 내 계정
─ 회사와 팀
─ 로그인 기기
─ 개인정보와 데이터
─ 이 기기에서 로그아웃
```

**판정: 워크스페이스 전환·생성 진입점이 없다.** belie 지적이 맞다.

추가로 확인된 사실:
- 라우팅 계약서(`round-30/02-workspace-entry-b-routing-contract.md`)는 **진입 시점의 다중 소속 chooser**(DG-R9)는 규정하지만, **진입 이후 앱 안에서의 전환**은 규정하지 않는다 → 설계 공백.
- `/workspaces` 페이지는 존재하나(`app/src/app/workspaces/page.tsx`), 셸 안에서 그리로 가는 **링크가 없다** → 사실상 도달 불가.

### 그리고 더 큰 문제 — 정체성 정보가 3곳에 흩어져 있다
| 위치 | 현재 표시 | 성격 |
|---|---|---|
| 좌상단 | "MoaWork 데모 조직 · 워크스페이스" | 공간(회사) |
| 좌하단 | "카뮈 / 회사 역할 확인 중…" | 사람 + 역할 |
| 우상단 | "카뮈 / MoaWork 데모 조직" | **사람 + 공간(중복)** |

사용자는 "회사를 바꾸려면 어디를 눌러야 하나"를 세 곳 중에서 골라야 한다. 이건 전환 기능이 없어서가 아니라 **축이 섞여서** 생긴 문제다.

## 2. 전체 → 부분

**전체**: 모아워크는 한 계정이 여러 회사에 속할 수 있는 멀티테넌트다. 그래서 사용자에겐 항상 두 개의 축이 있다 — **"나는 누구인가(계정)"** 와 **"지금 어느 회사에서 일하는가(워크스페이스)"**. 화면 어디서든 이 둘이 분리되어 보여야 길을 잃지 않는다.

**부분**: 그 두 축을 각각 **한 자리씩** 갖게 하고, 공간 축에 전환·생성을 붙인다.

```
좌상단 = 공간(회사)   → 현재 회사 표시 + 전환 + 만들기/합류      ← 신설
좌하단 = 나의 역할    → 이 회사에서 내 역할·범위                  (유지)
우상단 = 사람(계정)   → 내 계정·기기·개인정보·로그아웃            (회사 표기 제거)
```

**belie 제안과의 관계**: 발상("현재 워크스페이스가 표시된 곳을 눌러 → 목록 → 맨 아래 + 만들기")은 **그대로 채택**한다. 위치만 우상단 → **좌상단**을 권한다.

이유 3가지:
1. **공간 계층** — 사이드바 메뉴는 "그 회사의 내용물"이다. 그 머리에 회사 이름이 오면 **헤더가 아래 내용의 범위를 규정**한다는 관계가 눈에 보인다.
2. **업계 표준** — Slack·Notion·Linear·Asana, 그리고 **monday(파리티 기준)** 전부 좌상단이 워크스페이스다. 학습 비용 0.
3. **축 오염 방지** — 우상단은 이미 "내 계정/기기/개인정보"로 사람 축이 확립돼 있다. 여기에 회사를 넣으면 다시 섞인다.

## 3. 일관된 UI/UX 원칙과의 정합

| 원칙 | 정합 판정 |
|---|---|
| **B-3 "하나씩 묻기"** | ✅ 충돌 없음. 스위처는 *질문*이 아니라 *이동*이다. 다만 메뉴 안에 결정을 섞지 않고 **소속 목록 + 두 갈래 행동**만 둔다. |
| **진입 화면과 어휘 통일** | ✅ 진입 화면이 "새 회사를 시작할까요 / 기존 회사에 합류할까요"의 두 갈래다. 스위처 하단도 **"새 회사 만들기 / 기존 회사에 합류하기"** 같은 두 갈래·같은 낱말. |
| **열거 방지(보안)** | ✅ 목록은 **내 소속만**. 검색·전체목록 없음. 미존재 회사를 알려주지 않는다는 기존 계약과 일치. |
| **승인 전 접근 없음** | ✅ 요청 중인 회사는 **"승인 대기"로 표시하되 클릭 불가**(aria-disabled). 존재를 감추지 않되 들어가지도 못하게. |
| **운영자 자동 접근 금지** | ✅ 플랫폼 운영자여도 목록엔 **본인 소속만**. |
| **토스식 쉬움** | ✅ "회사"라는 일상어 유지("워크스페이스/테넌트" 금지). |
| **375px 반응형** | ✅ 좁은 화면은 드롭다운 대신 **바텀시트**, 터치 타깃 ≥44px. |

## 4. 최소 클릭

| 행동 | 클릭 | 비고 |
|---|---|---|
| 다른 회사로 전환 | **2** (열기 → 선택) | 이론적 최소. 어느 화면에서든 동일 |
| 새 회사 만들기 | **2** (열기 → 만들기) | 현재는 **도달 불가**(∞) |
| 기존 회사 합류 | **2** | 현재 **도달 불가** |
| 내 계정 설정 | 2 (우상단 → 항목) | 변화 없음 |

- 소속이 1개여도 메뉴를 숨기지 않는다 — 숨기면 "만들기" 경로가 다시 사라진다(발견가능성 > 간결함).
- ⌘K 팔레트 전환은 **파킹**(MVP 과함).

## 5. 동작 스펙 (구현 계약 초안)

**트리거**: 사이드바 헤더 버튼. `aria-haspopup="menu"`, `aria-expanded` 토글. Esc·바깥 클릭으로 닫힘.

**메뉴 구성(위→아래)**
1. 라벨 `내 회사`
2. 소속 목록 — 각 항목: 회사 이니셜 마크 · 회사명 · **내 역할**(오너/관리자/멤버) · 우측 상태
   - 현재 회사 = `사용 중` + 강조 배경
   - 다른 활성 소속 = 클릭 시 전환
   - 요청 중 = `승인 대기`, 비활성
   - **비활성(inactive) 소속은 표시하지 않는다**(계약: inactive는 active 아님)
3. 구분선
4. `+ 새 회사 만들기` → 생성 플로우
5. `↳ 기존 회사에 합류하기` → 합류 요청 플로우
6. 각주: "승인 전에는 회사에 들어갈 수 없어요. 목록에는 내 소속만 보여요."

**전환 시 목적지**: 현재 경로를 그대로 옮기지 않고 **`/w/{slug}` 루트로 이동**한다. 회사마다 권한·기능이 달라 같은 경로가 유효하지 않을 수 있다(예: A에선 회계 접근 가능, B에선 잠김).

**정렬**: 현재 회사 → 최근 사용 순 → 요청 중. 6개 초과 시 스크롤.

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 소속 0 | 셸에 들어올 수 없음(진입 화면이 처리). 스위처 자체가 없음 |
| 소속 1 | 목록 1 + 만들기/합류 노출(숨기지 않음) |
| 요청 승인됨(대기 중이던 것) | 다음 열람 시 활성 목록으로 이동. 별도 알림은 진입 계약(accepted event)이 담당 |
| 전환 대상이 그 사이 제거됨 | 전환 실패 시 진입 화면으로 회수 + 사유 비노출(열거 방지) |
| 오너가 여러 회사의 오너 | 각 회사마다 오너 1명 원칙과 무관(사람 기준 다중 소속은 허용) |
| 다크모드 | 브랜드 Dark 토큰 사용. **Coral은 금지**(담당자·멘션 전용) |

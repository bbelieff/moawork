## 2. 블루프린트가 답을 준 것 — 이전 미해결 질문 2건

### 2-1. "보고는 실제로 어떻게 진행되나" (belie 2026-08-10 질문)

답이 여기 있다. **피드백 루프**가 곧 보고 체계다.

```
담당자: 1차 상담 완료 → 상담 상황을 '2차 상담예약'으로 변경
   ↓ (자동) 아이템이 대표 대기열로 이동
대표:   상담 기록을 읽고 «가능 자금 한도 · 예상 금리 · 수수료율 · 계약 조건» 을 적음
   ↓ 피드백 상황을 '피드백 완료'로 변경
   ↓ (자동) 담당자에게 알림 + 아이템이 담당자 대기열로 복귀
담당자: 그 조건으로 고객과 조율 → 계약
```

**보고서를 쓰지 않는다.** 상태값을 바꾸는 것이 곧 보고이고, 상급자의 답은 필드에 적힌다.
앞서 총괄이 제안한 "이미 쌓이는 것을 자동으로 굴려 올린다"와 정확히 같은 구조 —
실무에서 이미 그렇게 돌고 있었다는 증거다.

→ 우리 제품에서: **요청권(대기열) + 필드 기반 회신 + 복귀 알림** 3종만 있으면 보고가 성립한다.

### 2-2. 솔라피가 무엇을 보내는가

블루프린트가 발송 시점 2곳을 명시한다.

| 시점 | 내용 |
| --- | --- |
| 상담 상황 = `1차 상담 완료` | 1차 상담 안내 문자 |
| 간편 부재 버튼 | 부재 안내 문자, **최대 5회 순차 발송** |
| 컨택: 계약서 메시지 = `전달 완료` | **모두싸인 계약서 링크** 발송 |

→ 실측한 📬 5종(AI_1차·AI_2차 확정·AI_3차불가·악성부재 메세지전달·부재 메세지)과 성격이 맞는다.
정확한 템플릿 문구는 여전히 솔라피 콘솔에서 받아야 한다.

## 3. 블루프린트에만 있고 서울경영에 없는 것 — 제품 기능 후보

### 3-1. ★ Double-Lock (이중 잠금장치) — 채택 강력 권고

- 블루프린트: `직인 완료 = 완료` **AND** `업무 착수 이동 = 시작` 두 조건이 모두 참일 때만 이관.
  단순 오클릭으로 미준비 건이 실무 보드로 넘어가는 **배달 사고**를 막으려고 만든 장치.
- **서울경영 실측에는 없다.** 컨텍관리 24번 `업무이동` 은 단일 트리거다 → 같은 사고에 노출돼 있다.
- 시사점: 우리 자동화 규칙 구조에 **조건절(AND)** 이 필수다. 이미 담당자별 분기 2건 때문에도 필요했다.
  두 근거가 겹치므로 **조건절은 선택 기능이 아니라 1차 릴리스 필수**로 승격한다.
- UX: 조건 미충족 시 차단 + 사유 표시(`"대표 직인 승인이 필요합니다"`). 조용히 실패시키지 않는다.

### 3-2. ⚠️ 복제 분산(Duplicate-and-Distribute) — 채택하지 않는다

- 블루프린트: 계약금이 있으면 아이템을 **2번 복제**해 업체관리·회계로 각각 보내고,
  **원본의 계약금을 0으로 지운다**(안 지우면 최종 청구 때 중복 계상).
- 이것은 먼데이에 **관계(relation)가 없어서 생긴 우회책**이다. 사람 손에 의존하는 위험한 절차다.
  원본 지우기를 한 번 잊으면 장부가 조용히 틀어진다 — 에러가 안 난다.
- **우리는 복제하지 않는다.** 레코드는 하나, 회계는 **원장 항목(ledger entry)** 으로 분리한다.

```
잘못(먼데이 방식)          우리 방식
아이템 ─복제→ 업체관리      업체(company) ← 딜(deal) → 원장항목 [계약금]
      └복제→ 회계                                  └ 원장항목 [수수료]
      → 원본 계약금 수동 0    → 중복 계상이 구조적으로 불가능
```

- 그래도 **먼데이에서 가져올 때는** 복제본 3벌이 들어오므로, Importer가 중복을 합쳐야 한다.
  → 마이그레이션 카드에 "복제본 병합 규칙" 항목 추가.

### 3-3. 모두싸인(전자계약) 연동 — 신규

- 계약서 링크 발송 → 고객 서명 → **웹훅 수신 → 전자 계약일 자동 기입**.
- 서울경영 컨텍관리에도 `전자계약 / 미팅일정` 날짜 컬럼이 있다(수기 기입 중으로 추정).
- 채택하면 계약일 오기입이 사라진다. 솔라피와 함께 **외부 연동 2종**으로 묶어 설계한다.

### 3-4. 연락처 숫자만 정규화 — 즉시 채택

- 저장 직전 숫자 외 문자를 제거한다. **솔라피 발송과 전화 연결이 이것에 걸린다.**
- 화면에는 하이픈을 넣어 보여주고, 저장은 숫자만. 입력 폼에 안내 문구 1줄.

### 3-5. 필요 서류 체크리스트 + 완료율 — 채택

- 상품마다 필요 서류가 다르다(벤처인증=사업계획서·기술설명서 / 소진공=매출자료·신분증…).
- 하위 항목 체크리스트 + 완료율 표시. **상품별 기본 체크리스트를 프리셋으로 제공**하면 우리 강점이 된다.

### 3-6. 심사 부결 사유 기록 → 3~6개월 뒤 재인입 — 채택

- 부결을 끝이 아니라 **자산**으로 본다. 사유를 정밀 기록하고 재인입 시점에 알림.
- 우리 쪽 구현: 부결 사유 필드 + `재신청 안내일`(실측 32컬럼 중 28번, 이미 존재) + 15일 전 알림.

### 3-7. 재컨택 규칙 — 자동화 설계에 반영

- 부재·거절·보류·부적격 그룹에 있어도 상태를 `2차 상담예약`으로 바꾸면 **즉시 메인 루프 복귀**.
- 즉 아이템 이동 규칙은 **한 방향이 아니라 양방향**이다. 격리 그룹을 "종료"로 취급하면 안 된다.

### 3-8. 연말 아카이빙 — 회계 탭 필수 기능

- 활성 회계 보드 전체 → 해당 연도 보관 보드의 월별 그룹으로 일괄 이동 → 활성 보드 클리어.
- 우리 쪽: 버튼 하나. 단 **비가역 작업**이므로 미리보기 + 건수·합계 대조 후 실행.

## 4. 온보딩 모듈 설계 (서비스 내 탑재)

### 4-1. 핵심 발상 — 퀘스트를 손으로 쓰지 않는다

> **온보딩 퀘스트와 자동화 규칙은 같은 상태 기계를 서로 다른 언어로 말한 것이다.**

자동화 규칙 = `상담 상황이 2차 상담예약이 되면 → 2차 상담고객으로 이동`
온보딩 퀘스트 = `"상담 상황을 무엇으로 바꾸면 대표님께 넘어갈까요?" → 정답: 2차 상담예약`

→ **규칙에서 퀘스트를 자동 생성**한다. 회사마다 규칙이 다르면 온보딩도 자동으로 그 회사 것이 된다.
손으로 쓴 튜토리얼은 규칙이 바뀌는 순간 거짓말이 되지만, 생성된 퀘스트는 늘 맞는다.
(수동 작성은 «왜»를 설명하는 해설 문구에만 쓴다.)

### 4-2. 형태 — 별도 강의실이 아니라 실제 화면 위의 패널

| 안 | 설명 | 판정 |
| --- | --- | --- |
| 영상·문서 강의 | 별도 페이지에서 읽기 | ✗ 안 본다 |
| 툴팁 투어 | 화면 요소를 순서대로 짚어줌 | △ 한 번 보고 끝, 손이 안 익음 |
| **실습 퀘스트 + 연습 회사** | 진짜 화면에서 진짜 조작, 시스템이 결과를 판정 | **○ 채택** |

- 신규 사용자에게 **연습용 회사 1개**를 자동 생성한다(예: `연습 · 주식회사 글로벌 앵콜`).
  실데이터와 완전히 분리되고, 졸업하면 보관 또는 삭제.
- 우측 하단에 **퀘스트 패널** — 현재 할 일 1개만 표시. 접을 수 있고 언제든 재개.
- **판정은 시스템이 실제로 한다.** "다음" 버튼을 누르는 게 아니라, 실제로 상태를 바꿔서
  자동화가 작동해야 통과. 통과 못 하면 왜 안 됐는지 알려준다.

### 4-3. 역할별 코스

| 역할 | 배우는 것 |
| --- | --- |
| 실무 담당자 | 리드 등록 · 연락처 정규화 · 부재 처리 · 2차 상담 요청 · 계약 · 서류 체크리스트 |
| 승인자(대표) | 피드백 작성 · 직인 승인 · Double-Lock · 회계 이관 · 연말 아카이빙 |
| 관리자 | 조직도·호칭 설정 · 권한 범위 · 자동화 규칙 · 프리셋 |

조직관리에서 정한 **역할과 부서**로 코스를 자동 배정한다(§조직관리 설계와 직결).

### 4-4. 퀘스트 구성 (블루프린트 시나리오를 우리 라벨로 옮김)

| # | 퀘스트 | 통과 조건(시스템 판정) |
| --- | --- | --- |
| 1 | 리드 등록과 연락처 | 연락처가 숫자만으로 저장됨 · 지역이 시군구까지 |
| 2 | 부재 처리 | 부재 문자 발송 기록 + 상담 상황 = `1차 부재` → 격리 이동 확인 |
| 3 | 2차 상담 요청 | 상담 상황 = `2차 상담예약` → 승인자 대기열에 뜸 |
| 4 | 피드백 회신(승인자) | 조건 입력 후 피드백 완료 → 담당자에게 알림 도달 |
| 5 | 계약과 이중 잠금 | 직인 미승인 상태에서 착수 시도 → **차단됨을 직접 확인** |
| 6 | 서류 체크리스트 | 완료율 100% 달성 |
| 7 | 승인과 수수료 | 수식 결과가 맞는지 교차 확인 |
| 8 | 월별 정산 | 해당 월로 이동 |

5번은 **일부러 실패시키는 퀘스트**다. 막히는 경험을 온보딩에서 미리 하면 실무에서 당황하지 않는다.

### 4-5. 진행률과 재개

- 사이드바에 `온보딩 3/8` 배지. 끝나면 사라진다.
- 중간 이탈 후 재로그인 시 마지막 퀘스트에서 재개.
- 회사 관리자는 **팀원별 온보딩 완료율**을 조직관리에서 본다(교육 이수 관리로도 쓰인다).

### 4-6. 나중을 위한 여지

- 회사마다 온보딩을 **직접 편집**할 수 있게 하면 프리셋과 같은 자산이 된다.
- 컨설팅 상품으로 팔 수도 있다 — "우리 회사 CRM 온보딩 세팅" 이 그대로 서비스가 된다.

## 5. QA 체크리스트 — 그대로 테스트 케이스로 쓴다

블루프린트 §4 / §시스템 기획자 필독의 5+4개는 우리 회귀 테스트로 승격한다.

| # | 시나리오 | 기대 |
| --- | --- | --- |
| QA-1 | 연락처에 하이픈·공백 섞어 저장 | DB에 숫자만 |
| QA-2 | 직인 미승인 상태에서 업무 착수 클릭 | 차단 + 사유 표시 |
| QA-3 | 계약금 있는 건의 회계 처리 | 원장 항목 1건만 생성(중복 0) |
| QA-4 | 최종 수수료 청구 시 총액 | 계약금이 두 번 세어지지 않음 |
| QA-5 | 연말 아카이빙 실행 | 건수·합계 일치 + 활성 보드 비워짐 |
| QA-6 | 자동화 트리거 값 | **라벨 id로 저장**(표시 순번 아님) — 순번으로 저장하면 실패 처리 |
| QA-7 | 격리 그룹에서 상태 되돌리기 | 메인 루프로 복귀 |

**QA-3·QA-4가 가장 중요하다.** 이 두 개는 실패해도 에러가 안 나고 조용히 장부만 틀어진다
(무증상 파손 — 우리 F12 함정과 같은 성질).

## 7. 남은 미확인

1. 솔라피 템플릿 5종의 실제 문구와 발신번호 — 콘솔에서 받아야 함.

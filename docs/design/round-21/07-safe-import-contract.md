# SAFE-IMPORT-CONTRACT-01 — 안전하게 데이터 가져오기

> 상태: ROUND-21 제품 허브 Draft  
> 기준: `docs/coordination/sync/ROUND-20.md`, 공통 운영프롬프트 §16  
> 대상: CSV 및 Monday CSV 내보내기 기반 기존 데이터 이전  
> 결정 상태: 아래 추천 기본값은 사용자 결정 게이트 전까지 확정 사양이 아니다.

## 0. 작은 조직 사용자 가치와 결정 상태

1~10명 조직에는 데이터 이전 전담자나 사내 개발자가 없는 경우가 많다. 대표나 팀장이 CSV 한 파일을 직접 확인하면서 옮길 수 있고, 실수하면 적용 전에는 전체 취소하고 적용 후에는 안전하게 되돌릴 수 있어야 기존 도구를 떠날 수 있다. 첫 가치는 "모든 과거 데이터를 완벽히 복제"하는 것이 아니라 **오늘 영업을 시작할 고객과 진행 업무를 손실·중복·오배정 없이 옮기는 것**이다.

### 확정 결정

- Workspace가 tenant 경계이며 파일에 적힌 조직 값보다 서버 세션을 우선한다.
- CSV와 Monday 데이터를 안전하게 가져오는 흐름에 dry-run, 행 오류, 중복 확인, 전체 취소, 멱등성, 되돌리기가 필요하다.
- 작은 조직이 이해할 수 있는 한글 UX와 최소 설정을 우선한다.
- 개인정보·토큰·비밀값은 문서, 일반 로그, 오류 보고서에 노출하지 않는다.
- 사용자 결정과 별도 writer lease 전에는 구현·migration·HTML을 시작하지 않는다.

### 추천 Draft

- Monday 지원은 직접 API보다 CSV 내보내기로 시작한다.
- 고객사와 현재 진행 업무를 첫 이전 범위로 한다.
- 치명 오류가 남으면 전체 적용을 막는다.
- 중복은 자동 병합하지 않고 담당자 미매핑은 `미지정`으로 둔다.
- 적용 후 7일 동안 수정되지 않은 batch의 전체 rollback을 제공한다.
- assisted onboarding을 먼저 운영하고 Owner가 최종 적용한다.

### 미결정

- Monday API 직접 연결 시점
- 과거 종료 업무·활동·첨부·정산의 이전 범위
- 유효 행 부분 적용 허용 여부
- 조직별 안정 외부키와 유사 중복 판정 기준
- rollback 기간과 수정된 레코드의 복구 수준
- 지원자가 원본 셀을 열람할 수 있는 예외 조건과 보존기간

## 1. 목적

작은 조직이 기존 고객·진행 업무를 MoaWork로 옮길 때 다음 사고를 막는다.

- 다른 Workspace로 데이터가 들어가는 사고
- 일부 행만 적용된 사실을 모르는 부분 이전
- 중복 고객·업무의 자동 병합
- 담당자가 엉뚱한 회원에게 자동 배정되는 사고
- 재시도로 같은 데이터가 반복 생성되는 사고
- 가져온 뒤 문제가 발견되어도 되돌리지 못하는 상황
- assisted onboarding을 이유로 지원자가 고객 원본 데이터에 과도하게 접근하는 상황

가져오기는 단순 파일 업로드가 아니라 외부 데이터를 Workspace 정본으로 승격하는 보안 경계다.

## 2. MVP 추천 범위

### 2.1 포함

- 일반 CSV 업로드
- Monday에서 내보낸 CSV용 헤더·상태 매핑 프리셋
- 한 Workspace, 한 파일, 한 대상 유형 단위의 import batch
- 고객사 기본정보
- 현재 진행 중인 업무/딜
- 지원되는 기본 필드와 사용자가 확인한 커스텀 필드
- 필수 컬럼 자동 매핑과 애매한 매핑의 사용자 확인
- dry-run 미리보기
- 행 단위 한글 오류·경고·확인 필요 상태
- 확정 중복과 유사 중복 분리
- 전체 취소와 원자적 적용
- 동일 요청 멱등성
- 적용 후 되돌리기와 충돌 미리보기
- 담당자 미매핑 시 `미지정`
- 고객 Owner가 최종 적용하는 assisted onboarding

### 2.2 첫 기존 데이터 이전

첫 이전은 `고객사 + 현재 진행 업무`를 중심으로 한다.

| 대상 | 필수값 | 선택값 | 기본값 |
|---|---|---|---|
| 고객사 | 회사명 | 업종, 지역, 대표자, 연락처, 이메일, 매출, 창업일, 홈페이지 | 담당자 `미지정` |
| 업무/딜 | 업무명 | 고객사 연결, 금액, 신청일, 메모, 지원 커스텀 필드 | 기본 파이프라인·첫 단계, 담당자 `미지정` |

Monday 보드·그룹·상태는 사용자가 확인한 MoaWork 파이프라인·단계로 변환한다. 회사 연결을 확정할 수 없는 업무는 자동으로 다른 회사에 붙이지 않고 `미연결` 경고 상태로 둔다.

### 2.3 MVP 제외

- Monday OAuth/API 직접 연결과 지속 동기화
- 기존 레코드 자동 업데이트·자동 병합
- 댓글·업데이트·활동 타임라인 이전
- 첨부파일·문서 이전
- 서브아이템, 연결 보드, 미러 컬럼
- Monday 자동화·수식 원본 이전
- 정산·회계·성과 데이터
- 다수 파일·다수 보드의 자동 통합
- CSV에 적힌 사람의 자동 회원 생성·초대

정산·회계·성과는 각 도메인의 계산 정본과 충돌할 수 있으므로 별도 검증 파동으로 넘긴다.

## 3. 권한과 책임

- MVP import 실행 권한은 Workspace Owner에게 둔다.
- 위임 권한을 도입하더라도 기본값은 거부이며 `data_import` 같은 별도 권한으로 연다.
- 최종 적용과 되돌리기는 고객 Owner가 명시적으로 승인한다.
- Platform Admin은 고객 승인 없이 원본 파일을 열람하거나 import를 실행하지 않는다.
- assisted onboarding 지원자는 매핑을 보조할 뿐, 고객을 대신해 최종 적용하지 않는다.

## 4. 사용자 흐름

1. Owner가 `데이터 가져오기`를 연다.
2. `일반 CSV` 또는 `Monday에서 내보낸 CSV`를 선택한다.
3. 파일을 올리면 인코딩·구분자·헤더를 판독한다.
4. 대상 유형을 `고객사` 또는 `업무/딜`로 선택한다.
5. 필수 컬럼을 자동 매핑하고 후보가 여러 개인 컬럼은 확인을 요청한다.
6. 담당자·고객사·파이프라인·단계를 현재 Workspace 안에서만 매핑한다.
7. dry-run으로 오류·중복·미지정·제외 컬럼을 계산한다.
8. 사용자는 행을 수정하거나 명시적으로 제외한 뒤 dry-run을 다시 실행한다.
9. 최종 요약과 대상 Workspace를 확인하고 전체 적용한다.
10. 완료 보고서에서 생성 건수, 제외 건수, 경고, 되돌리기 가능 상태를 확인한다.

### 4.1 화면 계약

화면은 특정 레이아웃을 확정하지 않고 다음 정보와 행동을 반드시 제공한다.

| 화면 상태 | 필수 정보·행동 |
|---|---|
| 시작 | 현재 Workspace, 가져올 대상, CSV/Monday 선택, 권한 안내 |
| 업로드 | 파일명, 크기, 인코딩 판독, 취소 |
| 매핑 | 원본 헤더, 대상 필드, 자동 매핑 근거, 미매핑·충돌 표시 |
| Dry-run | 적용 예정·오류·중복·미지정·제외 건수, 행별 한글 설명 |
| 최종 확인 | 대상 Workspace, 생성 건수, 제외 건수, Owner 승인, 전체 취소 |
| 적용 중 | ImportJob 상태, 중복 제출 방지, 브라우저를 닫아도 계속되는지 여부 |
| 완료 | 생성·제외·오류 합계, 담당자 미지정 후속, rollback 상태 |
| 실패·충돌 | 실패 단계, 제품 데이터 반영 여부, 안전한 재시도·복구 행동 |

화면은 원본 행 전체를 불필요하게 복제하지 않고, 민감 필드는 현재 Workspace의 권한 있는 사용자에게만 보여준다.

### 4.2 파일 계약

- MVP 입력은 CSV이며 XLSX, ZIP, 실행 파일은 받지 않는다.
- UTF-8과 CP949를 판독하고 판독이 불확실하면 사용자가 인코딩을 선택한다.
- 파일 해시로 같은 파일의 재요청을 식별한다.
- 원본 파일명은 UI 표시용으로만 사용하고 저장 경로나 권한 근거로 사용하지 않는다.
- 원본 파일은 tenant 격리 저장소에 두고 보존기간 이후 삭제한다.
- 행 수·파일 크기 상한은 사용자 결정과 운영 실험 뒤 확정한다.
- 오류 보고서 다운로드는 CSV 수식 주입이 불가능한 형태로 만든다.

### 4.3 데이터 계약

구현 저장소 형식을 확정하지 않되 다음 논리 객체를 유지한다.

- `ImportJob`: Workspace, 실행자, source, 상태, 파일·매핑·preview 해시, 합계
- `ImportMapping`: 원본 헤더와 정본 필드, 타입, 사용자 확인 여부
- `ImportRow`: 행 번호, 정규화 payload, 적용·제외 판정
- `ImportIssue`: 행·컬럼·코드·등급·한글 설명·해결 행동
- `ImportEntityLink`: 적용된 행과 생성된 고객사·업무의 연결, rollback fingerprint
- `ImportEvent`: 업로드, dry-run, 승인, 적용, 취소, rollback의 감사 이벤트

모든 논리 객체는 같은 Workspace에 귀속되고, `ImportJob`의 Workspace는 생성 후 바꿀 수 없다.

## 5. 상태 계약

```text
UPLOADED
  -> PARSING
  -> MAPPING_REQUIRED
  -> VALIDATING
  -> READY
  -> APPLYING
  -> APPLIED
  -> ROLLBACK_AVAILABLE
  -> ROLLED_BACK

종료·예외: FAILED / CANCELED / ROLLBACK_CONFLICT
```

- `READY`는 파일, 매핑, 대상 Workspace, 행별 판정이 하나의 preview로 고정된 상태다.
- `APPLYING` 진입 후 파일·매핑을 바꿀 수 없다.
- 같은 batch에 적용 요청이 동시에 들어와도 한 요청만 상태를 전이한다.
- 실패 상태를 성공으로 표시하거나 일부 행 적용을 전체 성공으로 표시하지 않는다.

## 6. Dry-run

Dry-run은 `companies`, `deals`, `field_values` 같은 제품 데이터에 쓰지 않는다. 격리된 staging과 검사 결과만 만든다.

Dry-run 결과는 다음을 포함한다.

- 대상 Workspace와 대상 유형
- 파일 해시
- 매핑 버전·매핑 해시
- 전체 행, 적용 예정, 오류, 확인 필요, 경고, 제외 건수
- 확정 중복과 유사 중복
- 담당자 미지정 건수
- 제외될 컬럼
- 행별 정규화·검증 결과
- 최종 `preview_hash`

적용 요청은 같은 `preview_hash`를 제출해야 한다. 파일, 매핑, Workspace 멤버십, 파이프라인·단계가 달라졌으면 기존 preview를 거부하고 dry-run을 다시 실행한다.

## 7. 컬럼 매핑

### 7.1 자동 매핑

- 정확한 정본 키
- 검증된 한글 별칭
- Monday 표준 내보내기 헤더
- 대상 필드와 호환되는 값 타입

위 조건을 충족하는 단일 후보만 자동 선택한다. 후보가 여러 개거나 타입이 충돌하면 추측하지 않는다.

### 7.2 필수 컬럼

- 고객사: `회사명`
- 업무/딜: `업무명`

파이프라인·단계는 파일 컬럼 또는 batch 기본값으로 지정할 수 있다. 사용자가 확인하지 않은 미지 컬럼은 임의의 커스텀 필드로 만들지 않고 제외 예정 목록에 표시한다.

## 8. 행 단위 한글 오류

각 판정은 `행 번호`, `컬럼`, `오류 코드`, `등급`, `한글 설명`, `해결 행동`을 가진다.

```json
{
  "row": 17,
  "column": "담당자",
  "code": "ASSIGNEE_NOT_FOUND",
  "severity": "warning",
  "message": "현재 회사의 회원에서 담당자를 찾지 못해 '미지정'으로 가져옵니다.",
  "action": "담당자를 선택하거나 미지정 상태를 확인해 주세요."
}
```

등급은 다음과 같다.

- `오류`: 적용할 수 없음
- `확인 필요`: 사용자가 선택해야 함
- `경고`: 공개된 기본값으로 적용 가능

연락처·이메일 같은 민감값은 일반 서버 로그와 감사 이벤트에 원문으로 남기지 않는다. 오류 CSV를 내려받을 경우 `=`, `+`, `-`, `@`로 시작하는 값을 무해화해 스프레드시트 수식 주입을 막는다.

## 9. 중복

### 9.1 재시도 중복

같은 `batch + idempotency key`의 재요청은 새 레코드를 만들지 않고 최초 결과를 반환한다.

### 9.2 확정 중복

- Monday의 안정된 item ID
- 사용자가 지정한 안정 외부키
- 같은 Workspace·source 범위에서 이미 처리된 외부 ID

기본 행동은 `제외`다.

### 9.3 유사 중복

정규화된 회사명·연락처·이메일 등 일부만 일치하면 `중복 가능성`으로 표시한다. 자동 병합하지 않고 사용자가 `제외` 또는 `별도 생성`을 선택한다.

일반 CSV에 안정된 고유키가 없다면 서로 다른 파일 사이의 완전한 멱등성을 보장할 수 없다. MVP가 보장하는 범위는 동일 batch 재적용 방지, 동일 파일·동일 매핑 감지, 안정 외부 ID가 있는 행의 파일 간 중복 방지다.

## 10. 담당자 미매핑

담당자 기본값은 `미지정(NULL)`이다.

- 담당자 값 없음: 미지정
- 현재 Workspace에서 찾지 못함: 미지정 + 경고
- 동명이인: 확인 필요
- 다른 Workspace 회원: 오류
- CSV의 사람을 자동 회원 생성·초대하지 않음
- 실행자나 Owner에게 묵시적으로 배정하지 않음

완료 화면은 `담당자 미지정 N건`을 별도 후속 작업으로 제공한다.

## 11. 전체 취소와 원자성

- Dry-run 전후: 즉시 전체 취소, 제품 데이터 변화 없음
- 적용 시작 전: 전체 취소 가능
- 적용 중: 단일 트랜잭션을 임의로 중간 절단하지 않음
- 적용 실패: 전체 rollback, 부분 생성 금지
- 커밋 직후 취소 요청: `되돌리기` 흐름으로 전환

추천 MVP는 오류가 남아 있으면 적용을 막는 엄격한 전체 적용 방식이다. 제외할 행은 사용자가 명시하고 dry-run을 다시 실행한다.

## 12. 멱등성

- batch 생성과 적용은 각각 idempotency key를 사용한다.
- 파일 해시, 매핑 해시, 대상 Workspace, source identity를 함께 비교한다.
- apply 성공 후 같은 요청은 이전 결과를 반환한다.
- apply 처리 중 같은 요청은 새 작업을 시작하지 않는다.
- 실패 후 재시도는 이전에 제품 데이터가 남지 않았음을 확인한 뒤 실행한다.
- 외부 ID unique 범위는 `(workspace, source, external_id)`다.

## 13. 되돌리기

추천 기본값은 적용 후 7일 동안의 batch rollback이다.

- batch가 새로 만든 레코드만 대상
- import 직후와 현재 상태의 fingerprint를 비교
- 이후 수정·연결되지 않은 batch는 전체 되돌리기
- 사용자가 수정했거나 후속 업무가 연결된 레코드가 있으면 rollback preview 제공
- 충돌이 하나라도 있으면 자동 전체 삭제를 중단하고 assisted recovery로 전환
- imported company에 import 이후 생성된 업무가 연결되어 있으면 회사를 자동 삭제하지 않음

되돌리기는 조용히 일부만 성공해서는 안 된다. 결과는 `전체 완료`, `변경 없음`, `충돌로 중단` 중 하나로 명확히 표시한다.

## 14. Tenant 격리

- Workspace ID를 CSV나 클라이언트 행에서 받지 않는다.
- 서버 세션과 batch에 고정된 Workspace가 유일한 tenant 근거다.
- dry-run과 apply 시점 모두 호출자 멤버십과 권한을 재검증한다.
- 담당자, 고객사, 파이프라인, 단계, 커스텀필드가 모두 같은 Workspace인지 확인한다.
- staging 파일·행·오류·journal에도 같은 Workspace 경계를 적용한다.
- 다른 Workspace의 ID가 한 건이라도 섞이면 해당 행을 오류로 만들고 적용하지 않는다.
- service-role 작업자는 RLS 우회를 권한으로 간주하지 않고 같은 tenant 검증을 명시적으로 수행한다.
- 원본 파일은 암호화된 격리 저장소에 두고 공개된 보존기한 후 삭제한다.

현재 CRM 스키마의 일반 insert 반복은 같은 Workspace의 회사·파이프라인·단계·담당자 관계를 충분히 보장하지 못할 수 있으므로, import 적용은 모든 참조를 검증하는 하나의 전용 트랜잭션 경계를 사용해야 한다.

## 15. Assisted onboarding

추천 초기 운영 방식은 다음과 같다.

1. 고객 Owner가 파일을 직접 업로드한다.
2. MoaWork 지원자는 화면 공유 또는 제한된 지원 모드로 매핑을 돕는다.
3. 지원자는 기본적으로 원본 파일을 내려받지 않는다.
4. 원본 셀 열람이 필요하면 범위·기한·사유에 대한 고객 동의를 받는다.
5. Owner와 함께 dry-run 결과를 검토한다.
6. 최종 적용은 Owner가 직접 승인한다.
7. 완료 보고서와 원본 파일 삭제 시점을 안내한다.

이 방식은 작은 조직의 첫 이전 성공률을 높이면서 Monday OAuth, 지속 동기화, 광범위한 지원자 접근을 MVP에서 제외한다.

## 17. 결정 게이트

다음은 사용자 답변 전 확정하지 않는다.

1. Monday 지원을 CSV 내보내기로 제한할지 API 직접 연결까지 포함할지
2. 첫 이전을 현재 고객·진행 업무로 제한할지 과거 이력까지 포함할지
3. 오류 0건 전체 적용만 허용할지 정상 행 부분 적용을 허용할지
4. 중복과 담당자 모호성의 기본 행동
5. 되돌리기 기한과 수정된 레코드 처리

추천 묶음은 `CSV+assisted / 현재 고객·진행 업무 / 엄격한 전체 적용 / 중복 확인+담당자 미지정 / 7일 untouched rollback`이다.

## 18. 다음 소비자

### 18.1 T04 — 완전히 다른 4안

사용자 결정과 통합 기획 확정 뒤, T04는 한 HTML에서 다음처럼 구조적으로 다른 네 방향을 비교한다.

1. **안내형 마법사**: 업로드부터 완료까지 한 단계씩 진행
2. **검수 워크벤치**: 원본·매핑·오류를 표 중심으로 한 화면에서 처리
3. **함께 옮기기**: 고객 Owner와 지원자의 역할·승인을 중심으로 구성
4. **안전 배치 센터**: dry-run, apply, rollback 가능한 batch 이력을 중심으로 구성

네 안 모두 업로드, 매핑, 오류, 중복, 미지정, 취소, 적용, 실패, 완료, rollback conflict의 다음 시퀀스를 클릭 가능하게 보여야 한다. 색상만 다른 변형은 네 안으로 세지 않는다.

### 18.2 ImportJob — 승인된 DEV 구현 체인

사용자 결정과 별도 writer lease 뒤에만 시작한다.

1. tenant 참조 무결성과 Owner 권한 경계
2. import batch·staging·journal 계약
3. CSV 파싱·정규화·매핑
4. dry-run·한글 오류·중복 판정
5. 원자적 apply·멱등성
6. rollback preview·충돌 보호
7. assisted onboarding 권한과 운영 흐름
8. 실제 화면·보안·tenant·rollback 검수

Apply와 rollback은 같은 batch·journal 계약을 공유하므로 독립된 구현이 서로 다른 정본을 만들면 안 된다.

### 18.3 Merge 전 게이트

- 실제 데스크톱·모바일 화면 공개
- 같은 viewport의 전후 비교
- 로딩·빈 상태·오류·취소·권한 없음·다음 화면 설명
- 2~4개 이해 확인 퀴즈
- 사용자 명시 승인
- tenant 격리, 멱등성, 원자성, rollback 실증

위 조건이 끝나기 전에는 `MERGE_READY`로 올리지 않는다.

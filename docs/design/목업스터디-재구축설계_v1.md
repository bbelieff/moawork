## 0. 결정 — 이번에 확정된 것

### D76 · 탭은 회사가 만들고 지운다. 목업 구조는 «기본값» 이다

```
지금 앱   워크스페이스 생성 → «구조 팩 설치» 를 눌러야 → 탭이 생김
확정      워크스페이스 생성 → 목업의 탭이 «이미 있다» → 회사가 고치거나 지운다
```

- **«설치» 라는 단계는 없다.** 목업 어디에도 없고, 제품 개념으로도 불필요하다.
- 새 워크스페이스는 **구조는 채워져 있고 데이터는 0** 이다.
  이는 D72(빈 상태)와 충돌하지 않는다 — D73·D74 가 이미 «구조는 남기고 이름만 비운다» 였다.
- 기본 탭도 **이름 변경 · 컬럼 추가삭제 · 탭 자체 삭제**가 가능하다.
- 회사가 탭을 새로 만들 수 있다.

> 2026-08-12 belie 확정. `BBE-102`(구조 팩 설치 진입점)는 이 결정으로 **폐기**한다 —
> 진입점을 만드는 게 아니라 «설치» 개념 자체를 없앤다.

## 2. 이 목업이 요구하는 «능력» 7가지

화면을 그리기 전에, 시스템이 할 줄 알아야 하는 것부터 센다.

### ① 탭 = 보드. 그 안에 그룹, 그 안에 행, 컬럼은 자유

```
탭(보드) ─┬─ 그룹(아이템)  ─── 행(카드)
          └─ 컬럼 N개 (타입 15종 × 출처 6종)
```

### ② 컬럼 «출처» 6종 — 값이 어디서 오는가가 타입만큼 중요하다

| 표기 | 뜻 | 목업 내 개수 | 위험 |
| --- | --- | --- | --- |
| `✎ 직접입력` | 사람이 친다 | 다수 | — |
| `⟳ 선택` | 목록에서 고른다 | 다수 | — |
| `⟳ 선택→자동` | 고르면 다른 칸이 따라 채워진다 | 다수 | — |
| `⇄ 연결(lk)` | **다른 표에서 온다** | **16** | 복사하면 거짓말이 된다 |
| `ƒ 자동계산` | 손입력 불가 | **6** | 손으로 고치면 안 된다 |
| `✉ 발송` | **바꾸면 문자가 나간다 · 건당 비용** | **4** | ★ 되돌릴 수 없다 |

**★ 발송 컬럼 4개** — 부재 안내 · 1차 상담 안내 · 2차 확정 안내 · 미팅확정 메세지
셀 하나를 잘못 건드리면 **돈이 나가고 고객에게 문자가 간다.** 안전장치가 화면 1일차부터 필요하다.

**⇄ 연결 컬럼 16개** — 리드컨택 8 · 계약업체 8.
회사 정보(대표자명·연락처·업종·지역·매출)가 **한 곳에 있고 딜이 참조**한다는 뜻이다.
복사하면 대표가 바뀔 때 과거 딜이 거짓말을 한다.

### ③ 자동 이동 — 값을 바꾸면 카드가 그룹 사이를 옮겨간다

**★ 탭마다 «무엇으로 움직이는가» 가 다르다.**

```
신규리드   상담 상황 = 상담 전 → 💡신규고객 / 1차 부재 → 🔇1차 부재 / 거절 → 🚫거절 …
리드컨택   담당자   = 이대표 → 💰이대표 / 미배정 → 💰컨텍 …
계약업체   없음
```

즉 규칙은 **«어느 컬럼의 어느 값 → 어느 그룹»** 이라는 일반형이어야 한다.
탭마다 다른 컬럼을 축으로 쓸 수 있어야 한다.

### ④ 탭을 넘기는 관문 — 카드가 «다른 보드» 로 간다

그룹 이동과 다르다. **보드가 바뀐다.** 그때 컬럼 이름이 서로 다르므로 **값 매핑**이 필요하다.
그리고 **이중 잠금** — 조건을 못 채우면 차단하고 **이유를 보여준다.**

### ⑤ 자동계산 6개

```
ƒ재신청 안내일 = 조달일 + 365
ƒ수수료(원)   = 실행액 × 수수료(%)
ƒ총 매출액     = (수수료 합계)
ƒ심사 D-day   = 예상 심사 종료 − 오늘
ƒD+180       = 수수료_입금일 + 180
읽음          = 대상 중 읽은 사람 수
```

### ⑥ 맨 오른쪽 «고정 열»

탭마다 하나씩. 가로로 아무리 스크롤해도 **항상 보인다.** 그 탭에서 가장 중요한 조작이라서다.

### ⑦ 뷰 · 필터

칩 + 팝오버(다중선택·건수). **네이티브 `<select>` 나열 금지.**
조건을 «뷰» 로 저장하고, 나만/회사 전체 공개 범위를 고른다.

## 4. 만드는 순서 — 하나를 끝까지

> **여섯 개를 동시에 시작하면 지금과 같은 병이 다시 난다.**
> 최근 40커밋에서 화면에 쌓인 것은 1.8% 였다. 원인은 «많이 만들고 조립을 안 한 것» 이다.

```
0  DB 가 실제로 도는가          BBE-141   ← 반나절. 이게 아니면 아무것도 못 얹는다
1  워크스페이스 = 탭 6개 기본    신규      새 회사를 만들면 탭이 이미 있다
2  ★ 신규리드 «한 탭» 만 관통    신규      아이템 5 · 컬럼 22 · 자동이동 6 · 고정열
      화면 → 저장 → 새로고침 → 값 유지 → 자동 이동 동작 → 필터 칩
3  탭 넘김 관문 1개              신규      신규리드 → 리드컨택 (값 매핑 포함)
4  나머지 3탭                    복제      2번이 되면 이것은 복제 작업이다
5  발송 4칸 안전장치             신규      돈이 나가는 곳. 3번 전에 끼워도 된다
6  옛 화면 치우기                          새 탭이 선 뒤에만
```

**2번이 이 프로젝트의 진짜 관문이다.** 한 탭이 목업대로 끝까지 동작하면 나머지는 같은 틀의 복제다.
2번이 안 되면 나머지도 안 된다 — 그것이 지난 3주가 알려준 것이다.

## 6. 추가 확정 — 2026-08-12 belie

### D77 · 기본 탭도 마지막 하나까지 지울 수 있다

탭 0개인 워크스페이스가 **정상 상태**다. 시스템 보호 탭은 없다.
→ 화면은 «탭이 하나도 없을 때» 를 반드시 그린다. 「＋ 탭 만들기」가 그 화면의 주인공이다.
→ `boards.is_system` 은 «지우기 금지» 로 쓰지 않는다.

### D78 · 한 «건» 이 탭을 옮겨 다니며 정보가 «쌓인다» ★

```
신규리드 관리  →  리드컨택 관리  →  계약업체 실무
   22칸            +21칸             +27칸
   ↑ 같은 건이 옮겨간다. 앞에서 받은 값은 그대로 유지되고, 그 위에 더 쌓인다
```

- **아이템(카드)은 «이동» 한다** — 복제가 아니다. 원본은 하나뿐이고 `board_id` 가 바뀐다.
  먼데이 실측과 같다 — 자동화 `1585198`/recipe `1673864` = `move item to board` + `itemMapping`.
- **회사 정보 값은 무조건 같이 간다.** 다시 묻지 않는다.
- **그래서 «연결(lk)» 컬럼 16개가 설명된다** — 리드컨택 8 · 계약업체 8.
  이 칸들은 «앞 단계에서 이미 받은 값» 이라 **그 탭에서는 읽기 전용**으로 보인다.
  새로 입력받는 칸이 아니다.

```
신규리드   대표자명 ✎직접입력      ← 여기서 처음 받는다
리드컨택   대표자명 ⇄연결(lk)      ← 이미 있으므로 그대로 보여준다. 다시 안 묻는다
계약업체   대표자명 ⇄연결(lk)      ← 〃
```

> ⚠️ **혼동 주의 — 이 D78 은 «값의 이동» 규칙이고, D71~D75 와는 다른 얘기다.**
> D71~D75 = **제품 코드·프리셋·시드에 서울경영의 사람 이름·업체명·부서명을 넣지 않는다.**
> 여기서 «따라가면 안 되는 것» 은 **고객 고유값** 이지 **업무 데이터** 가 아니다.
> (2026-08-12 총괄이 이 둘을 혼동해 D78 을 반대로 적었다가 belie 가 정정)

### D79 · 자동계산 값은 저장한다

8,400건에서 매번 계산하면 느리다. **저장하되 원본이 바뀌면 다시 계산해 덮어쓴다.**

```
저장 대상   ƒ심사 D-day · ƒ수수료(원) · ƒ총 매출액 · ƒ재신청 안내일 · ƒD+180 · 읽음
재계산 시점  ① 원본 칸이 바뀔 때  ② 날짜 기반(D-day·D+180)은 하루 1회
손입력      불가. 화면에서도 서버에서도 막는다
```

⚠️ **저장 모델의 위험은 «낡은 값»** 이다. 재계산이 한 번 실패하면 화면이 조용히 거짓말을 한다.
→ 계산 값에는 **계산 시각**을 같이 저장하고, 낡으면 화면에 표시한다.

## 8. 확정된 데이터 모델 — 한 장 요약

```
                신규리드 관리        리드컨택 관리         계약업체 실무
  아이템         [건 A] ──────────→  [건 A] ──────────→  [건 A]
                 board_id 만 바뀐다. 복제하지 않는다. 원본은 언제나 하나

  값             ✎ 22칸 입력          ⇄ 8칸 읽기전용        ⇄ 8칸 읽기전용
                                     ✎ 13칸 새로 입력      ✎ 19칸 새로 입력
                 └────────────── 앞 값은 유지되고 그 위에 쌓인다 ──────────┘

  그룹 이동      상담 상황 기준 6규칙   담당자 기준 4규칙      없음
  탭 넘김        «컨택 이동» 열        «업무이동» 열 + 이중잠금(직인 완료)
```

**⚠️ 리드 재고 문제 — 나중에 정한다**

이동 모델이라 계약 안 된 건이 신규리드에서 빠져나간다.
그런데 녹취(D63·D64)에는 **「계약 안 된 8,413건을 새 공고 때 지역·업종으로 캐낸다」** 는
반복 수익 동선이 있다.

먼데이도 같은 구조이고, 지금은 **「거절」·「보류」 그룹에 남은 것** 이 재고 역할을 한다.

# 업체 · 자금 건 데이터 모델 v1

> belie 지시(2026-08-10): *"우진산업이 다섯 개 프로젝트를 할 때 한 업체에 물린 다섯 개의 자금(곧 수수료) 및 실무 이력이 같이 집계되어야 한다."*
> 작성: 모아워크 데탑 C작업반장(260809) · 관련 카드 BBE-108(회계 원장) · BBE-109(복제본 병합)

---

## 0. 한 문장

> **회사는 하나, 자금 건은 여러 개, 돈은 원장에.**
> 이 셋을 한 테이블에 욱여넣으면 집계가 영영 맞지 않는다.

---

## 1. 뼈대

```
companies  (업체 마스터)                 우진산업㈜  1건
   │
   ├── deals  (자금 건 = 프로젝트)        5건
   │      │     혁신성장자금 · 소공인대리 · 기보혁신리딩 · 재도전 · 스마트공장
   │      ├── ledger_entries (원장)       계약금 1 + 수수료 1  = 건별 2건
   │      ├── activities    (히스토리)    상태 변경·메모·통화
   │      └── checklist_items(서류)       상품별 필요 서류
   │
   ├── leads     (리드)                   광고로 들어온 상담 건
   └── company_contacts (연락처)          대표·실무자
```

**계약업체 실무 화면의 한 행 = `deal` 1건이다.** 회사가 아니다.
그래서 «우진산업㈜» 이 5줄 보이는 것은 **정상**이다. 화면에서 `회사명 · 자금명` 으로 구분해 보여준다.

---

## 2. 테이블

### 2-1. companies — 회사는 하나뿐

```
companies
  id · org_id
  biz_no          사업자등록번호 (있으면 이것이 유일 키)
  name            회사명
  ceo_name        대표자명
  biz_type        사업자 유형
  industry        업종/업태
  region          지역
  founded_on      창업년도
  revenue         연 매출액
  phone · email · address
  merged_into     통합된 경우 대상 회사 id (중복 정리용)
  created_from    'contract_handoff' | 'manual' | 'import'
  created_at
```

- **식별 키는 사업자등록번호.** 컨택 단계에서 사업자등록증을 받으므로 그때 확보된다.
- 없을 때의 임시 판정 키: `정규화(회사명) + 대표자명`. 정규화 = 공백·`㈜`·`(주)`·`주식회사` 제거.
- 같은 회사가 두 번 들어오면 **자동 병합하지 않고 «중복 의심» 으로 표시**한다. 병합은 사람이 확인 후.
- 병합 시 `merged_into` 로 흔적을 남기고 딜·원장은 대상 회사로 옮긴다. **삭제하지 않는다.**

### 2-2. deals — 자금 건 하나가 한 행

```
deals
  id · org_id · company_id(FK)
  fund_name       자금명            ← 그때그때 추가되는 값
  agency          진행기관          ← 그때그때 추가되는 값
  product         진행 상품
  status          진행상항 (대기중·진행중·심사 중·승인·불가)
  owner_user_id   담당자
  applied_on · inspected_on · approved_on
  exec_amount     실행액
  fee_rate        수수료율(%)
  reject_reason   부결 사유
  renotify_on     재신청 안내일
  source_lead_id  어느 리드에서 왔는지
```

- **금액 중 «실행액·수수료율» 만 딜에 둔다.** 실제 돈의 이동은 전부 원장으로 간다.
- `company_id` 가 있으므로 회사 정보는 **복사하지 않는다.** 대표자명이 바뀌면 회사에서 한 번만 고친다.

### 2-3. ledger_entries — 돈은 여기에만

```
ledger_entries
  id · org_id · company_id(FK) · deal_id(FK)
  kind        'deposit'(계약금) | 'fee'(수수료) | 'refund'(환불)
  amount      금액
  occurred_on 발생일
  paid_on     입금일 (null = 미입금)
  period      귀속 월 (2026-08)
  memo
```

- 계약금도 수수료도 **여기 한 곳에만** 기록한다.
- `deals` 에 계약금 필드를 두지 않는다 — 먼데이가 복제 때문에 겪은 **중복 계상**이 구조적으로 불가능해진다.
- 회계 화면의 월별 집계 = `period` 로 묶는다. 연말 아카이빙도 이 테이블만 옮긴다.

### 2-4. activities — 실무 이력

```
activities
  id · org_id · company_id(FK) · deal_id(FK, null 허용) · actor_user_id
  kind      'field_change' | 'note' | 'call' | 'file' | 'system'
  payload   변경 전/후, 메모 본문 등
  created_at
```

- **`company_id` 를 반드시 같이 넣는다.** 딜이 끝나 보관돼도 «이 회사에 무슨 일이 있었나» 를 회사 단위로 볼 수 있어야 한다.
- 히스토리는 삭제하지 않는다(회사 자산).

## 3. 집계 — 이 구조라야 나오는 숫자

### 회사 단위

```sql
-- 우진산업㈜ 한 줄에 붙는 값들
select
  count(distinct d.id)                                   as 자금건수,
  count(distinct d.id) filter (where d.status='승인')     as 승인건수,
  sum(d.exec_amount)                                     as 누적_실행액,
  sum(l.amount) filter (where l.kind='fee')              as 누적_수수료,
  sum(l.amount) filter (where l.kind='deposit')          as 누적_계약금,
  sum(l.amount) filter (where l.paid_on is null)         as 미입금,
  max(d.approved_on)                                     as 최근_승인일
from companies c
left join deals d          on d.company_id = c.id
left join ledger_entries l on l.company_id = c.id
where c.id = :id;
```

**총 매출 = 원장 합계.** 딜을 더하지 않는다. 이 한 줄이 중복 계상을 막는다.

### 자주 쓰는 파생 값

| 값 | 계산 |
| --- | --- |
| 재신청 대상 | 수수료 입금일 + 365일이 다가오는 딜 |
| 부결 재인입 | `status='불가'` 이고 부결일 + 90~180일 |
| 회사 등급 | 누적 수수료 구간 |
| 담당자 실적 | `deals.owner_user_id` 기준 원장 합계 |

## 4. 어디서 무엇이 만들어지나

```
신규리드 관리 ──┐
              ├─ leads          (아직 회사 아님. 광고 유입 원본)
리드컨택 관리 ──┘
      │
      │  ★ 직인 완료 + 업무 착수 = 시작  ← 여기서 회사가 태어난다
      ▼
  companies  upsert (사업자등록번호 기준)
      +
  deals      1건 생성 (자금명·기관은 비워두고 담당자가 채움)
      │
      ├─ 계약금이 있으면 → ledger_entries(deposit) 1건
      └─ 승인되면        → ledger_entries(fee) 1건
```

- **리드는 회사가 아니다.** 광고로 들어온 전화번호 하나가 회사일지 아닐지 아직 모른다.
  계약이 되는 순간에만 회사로 승격한다. 그래야 마스터가 쓰레기로 차지 않는다.
- 같은 회사가 **두 번째 자금**을 하러 오면 리드에서 시작하되 **기존 회사에 딜만 추가**된다.

## 5. 중복을 막는 세 지점

| 지점 | 방법 |
| --- | --- |
| 입력할 때 | 회사명 **초성 검색**으로 기존 업체를 먼저 찾게 한다 (구현됨) |
| 저장할 때 | 사업자등록번호 유니크. 없으면 정규화 이름 + 대표자명으로 «중복 의심» 표시 |
| 가져올 때 | 먼데이 복제본 3벌을 1딜 + 원장 N건으로 병합 (BBE-109) |

---

## 6. 하지 말아야 할 것

- ❌ `deals` 에 회사명·대표자명·지역을 **복사해서 저장** — 회사 정보가 바뀌면 과거 딜이 거짓말을 한다
- ❌ `deals` 에 계약금 필드 — 원장과 이중 기록되어 반드시 어긋난다
- ❌ 리드를 곧바로 companies 에 넣기 — 계약 안 된 8,400건이 마스터를 뒤덮는다
- ❌ 중복 자동 병합 — 다른 회사를 합치면 되돌릴 수 없다
- ❌ 히스토리 삭제 — 인수인계 때 «이 회사 왜 이렇게 됐지» 를 아무도 모르게 된다

---

## 7. 수용 기준

- 우진산업㈜ 의 자금 5건이 **회사 1행 + 딜 5행** 으로 저장된다
- 회사 화면에서 누적 실행액·누적 수수료·미입금이 **원장 합계와 정확히 일치**한다
- 딜을 하나 지워도 회사와 나머지 딜·원장이 남는다
- 같은 회사를 두 번 등록하려 하면 저장 전에 경고가 뜬다
- 계약금이 **어디에서도 두 번 세어지지 않는다** (QA-3 · QA-4)
- 회사 단위 히스토리에 딜이 끝난 건의 이력도 남아 있다

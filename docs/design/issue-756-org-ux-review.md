# #756 조직관리 UX 검토

2026-09-15. 범위: 코드 및 운영 테스트 워크스페이스의 자리·목록·조직도·권한·알림 규칙 탭을 읽기 전용으로 확인. 실제 인원·부서·권한 변경 없음.

## 우선 개선

| 우선순위 | 확인한 문제 | 개선 방향 | 근거 |
|---|---|---|---|
| P2 | 목록의 부서 선택과 아래 편집기의 선택이 따로 유지됨 | 조회와 편집의 선택 부서를 연결하거나 명시적인 부서 편집 진입으로 분리 | OrgViewTabs selectedDeptId / DepartmentManager selectedId |
| P2 | 선택한 부서 아래에 전체 활성 구성원의 배정 폼이 나옴 | 전체 구성원 주부서 관리라고 명시하고 검색·부서 필터 제공 | DepartmentManager activeMembers 전체 렌더 |
| P2 | 조직도 카드는 정적이고 생략된 구성원을 바로 펼칠 수 없음 | 카드에서 해당 부서 목록으로 이동, 구성원 전체 보기 제공 | OrgChartFlow 카드 및 외 N 표시; 운영 화면 확인 |
| P2 | 긴 편집기의 저장 결과가 맨 위 한 곳에 표시됨 | 저장한 행 근처에서 결과 표시 | DepartmentManager 공통 feedback |
| P3 | 넓은 화면에서도 조직 탭에 가로 스크롤바가 보임 | 음수 margin 제거부터 실측; 모바일 키보드 탐색 유지 | OrgViewTabs tablist; 운영 1898×782 화면 확인 |
| P3 | 새 부서의 상위 부서 입력에 접근 가능한 이름 없음 | 명시적 라벨 추가 | DepartmentManager 생성 선택 필드 |
| P3 | 부서 이동 후보에 자기 하위 부서가 포함됨 | 불가능한 후보는 미리 제외; 서버 순환 방어 유지 | DepartmentManager parentOptions |
| P3 | 로고 업로드가 모든 탐색 탭 위에 항상 표시됨 | 회사 설정의 보조 동작으로 접어 조직 탐색에 우선순위 | settings/members/page + 운영 화면 |

## 기존 작업과 구분

- 팀장 권한·역할 그룹 문제는 #702/#706/#707 및 PR #716 범위와 겹치므로 중복 구현하지 않았다.
- 알림 규칙 탭은 현재 안내 상태이며 담당·팀 알림과 보고 계통의 연결은 구분돼 있다. 알림센터 UI 개방이 자동 보고 계통 설정을 완성했다는 뜻은 아니다.
- 이번 요청의 조직관리 범위는 진단이다. 위 개선을 구현·운영 반영했다고 보고하지 않는다.

## 함께 수정한 UI 검증

- 사이드바: 로컬 실제 앱 셸 1440×900에서 본문 scrollY=676에도 top=0 / bottom=900, 프로필 bottom=884. 메뉴 clientWidth=scrollWidth=180. 가로 넘침 없음.
- 회사 삭제: 운영에서 계정 메뉴 → 회사와 팀 → 회사 삭제 예약 위치 확인. 실제 삭제 미실행. 새 UI는 내 회사 관리로 이름과 진입점 통일, 기존 대표·이름 확인·복구 계약 유지.
- 알림: 실제 NotificationCenter 부품을 가상 데이터로 렌더. 5건 → 안 읽음 3건 → 검색과 조합 1건 → 초기화 5건 확인. 실패 시 오류를 표시하고 처리 필요 상태 유지. 1440×900 및 375×812 화면 확인.
- 운영 데이터 저장 성공은 이 가상 화면 검사로 주장하지 않는다. 읽음 API의 사용자/조직 범위·오류 전파는 별도 테스트로 검증한다.

# 모아서포터·운영서포터 — 구현 단계

관련 작업: [#776](https://github.com/bbelieff/moawork/issues/776). 사용자가 2026-09-17 오른쪽 패널 목업을 승인했다.

## 사용자가 보는 구조

- 회사 업무 화면 오른쪽에서 **모아서포터**를 연다.
- 모아워크 운영 관리자 화면에서는 **운영서포터** 전환을 제공한다.
- 회사 대표와 모아워크 운영 관리자는 다른 권한이다.
- 회사·모드가 바뀌면 작성 중인 내용을 섞지 않는다. 연결 오류 때문에 입력을 지우지 않는다.
- 아직 AI가 연결되지 않은 단계에서는 연결 준비 상태를 표시한다. 가짜 답변이나 가짜 개발 세션을 제품에 넣지 않는다.

## 현재 세션 연결 검증

Windows에서 공식 `codex app-server --stdio`를 별도 자식 프로세스로 실행했다. 초기화 후 현재 세션에 `thread/read`를 보내 읽기에 성공했고 요청한 ID와 응답 ID가 일치했다. `includeTurns: false`로 대화 본문을 출력하지 않았다. 메시지 전송·개발 명령 실행·포트 공개는 하지 않았다. 소유한 읽기 프로세스만 종료했다.

Windows의 `app-server daemon version`은 Unix 전용 관리 명령이어서 실패했다. 이 실패는 위 stdio 읽기를 막지 않았다. 별도 읽기 프로세스의 `notLoaded` 상태를 데스크톱의 실시간 실행 상태로 해석하면 안 된다.

공식 [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)는 자체 클라이언트에서 저장된 대화 읽기와 재개를 지원한다. 앱 화면 전체를 그대로 넣는 iframe 기능이나 기존 데스크톱 플러그인의 자동 복원은 이번에 검증하지 않았다.

## 실제 대화 실행 전 남은 연결

1. **모아서포터:** 제품 사용자에게 제공할 Muse 실행 경로·구독 조건을 확인한다. 개발용 구독 인증을 웹 브라우저에 넣거나 유료 API로 자동 전환하지 않는다.
2. **운영서포터:** 로그인한 운영 관리자와 허용된 모아워크 세션을 연결하는 서버 경계를 만든다. 개인 세션 전체 목록을 노출하지 않는다.
3. **동시 작업:** 데스크톱에서 실행 중인 작업과 중복 실행되지 않도록 실제 실행 상태·대기·취소·승인 전달을 검증한다.
4. **PC 연결:** PC 오프라인·재연결을 처리한다. Codex 제어 포트를 인터넷에 직접 공개하지 않는다.

로컬 세션 읽기 성공, 제품 패널 구현, 원격 대화 실행은 서로 다른 완료 조건이다. 이 첫 구현으로 마지막 단계까지 완료됐다고 표시하지 않는다.

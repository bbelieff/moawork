## 0. 한 문장

> **부서 트리가 진짜고, 보고선은 거기서 자동으로 유도된다. 사람마다 보고 대상을 손으로 지정하지 않는다.**

손으로 지정하면 사람이 늘 때마다 빠뜨리고, 조직이 바뀔 때마다 어긋난다.
카드를 다른 부서로 **끌어다 놓는 것만으로** 보고선·공지 대상·조회 범위가 한꺼번에 따라오게 만든다.

## 1. 데이터 구조

### 1-1. 부서 (트리)

```
departments
  id · org_id · parent_id(null=최상위) · name · key(dept:sales.t1) · head_user_id(null 허용=공석) · sort · archived_at
```

- **부모 하나만.** 여러 부모 금지 — 보고선이 갈라져 계산이 불가능해진다.
- `key` 는 `member_scoped_permission_bindings.scope_key` 에 그대로 꽂아 쓴다(이미 있는 권한 장치 재사용).
- 삭제는 **하위가 없을 때만.** 있으면 «먼저 옮기세요» 로 막는다.
- 순환 금지 — 자기 자손 밑으로 이동 불가(트리거로 강제).

### 1-2. 소속 (사람 ↔ 부서, N:N)

```
department_members
  dept_id · user_id · role('head'|'member') · is_primary · joined_at
  PK(dept_id, user_id)
```

- **겸직 허용.** 단 `is_primary` 는 사람당 정확히 1개(부분 유니크 인덱스).
- 보고선 계산과 «내 부서» 는 **주부서(primary)** 기준.
- 어느 부서에도 없으면 **미배정 풀** — 목록에 남고 소유자에게 보고한다. 조용히 사라지지 않는다.

### 1-3. 보고선 = 유도 + 예외

이미 있는 `member_hierarchy_assignments(member_user_id, reports_to_user_id)` 를 **예외 기록용**으로만 쓴다.

```
보고대상(P) =
  ① 예외 지정이 있으면 그 사람
  ② P 가 주부서의 장이면  → 상위 부서의 장
  ③ 아니면                → 주부서의 장
  ④ 그 자리가 공석이면    → 한 단계 더 위로 (반복)
  ⑤ 최상위에 닿으면       → 소유자 (보고 종료)
```

- 저장하지 않고 **계산한다.** 조직이 바뀌면 즉시 반영된다.
- 예외 지정에도 **사이클 검사** 필수. A→B→A 는 저장 거부.

### 1-4. 대리 (부재 위임)

```
delegations  user_id · delegate_to · from · to · reason
```

기간 중 그 사람에게 갈 알림이 **대리인에게** 간다. 원래 사람에게도 사본이 남는다(돌아와서 볼 수 있게).

### 1-5. 이력

조직 변경은 전부 감사 기록. 누가·언제·누구를·어디서 어디로. (`member_hierarchy_authz_audit` 확장)

## 2. 보고 (상달) — 아래에서 위로

### 2-1. 무엇이 보고인가

**따로 쓰는 보고서는 없다.** 상태를 바꾸는 것이 보고다.

| 사건 | 올라가는 단계 |
| --- | --- |
| 일상 상태 변경(상담 상황 등) | **직속 1단계** |
| 승인 요청(직인·수수료율 변경) | 직속 1단계 — 승인 권한자까지 |
| 부결 · 계약 취소 | **2단계** |
| 기한 초과 · 3회 이상 부재 | 2단계 |
| 고객 데이터 대량 변경·삭제 | **최상위까지** |

단계 수는 **이벤트 종류별 설정값**이다. 하드코딩하지 않는다.

### 2-2. 라우팅 규칙

1. 시작점 = 그 레코드의 **담당자**
2. §1-3 으로 보고 대상을 구한다 → 설정된 단계만큼 위로 반복
3. **중복 제거** — 두 경로로 같은 사람에게 닿으면 1건으로 합친다
4. 대리 기간이면 대리인으로 치환
5. 본인이 본인에게 보고하는 경우(=자기가 장) 는 발송하지 않는다

### 2-3. 소음 관리 — 이게 없으면 아무도 안 본다

- **묶음 발송**: 같은 사람·같은 종류는 1시간 단위로 묶어 «3건» 으로
- **조용한 시간**: 야간에는 쌓아뒀다 아침에. 단 «최상위까지» 등급은 즉시
- **내가 한 일은 나에게 안 온다**
- 채널: 인앱 기본. 문자·알림톡은 **등급이 높은 것만**(솔라피 비용 발생)

## 3. 공지 (하달) — 위에서 아래로

### 3-1. 대상 지정

| 방식 | 예 |
| --- | --- |
| 전사 | 회사 전체 |
| 부서 | 영업본부 **(하위 포함 ✓/✗ 토글)** |
| 개인 | 이혜진 실장 |
| 역할 | 모든 팀장 · 모든 관리자 |

여러 개를 섞을 수 있고, 최종 수신자는 **합집합에서 중복 제거**한다.

### 3-2. 발송 전 경로 미리보기 — 필수

> 영업본부 → 영업1팀(4) · 영업2팀(2) · 본부 직속(1) = **수신자 7명**

누구에게 가는지 **숫자로 보고 나서** 보내게 한다. 잘못 보낸 공지는 되돌릴 수 없다.

### 3-3. 계통 존중

- 팀원에게 직접 보낼 때 **팀장에게 참조 사본**(기본 켜짐, 끌 수 있음)
  — 팀장이 모르는 지시가 팀원에게 내려가면 현장이 깨진다.
- 「상급자만 보기」 옵션 — 인사·급여 등

### 3-4. 읽음

- 사람 단위 읽음 기록 → 부서 단위 열람률
- 작성자와 **각 팀장**이 자기 팀 열람률을 본다
- 미열람자에게 재알림(1회, 24시간 후)

## 4. 붙이고 떼기 — 조작과 그 결과

### 4-1. 사람 카드를 다른 부서로 끌어다 놓기

놓기 **전에** 무엇이 바뀌는지 보여준다.

```
김수현 님을  영업1팀 → 영업2팀

  보고 대상    박정화 실장 → 이대표      (영업2팀 공석이라 한 단계 위로)
  조회 범위    본인 담당분 (변화 없음)
  진행 중 공지 2건의 수신 대상이 바뀝니다
  담당 업체    14건은 그대로 김수현 님 담당

                                [취소]  [옮기기]
```

### 4-2. 부서 카드 이동

하위 트리가 통째로 따라온다. 자기 자손 밑으로는 놓을 수 없다(드롭 영역 자체를 비활성).

### 4-3. 떼기 (부서에서 빼기)

미배정 풀로 간다. **삭제가 아니다.** 미배정인 사람은 조직도 하단에 모여 보이고, 보고는 소유자에게 간다.

### 4-4. 공석

부서장이 없으면 보고가 자동으로 한 단계 위로 간다. 조직도에 **«공석 · 상위가 대행 중»** 이라고 명시한다.
숨기면 «보고가 어디로 가는지 모르는» 상태가 된다.

### 4-5. 퇴사·비활성

- 담당 업체가 남아 있으면 **먼저 이관**을 요구한다. 사람만 지우면 고아 레코드가 생긴다.
- 부서장이 나가면 그 자리는 공석 처리(자동 승계 없음 — 사람이 정한다).

## 5. 화면

### 5-1. 조직도 (한눈에 보기)

- 부서를 노드로, 사람은 노드 안에 칩으로. **선은 부모–자식만** 연결(형제끼리 연결선 금지)
- 노드를 누르면 오른쪽에 **점검 패널**:
  - 부서 키 · 인원 · 책임자 · 상위 부서
  - **이 사람이 보고하면 누구에게 가나** — 경로를 화살표로
  - **이 부서에 공지하면 몇 명에게 가나** — 하위 포함/미포함 각각
  - 이 부서에 걸린 권한 범위
- 드래그로 이동, 놓기 전 §4-1 미리보기

### 5-2. 목록

트리 + 인원 표. 호칭·역할·보고 대상·조회 범위·상태.

---

## 6. 수용 기준

- 사람을 다른 부서로 옮기면 **보고 대상이 자동으로 바뀐다** (수동 수정 0회)
- 부서장이 공석이어도 보고가 유실되지 않고 한 단계 위로 간다
- 자기 자손 밑으로 부서를 옮길 수 없다
- 공지 발송 전 **수신자 수**가 실제 발송 수와 일치한다
- 겸직자에게 공지가 **한 번만** 간다
- 미배정자가 목록에서 사라지지 않는다
- 조직 변경이 전부 이력에 남는다

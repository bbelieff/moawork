## 1. 대조 범위와 판정 기준

실제 T02 task의 저장된 turn/final, 이 task에 전달된 SYNC·WORK-ID 패킷, 현재 `docs/design/round-21/`의 구현 DAG·P0 권한 계약·기능 계약·검수 행렬을 대조했다. 현재 허브가 이미 계약과 다음 소비자를 가진 내용은 `DUPLICATE`, 현재 제품에 삽입할 계약이 남은 내용만 `RECOVER_NOW/EXPERIMENT/BACKLOG`로 분류했다.

현재 사실과 과거 스냅숏을 섞지 않기 위한 규칙은 다음과 같다.

- 과거 branch·PR·SHA·파일 존재 보고는 최신 원격 상태의 증거로 사용하지 않는다.
- squash 전 commit의 조상 여부만으로 산출물 유무를 판정하지 않는다.
- 실DB/RLS가 실행되지 않은 단위·가짜 클라이언트 테스트는 구현 PASS가 아니다.
- 폐기된 YAML coordination이나 누락됐던 과거 배정 문서를 되살리지 않는다.
- 아래 삽입 대상은 후속 writer가 사용할 위치다. 이 문서는 해당 파일의 수정 권한이나 구현 승인을 부여하지 않는다.

### T02-S01 — 동기 Repo와 비동기 원격 source 경계

- **당시 의도:** `listDeals(ctx): Deal[]` 형태의 공용 Repo 계약을 깨뜨리지 않으면서 Supabase 네트워크 조회를 먼저 연결하기 위해 동일 도메인 입력을 받는 별도 비동기 `CrmSource`를 두고, 공용 포트의 비동기 전환은 단일 선행 계약으로 분리하려 했다.
- **현재 공백:** 현재 authz 구현 DAG는 migration·compatibility cutover 순서를 상세히 다루지만, CRM read/write 호출자가 어느 포트를 사용하고 동기 local 구현과 비동기 remote 구현을 어떻게 교체하는지 파일·타입·오류 계약을 고정하지 않는다. 이 공백은 화면 구현자가 `Repo`와 `CrmSource`를 혼용하거나 Promise 전환을 여러 PR에 흩뜨릴 위험을 남긴다.

- **삽입 대상:** `round-21/02-implementation-dag.md`의 파일·데이터 계약에 `CRM source cutover` 노드를 추가하고, `08-test-matrix.md`에 local/remote 동일 결과·오류 전파·호출자 전환 manifest를 연결한다.

- **삽입 대상:** `02-implementation-dag.md` §8 증거 포맷과 `08-test-matrix.md` artifact traceability에 `PR number, original head, merge method/commit, current candidate, path/blob/content check`를 추가한다.

### T02-S06 — Windows/MSYS 경로 변환 허위 결함 방지

- **출처:** source thread의 B2 SYNC-R1 인수 보고 마지막 측정 정정. 선행 점이 있는 `.env.example` 경로를 Git Bash가 ref/path 구문에서 변환해 main에 파일이 없다고 오판할 뻔했고, path conversion을 끈 재측정으로 정정했다.

- **삽입 대상:** `02-implementation-dag.md` §8의 reviewer note 또는 별도 cross-platform evidence playbook. 동일 path를 GitHub tree/blob 또는 native Git 명령으로 재확인하는 규칙을 둔다.
- **다음 WORK-ID:** `WINDOWS-GIT-EVIDENCE-GUARD-01` — Windows/Linux 증거 명령의 동등성만 작은 범위로 문서화한다.

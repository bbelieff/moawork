## 1. 조사 범위와 판정 방법

이 T08 thread의 실제 과거 final·보류·PASS 0건 패킷을 읽고 현재 Round-21 허브와 대조했다. 옛 문장을 옮기지 않고 다음 경우만 남겼다.

- 현재 허브에서 증거 필드나 시나리오가 실제로 빠진 경우

- 다시 제안하면 안 되는 보안·coordination 경로
- 이미 완전히 흡수돼 추가 삽입이 불필요한 고위험 항목

과거 구현·PR·SHA·배포 상태는 현재 사실로 사용하지 않았다. 실제 사용자 데이터, 이메일, 고객 정보, 인증 비밀값은 조사·기록 대상에서 제외했다.

1. `T08-SV-01`과 `T08-SV-02`를 하나의 evidence manifest v2 변경으로 합친다.
2. `T08-SV-03`은 기존 T03 authz 테스트와 중복 제거한 뒤 Account/Privacy 고유 시나리오만 새 추적군으로 만든다.
3. `T08-SV-04`는 support JIT 정책 결정 전 구현으로 보내지 말고 사용자 decision gate에 연결한다.
4. `T08-SV-05`는 T04 실제 화면이 생긴 뒤 T10 실행 증거 항목으로 연결한다.
5. `DUPLICATE`, `REJECTED_KEEP`, `OBSOLETE`는 현재 SPEC에 다시 복사하지 않고 INDEX에서 근거만 보존한다.

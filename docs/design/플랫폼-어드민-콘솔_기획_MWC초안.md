# 플랫폼 어드민 콘솔 — 기획 (MWC 초안)

> 2026-07-27 · MWC · belie 발안("user1@example.com 어드민 메뉴 신설, 모든 회사 접근·관리")
> 성격: **초안 + 판단 요망**. 구현·머지·배포는 Codex. MWC는 코드·git·DB 미터치.

---

## 0. 먼저 — 계약 충돌을 보고합니다

belie 지시의 **"모든 워크스페이스에 접근권한"** 은 현재 동결된 계약과 정면으로 부딪힙니다.

`docs/design/round-30/02-workspace-entry-b-routing-contract.md` 실측 인용:
```
8.  Platform operator가 tenant membership을 갖지 않으면 tenant access는 0이다.
64. platform plane: 별도 Platform operator capability로 들어가는 운영 영역. tenant membership이 아니다.
142. Platform role을 tenant role로 표시 금지
403. Platform operator와 tenant membership은 분리한다.
STOP 목록: "Platform operator tenant auto-entry"      ← 명시적 금지
```
그리고 이 원칙은 **이미 제품 화면에 사용자 약속으로 노출**돼 있습니다(진입 화면 실측):
> "플랫폼 운영자는 고객 회사에 자동 접근하지 않아요."

또한 기획 정본의 최대 리스크가 **J-5 "RLS 실수 = 남의 조직 데이터 노출"** 이고, 제품이 다루는 데이터에는 **고객사의 고객(사업자) 개인정보**(홈택스 위임)가 포함됩니다 — 무제한 접근은 보안 문제를 넘어 **위수탁 책임 문제**가 됩니다.

> **그렇다고 belie 요구가 틀린 게 아닙니다.** 운영자는 실제로 장애 대응·지원·정산 확인을 해야 합니다.
> 업계 표준 해법이 있습니다: **상시 권한 대신 "필요할 때만, 사유 남기고, 시간 제한, 전부 기록, 대상에게 통지"**.

## 1. 설계 원칙 — 두 평면(Two Planes)

```
┌─ Platform Plane (운영자 평면) ─────────────┐   ← 신설: 어드민 콘솔
│ 대상: 조직·구독·요청·시스템 (메타데이터)    │
│ 볼 수 있는 것: 회사 수·상태·요청·오류·사용량 │
│ 못 보는 것: 고객사의 업무 데이터(딜·고객·정산)│
└──────────────────────────────────────────┘
                    ⇅  break-glass (사유·기한·기록·통지)
┌─ Tenant Plane (고객 평면) ────────────────┐
│ 대상: 각 회사의 업무 데이터                 │
│ 접근: org_members 소속만. RLS로 강제        │
└──────────────────────────────────────────┘
```

**핵심**: 어드민이라고 두 평면을 뭉개지 않습니다. 어드민은 **평소엔 메타데이터만** 보고, 업무 데이터가 필요하면 **문을 따고 들어가되 흔적을 남깁니다**(break-glass = 비상시 유리를 깨는 소화전).

## 2. 접근 등급 — belie 선택 필요

| 안 | 내용 | 장점 | 위험 |
|---|---|---|---|
| **A. 상시 전체 접근** (belie 원안 그대로) | 어드민은 언제나 모든 회사 열람·수정 | 가장 편함 | 계약·화면 약속 위반, RLS 무력화, 위수탁 책임, 사고 시 원인 추적 불가 |
| **B. Break-glass (권장)** | 평소 0 · 필요 시 **사유 입력 → 시간제한(기본 60분) → 읽기전용 → 전 행위 감사로그 → 대상 오너에게 통지** | 운영 가능 + 약속 유지 + 추적 가능 | 클릭 1~2회 추가 |
| C. 요청·승인식 | 대상 오너가 승인해야 접근 | 가장 안전 | 장애 시 대응 불가(오너가 자리에 없으면 멈춤) |

**MWC 권고: B.** 이유 — 운영에 필요한 건 "언제나 열려 있음"이 아니라 **"필요할 때 즉시 열림"** 이고, B는 그걸 주면서 사용자 약속("자동 접근하지 않아요")도 참말로 유지합니다. C는 장애 대응을 막아 실무에서 못 씁니다.

B를 택하면 화면 문구도 **거짓이 되지 않습니다** — "자동 접근하지 않아요"는 여전히 참(자동이 아니라 사유·기록·통지를 거침).

## 3. 어드민 콘솔 IA (신설 메뉴)

진입: 회사 전환 메뉴(좌상단) 최하단에 **`⚙ 플랫폼 관리`**(플랫폼 관리자에게만 노출) → `/platform`

```
/platform
├ 개요            운영 대시보드: 회사 수·신규 가입·대기 요청·오류·사용량
├ 회사 관리        전체 회사 목록(메타데이터) · 상태 · 오너 · 플랜 · 멤버 수
│   └ 회사 상세    메타 정보 + [🔓 접근 요청] 버튼(break-glass)
├ 가입 요청        기존 `/platform/workspace-requests` 흡수 (승인·거절)
├ 사용자           계정 목록 · 소속 · 로그인 기기 · 잠금/해제
├ 접근 기록        ★ break-glass 이력(누가·언제·왜·무엇을·얼마나)
├ 구독·플랜        entitlement 부여/회수(무료 베타 기간엔 조회 위주)
├ 시스템           마이그레이션 상태 · 잡 큐 · 오류 로그 · 공지 배포
└ 어드민 관리      app_admins 추가/제거(2인 이상 시 상호 승인 권장)
```

**어드민 워크스페이스가 별도 "회사"인가?** — **아닙니다.** 조직(org)으로 만들면 tenant plane에 섞입니다. `/platform`은 **회사가 아닌 별도 평면**이며, 좌상단 스위처에는 회사 목록과 **구분선 아래**에 별도 항목으로 둡니다.

## 4. Break-glass 흐름 (2클릭 + 사유)

```
1) /platform → 회사 상세 → [🔓 이 회사 열람하기]
2) 모달: 사유 선택(장애대응/고객지원/정산확인/보안점검) + 상세 1줄 + 기간(15/60분/4시간)
3) 확인 → /w/{slug} 진입 (읽기 전용 · 상단 고정 배너)
4) 만료 시 자동 종료. [지금 종료] 버튼 상시 노출
```

**진입 중 화면 규칙**
- 상단에 **지워지지 않는 배너**: `🔓 플랫폼 운영자 열람 중 · 사유: 고객지원 · 남은 시간 42분 · [지금 종료]`
- 배경색 구분(경고 톤) — 실수로 고객 화면과 헷갈리지 않게
- **오너 사칭 금지** — 화면 어디에도 어드민을 그 회사의 오너로 표시하지 않음(계약 142행)
- 기본 **읽기 전용**. 쓰기가 필요하면 **별도 승격**(사유 재입력 + 대상 오너 통지 강화)

**대상 회사에 보이는 것**
- 오너에게 알림 1건: "플랫폼 운영자가 <사유>로 <시간>에 열람했습니다. [기록 보기]"
- 그 회사의 `설정 > 접근 기록`에서 **고객도 직접 열람 가능**(투명성 = 신뢰 자산)

## 6. 데이터 모델 (신규 — Codex가 번호 배정)

```
platform_access_grants
  id · admin_email · org_id · reason_code · reason_text
  mode(read|write) · granted_at · expires_at · revoked_at · revoked_by

platform_access_events        -- 감사로그(append-only)
  id · grant_id · at · action(view|export|update|download)
  target_table · target_id · ip · user_agent

app_admins (기존 005)          -- 여기에 컬럼 추가 검토: can_break_glass, added_by, added_at
```

**RLS 정합**: 기존 `is_org_member()`를 **바꾸지 않습니다**. 대신 `has_active_grant(org_id)`를 **OR 조건으로 추가**한 정책을 별도로 둡니다 — 기존 격리 로직을 건드리지 않아야 J-5 사고를 막습니다.

## 7. 스위처와의 정합 (D-S1~S5)

- 좌상단 회사 메뉴 최하단, `기존 회사에 합류하기` **아래 구분선**에 `⚙ 플랫폼 관리` 1줄 추가.
- 어드민에게만 노출. 일반 사용자에겐 **존재 자체가 안 보임**.
- 어휘: "회사"(D-S3) 유지. 단 `/platform`은 회사가 아니므로 **"플랫폼 관리"**로 부름.
- 클릭 수: 콘솔 진입 2클릭 · break-glass 진입 3클릭(+사유).

## 8. 단계별 구현 제안

| 단계 | 범위 | 비고 |
|---|---|---|
| **P0** | `/platform` 셸 + 개요 + 회사 목록(**메타만**) + 가입 요청 흡수 | break-glass 없이 먼저. 위험 0 |
| **P1** | Break-glass 읽기 + 배너 + 감사로그 + 오너 통지 | 핵심 안전장치 세트로 한 번에 |
| **P2** | 쓰기 승격 · 사용자 관리 · 구독/entitlement | |
| **P3** | 시스템(잡 큐·오류) · 어드민 2인 이상 상호 승인 | |

**P0만으로도 belie의 실제 업무 대부분이 됩니다**(누가 가입했나, 어떤 회사가 있나, 요청 승인). 업무 데이터 접근은 P1에서 안전장치와 함께 붙이는 걸 권합니다.

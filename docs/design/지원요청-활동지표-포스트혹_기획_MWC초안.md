# A. 지원 요청 위젯 (채널톡식) + 권한 위임

## A-0. belie 발안의 진짜 가치 — 접근의 주도권이 뒤집힌다

break-glass는 **운영자가 문을 따는** 구조입니다. belie가 말한 "직원이 요청할 때 열어주기"는 **고객이 문을 열어주는** 구조 — 이게 훨씬 좋습니다.

| | **초대형 접근 (invited)** ← 신설·**기본 경로** | **Break-glass** ← 예외 경로 |
|---|---|---|
| 주도 | 고객(오너·관리자)이 위임 | 운영자가 개시 |
| 동의 | **명시적 동의 그 자체** | 사후 통지 |
| 심리 | "도와주세요" | "들어갑니다" |
| 용도 | 문의·설정 도움·오류 재현 | 장애 대응·보안 사고·고객 무응답 |
| 기록 | 동일하게 전량 기록 | 동일 |

> **원칙: 초대형이 기본, break-glass는 예외.** 운영자가 break-glass를 쓰기 전에 **"고객에게 위임 요청을 먼저 보냈는가"** 를 확인하는 단계를 넣습니다. 그러면 대부분의 접근이 동의 기반이 되고, 계약의 "자동 접근 없음" 약속이 더 강해집니다.

## A-1. 위젯 구성 (우측 하단 플로팅)

```
                                   ┌──────────────────────┐
                                   │ 무엇을 도와드릴까요?    │
                                   ├──────────────────────┤
                                   │ 💬 문의 남기기         │  → 1:1 스레드
                                   │ 🔓 화면 봐달라고 하기   │  → 권한 위임(오너·관리자)
                                   │ 📖 도움말 보기         │  → 가이드
                                   └──────────────────────┘
                                                    (?) ← 플로팅 버튼
```
- 버튼: 우측 하단 고정, 지름 52px, 미읽음 답변 있으면 **뱃지 숫자**(뱃지 규칙 준수 — 답변=내가 볼 일이므로 숫자).
- 모바일: 하단 탭바와 겹치지 않게 **우측 하단 + 안전영역 여백**, 열리면 풀스크린 시트.
- 색: Work Blue. **People Coral 금지**(담당자·멘션 전용).

## A-2. 권한 위임 (핵심 화면)

```
🔓 운영자에게 화면을 보여줄까요?
────────────────────────────────
얼마나:   [30분]  [2시간]  [오늘 안]        ← 기본 2시간
무엇을:   ● 보기만 (권장)   ○ 보기 + 고치기
왜:      [문의와 연결 ▾]  또는 직접 입력
────────────────────────────────
· 운영자가 보는 동안 화면 위에 표시돼요
· 언제든 [지금 중단]으로 끊을 수 있어요
· 홈택스 위임 서류는 운영자가 볼 수 없어요
             [취소]   [허용하기]
```

**권한 규칙**
| 역할 | 문의 | 권한 위임 |
|---|---|---|
| 오너 | ✅ | ✅ |
| 관리자 | ✅ | ✅ |
| 멤버 | ✅ | ❌ — **오너에게 요청**만(권한 상승 방지) |

- 멤버가 위임을 누르면 → "오너에게 요청을 보낼까요?" → 오너에게 알림(뱃지 숫자) → 오너가 승인.
- 위임 중에는 **고객 화면에도** 상단 배너: `🔓 운영자가 보고 있어요 · 남은 시간 1시간 42분 · [지금 중단]`
- 위임 종료·중단·만료는 **소식창에 기록**(회사 소식 탭).

## A-3. 1:1 채팅 — MVP는 자체 구현 권장

| 방식 | 판단 |
|---|---|
| **인앱 스레드 자체 구현** ← 권장 | 벤더 계약·비용·개인정보 위수탁 **3중 부담 없음**. 기존 `notifications`·소식창·첨부 인프라 재사용. 5인 조직 문의량은 적음 |
| 채널톡·인터콤 연동 | 기능은 풍부하나 **고객사 데이터가 제3자로 흐름** → 위수탁 고지 필요. **Phase 2 옵션** |

**스레드 구조**: `support_threads`(회사·개시자·상태) + `support_messages`(작성자·본문·첨부).
**자동 첨부 컨텍스트**(고객 데이터 아님, 진단용): 현재 경로 · 회사 slug · 역할 · 앱 버전 · 브라우저 · 최근 오류 ID.
**금지**: 고객사명/대표자명/연락처/금액을 컨텍스트에 자동 첨부하지 않음.

## A-4. 어드민 쪽 화면
`/platform/지원` — 문의 목록(회사·상태·최근 답변), 스레드 뷰, **[위임 요청 보내기]** 버튼, 위임 상태 표시. 위임이 살아 있으면 그 자리에서 `/w/{slug}` 진입.

# B. 활동지표 (어드민 콘솔)

## B-0. 원칙 — 지표는 집계값이라 break-glass가 필요 없다

여기가 중요합니다. 활동지표는 **개별 고객 데이터가 아니라 숫자 합계**입니다. 그래서 **P0에서 바로 볼 수 있고**, 접근 권한 문제도 없습니다.

> **규칙: 어드민 지표에는 고객 업무 데이터의 "내용"이 절대 들어가지 않는다.** 건수·시각·사용자 수만.

## B-1. 지표 세트

### ① 사용 활발도 (belie 요청: 활성 사용자)
| 지표 | 정의 | 왜 보나 |
|---|---|---|
| DAU / WAU / MAU | 기간 내 1회 이상 활동한 고유 사용자 | 기본 체온 |
| **스티키니스** = DAU/MAU | 0.2 미만이면 "가끔 쓰는 도구" | **가장 중요한 단일 지표** |
| 조직별 활성 멤버 수 | 초대 대비 실사용 | 좌석 낭비 감지 |

### ② 입력량 (belie 요청: 입력수)
| 지표 | 정의 |
|---|---|
| 쓰기 이벤트 수 | 딜 생성/수정 · 활동기록 · 정산 입력 · 컬럼 편집 합계 |
| 조직별 일 평균 쓰기 | 실제로 "굴리고 있는가" |
| **첫 쓰기까지 시간(TTFV)** | 가입 후 첫 딜 등록까지 — 온보딩 품질 |

### ③ 상호작용 (belie 요청: 클릭수)
| 지표 | 출처 |
|---|---|
| 화면별 조회수·클릭수 | **PostHog**(자체 DB로는 부정확) |
| 기능 채택률 | 그 기능을 1회 이상 쓴 조직 비율 |
| 이탈 지점(퍼널) | PostHog 퍼널 |

### ④ 건강도 (운영자가 진짜 필요한 것)
| 지표 | 의미 |
|---|---|
| **휴면 조직** (14일 무활동) | **이탈 선행지표 — 가장 먼저 봐야 함** |
| 오류율 · 잡 실패 수 | 시스템 이상 |
| 미처리 가입 요청 · 미답변 문의 | 운영자 자신의 밀린 일 |
| 리텐션 W1 / W4 | 정착률 |

## B-2. 조직 목록 표 (어드민 메인)

| 회사 | 멤버 | 마지막 활동 | 7일 쓰기 | 활성/전체 | 상태 |
|---|---|---|---|---|---|
| 서울경영지원센터 | 4 | 12분 전 | 231 | 4/4 | 🟢 활발 |
| 엘에스파트너스 | 2 | 6일 전 | 8 | 1/2 | 🟡 둔화 |
| (예시) | 3 | 21일 전 | 0 | 0/3 | 🔴 휴면 |

정렬 기본 = **위험 순**(휴면 → 둔화 → 활발). 운영자가 아침에 열면 **손봐야 할 회사가 맨 위**에 오게.

## B-3. 데이터 출처 — 이중 구조

```
자체 집계(Postgres)  →  권위 지표: 조직·멤버·쓰기수·휴면·리텐션
   근거: audit_logs · activities · deals · settlements (이미 존재)
   방식: 야간 배치로 platform_metrics_daily 롤업 (실시간 집계 금지 — 8,400건+ 부하)

PostHog            →  행동 지표: 클릭·화면조회·퍼널·세션·기능채택
```
- **자체 집계가 정본**입니다. PostHog는 보조 — 외부 서비스가 끊겨도 운영 지표는 살아 있어야 합니다.
- 신규 테이블: `platform_metrics_daily(date, org_id, active_users, writes, errors, …)` — 번호는 Codex 배정.

# C. PostHog 연결

## C-1. 현재 조건 (2026-07 확인)

- **무료: 월 100만 이벤트** + 세션 리플레이 5K · 피처플래그 100만 요청 등. 이후 1~2M 구간 이벤트당 $0.00005, 대량일수록 단가 하락. 플랫폼 패키지는 Boost $250/mo · Scale $750/mo · Enterprise $2,000/mo.
- **리전**: US / **EU(eu.posthog.com)** 선택 가능. 셀프호스팅(Docker)도 가능하나 PostHog가 프록시 문제 지원을 하지 않음.
- **리버스 프록시 권장**: 광고차단기·기업 방화벽 우회. **Next.js 16은 `middleware.js` → `proxy.js`로 이름이 바뀜** — **우리 레포에 `app/src/proxy.ts`가 이미 있음**(코덱스 작성) → 거기에 경로만 추가하면 됨.
- 경로명은 `/analytics`·`/tracking`·`/posthog` 같은 뻔한 이름 **금지**(차단기가 잡음) → 예: `/mw-sig`.

## C-2. 개인정보 — 여기가 제일 중요합니다

우리 제품은 **고객사의 고객(사업자) 정보**를 다룹니다. 분석 도구로 그게 새면 위수탁 사고입니다.

**전송 금지(하드 규칙)**
```
❌ 고객사명 · 대표자명 · 연락처 · 이메일 · 사업자번호 · 주소
❌ 금액(실행액·수수료·매출) · 계약 내용
❌ 홈택스 위임/수집 서류 관련 일체
❌ 사용자 이메일을 식별자로 사용
```
**전송 허용**
```
✅ 내부 UUID(user_id·org_id) · 역할 · 화면 경로(파라미터 제거)
✅ 이벤트명 · 소요시간 · 성공/실패 · 오류코드
✅ 조직 규모 구간(1~3 / 4~7 …)  ※실수 아닌 구간값
```
- **세션 리플레이 기본 OFF.** 켜야 한다면 입력값 전면 마스킹(`maskAllInputs`) + 오너 동의.
- **리전 = EU 권장**(GDPR 정합·데이터 거버넌스가 더 엄격). 다만 한국 데이터의 **국외 이전**에 해당하므로 **개인정보처리방침에 수탁자·이전 국가·항목 명시** 필요.
- 규제 요구가 커지면 **셀프호스팅으로 이전**(같은 SDK, 엔드포인트만 교체 — 갈아타기 비용이 낮게 설계).

## C-3. 이벤트 설계

**네이밍 규약**: `영역.대상.행동` (소문자·스네이크)
```
auth.login.succeeded          org.workspace.switched
crm.deal.created              crm.deal.stage_changed
settle.settlement.saved       board.column.created
support.thread.opened         support.grant.approved
admin.breakglass.started      admin.breakglass.ended
```
**필수 속성**: `org_id` · `role` · `plan_tier` · `app_version`
**금지 속성**: 위 C-2 목록 전부

**비용 가드**: 이벤트 화이트리스트만 전송(자동 캡처 남발 금지). 100만/월을 넘길 조짐이면 저가치 이벤트부터 샘플링.

## C-4. 리포트 수신
1. PostHog 대시보드(운영자 직접) — 퍼널·리텐션·클릭맵
2. **어드민 콘솔에 요약 임베드** — 주요 수치만 API로 당겨 `/platform/개요`에 표시
3. **주간 리포트**: 스티키니스·휴면 조직 수·오류율·상위 이탈 지점 → 매주 월요일 이메일/인앱

## E3 — EU 권고 철회 근거 (정정)

MWC가 처음에 EU를 권한 이유는 GDPR 정합이었으나, 재검토 결과 **우리 상황에 맞지 않는 근거**였다.

1. **대상이 없다** — GDPR은 EU 거주자 데이터에 적용된다. 현재 사용자는 전원 한국 사업자다.
2. **한국 PIPA 기준으로는 동일** — US·EU 모두 **국외 이전**이다. 고지·처리방침 명시 의무가 똑같이 발생하므로 EU를 골라도 이점이 없다.
3. **되돌릴 수 없다** — 리전 간 데이터 이전은 **Scale($750/월)·Enterprise 플랜에서만** 지원된다. 무료 요금제에서는 사실상 **일방향 선택**이므로, 기존 US 프로젝트가 있다면 유지가 안전하다.

→ **결론: US 유지.** EU 고객이 실제로 생기면 그때 별도 프로젝트 또는 마이그레이션(Scale 플랜 필요)으로 재검토.

## E2 보완 — 멤버 직접 위임 시 안전장치 (승인 없이 위험만 낮추기)

멤버가 오너 승인 없이 위임할 수 있으면 **권한 상승 통로**가 될 수 있다. 승인 단계를 넣지 않으면서 위험을 낮추는 장치:

| 장치 | 내용 |
|---|---|
| **범위 고정** | 멤버가 개시한 위임은 **읽기 전용만**. "보기+고치기"는 오너·관리자만 |
| **담당범위 상속** | scope=assigned 멤버가 위임하면 운영자도 **그 멤버 담당 건만** 열람(RLS 상속) |
| **즉시 통지** | 위임 즉시 **오너에게 알림(숫자 뱃지)** — "○○님이 운영자 열람을 허용했어요" |
| **오너 강제 종료** | 오너는 언제든 **[지금 중단]** 가능. 멤버는 자기 위임만 중단 |
| **기록** | 소식창·감사로그에 개시자·사유·시간 전량 기록 |
| **동시 상한** | 회사당 활성 위임 **1건**(중복 위임 방지) |

> 이러면 "승인 절차 없음"이라는 belie 결정은 그대로 지키면서, 멤버가 회사 전체 데이터를 통째로 열어주는 사고는 막힌다.

## E4 보완 — 리플레이 ON 시 필수 조건

리플레이는 화면을 그대로 녹화하므로 **고객사의 고객 개인정보가 그대로 담길 수 있다.** ON으로 가되 아래는 타협 불가:

```
maskAllInputs: true            // 모든 입력값 마스킹(기본)
maskTextSelector: '[data-pii]' // 고객명·사업자번호·금액 영역에 data-pii 부착 → 마스킹
                               // ※ 이 속성 부착이 실제 방어선. 화면 구현 시 필수 체크리스트 항목
차단 경로: /w/*/회계, /w/*/settlements, 홈택스 관련 화면 전면 녹화 제외
보존기간: 30일(기본값보다 짧게)
고지: 개인정보처리방침에 "서비스 개선 목적 화면 기록" 명시 + 수탁자(PostHog)·국외이전 국가 표기
```

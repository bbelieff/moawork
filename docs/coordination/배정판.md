## 1. 편제 — 4반 × 6세션 = 24

기계 2 × 진영 2 = **반 4개**, 각 반은 **총괄 1 + 반장 1 + 작업원 4 = 6세션**.
**C=클로드 · G=지피티(코덱스)**

```
반 하나의 속
  총괄     그 반의 문맥 유지 · 배정 집행 · 도장 취합 · 인수인계   ← 판단하지 않는다
  01       반장 겸 검수자                                        ← 코드를 만들지 않는다
  02~05    작업원 4칸                                            ← 만든다
```

> **왜 반마다 총괄을 두나** — 토큰 소진으로 한 세션이 멈추면 그 반의 «지금까지의 맥락» 이
> 통째로 사라진다. 실제로 2026-08-11 에 총괄 세션 문맥이 한 번 날아갔다.
> 총괄을 4개로 나누면 하나가 죽어도 나머지가 `배정판.md` 를 읽고 이어받는다.

> ⚠️ **총괄이 4개면 중복이 돌아올 수 있다.** 그래서 판단 권한은 하나만 갖는다 — §3.

| 반 | 뜻 | 성격 | 왜 이 성격인가 |
| --- | --- | --- | --- |
| **DC** | 데탑 클로드 | 조립(화면) | 브라우저가 있다 → 화면을 눈으로 확인할 수 있다 |
| **NC** | 노트북 클로드 | 조립·회수 | 〃 |
| **DG** | 데탑 코덱스 | 부품(DB·계약) | 브라우저가 없다 → 눈이 필요 없는 일 |
| **NG** | 노트북 코덱스 | 관문·검증 | 〃 |

> **원칙 — 화면(`page.tsx`·`layout.tsx`)은 C 진영만 만진다.**
> 근거: 2026-08-11 프로덕션 P0(PR #160)은 코덱스 브랜치였다. 화면을 바꿨는데 볼 수단이 없었다.

**20칸 밖**

| | 소유 | 침범 금지 |
| --- | --- | --- |
| **C 총괄** (Cowork) | 목업 정본 · 결정대장 · 배정판 · 판정 | 관제판·배포를 만들지 않는다 |
| **G 총괄** (코덱스) | 관제판 · 배포/CI 상태 · 회귀 감시 종합 | 목업·결정대장을 고치지 않는다 |

> ⚠️ 총괄층에서도 중복이 났다 — C총괄이 PR #136(목업 중복)과 대시보드를 두 벌 만들어 둘 다 폐기했다.

## 2. 검수 — 짝과 비상 경로

```
평시   DC ↔ DG      NC ↔ NG        같은 기계 안에서 진영을 건넌다
                                   (다른 모델이 봐야 «같은 쪽으로 잘못 읽기» 가 걸린다)

2단    돈 · 마이그레이션 · 권한(D24) · 프리셋/컬럼/아이템 구조
       → 반대편 기계 반장이 추가로 본다.  DC→NG · DG→NC · NC→DG · NG→DC

비상   진영이 통째로 마비(토큰 소진)되면  DC ↔ NC · DG ↔ NG
       같은 진영이라 열등하다. 도장에 「비상검수 — 동일 진영」을 반드시 적는다.
       → 진영이 살아나면 그 목록이 재검수 대상이 된다. 안 적으면 검증 안 된 게 조용히 섞인다.
```

**★ 검수자는 자기 폴더가 아니라 원격에서 받은 것으로 본다.**

```bash
git fetch origin && git checkout <PR head SHA>
```

2026-08-11 에 「정본 파일이 원격에 없음」으로 6세션이 몇 시간 멈췄다. 이 한 줄이 그것을 막는다.

**★ 각 반의 `01` 은 코드를 만들지 않는다.** 만들게 하면 검수가 멈춘다 — 08-11 관문 3건이 「검수자가 안 붙어 21:47 이후 정지」한 원인이 그것이다.

## 3. 대행 — 총괄이 멈췄을 때

```
C 총괄 마비  →  ① DC-01      ② C 진영 전체 마비면 G 총괄
G 총괄 마비  →  ① DG-01      ② G 진영 전체 마비면 C 총괄
```

**대행은 «집행» 만 한다. «결정» 은 못 한다.**

| 대행이 하는 것 | 못 하는 것 |
| --- | --- |
| 이 배정판대로 배정 발송 | 새 D번호(결정대장) 등재 |
| 도장 확인 · 1단 통과분 머지 | 목업 수정 |
| 회귀 감시 · 관제판 갱신 | 편제 변경 · 카드 신설 · 배정 변경 |

새 결정이 필요하면 **belie 에게 올린다.** 대행이 판단까지 하면 그게 중복의 시작이다.

**잔량 규칙** — 총괄·반장은 한도가 가까워지면 **멈추기 전에** 인수인계 도장을 남긴다.
`지금 무엇을 하던 중 · 다음 순서 · 미결 판단` 3줄. → `BBE-94`

## 6. 완료의 정의 (개정)

```
전:  코드 + 테스트 + CI
후:  코드 + 테스트 + CI + «그 화면 주소를 열어 눈으로 본 증거»
```

- 화면이 없는 계약·부품 카드는 «완주» 가 아니라 **«부품 납품»** 이다.
  반드시 「어느 화면이 이것을 쓰는가」를 후속 카드로 남긴다. **소비자 없는 부품은 만들지 않는다.**
- 브라우저가 없는 G 진영은 **MWC 에 클릭스루를 의뢰**하고 그 확인을 받아야 완주다.
- 「목업 86/86 PASS」를 완주 근거로 쓰지 마라. NG-02 완료 전까지 화면 일치는 **사람 눈** 으로만 판정한다.

# 디스패치 루프 — 한 마디로 한 라운드

**2026-08-12 · 디스패치 상주 운영 규칙**

> belie 가 밖에 있어도 목표까지 굴러가게 만드는 것이 이 문서의 목적이다.
> **belie 는 「다음으로 진행」 한 마디만 한다.** 나머지 판단은 여기 적힌 규칙이 한다.

**목표** — 목업을 구현한다. 완료 판정은 `docs/design/목업스터디-재구축설계_v1.md` §4-A.

---

## 0. 디스패치가 «할 수 있는 것» 과 «못 하는 것»

| 할 수 있다 | 못 한다 |
| --- | --- |
| 순서표(§4-A)에 있는 카드를 착수시킨다 | **순서표에 없는 새 카드를 만든다** |
| 창을 직접 호출한다 | 배정 자체를 새로 설계한다 |
| 도장·PR·판을 읽고 상태를 판정한다 | 돈·비가역 결정 |
| 재배차·반납 해제·검수 재요청 | 목업 수정 · D번호 등재 · 편제 변경 |

**순서표가 곧 배정이다.** 표에 카드와 칸이 이미 못 박혀 있으므로, 디스패치는 «만드는» 것이 아니라 «집행» 한다.
표 밖의 상황이 생기면 §5 로 belie 에게 올린다.

## 0.5 ★ 목표 — 라운드마다 «먼저» 읽는다

**정본: `docs/coordination/출시-최소조건.md`**

> **「사용자의 고객사 등록을 엑셀로 해서 실무플로우에 따라 수금까지 진행하는 절차를 완료한다」**
> — 총괄 정의 2026-08-19

```
① 엑셀로 고객사 일괄 등록      없다
② 실무 보드에 행이 생김        반쪽 — 신규리드만
③ 실무 진행                   있다
④ 수금                        반쪽 — 부품은 다 있고 «행» 이 안 생긴다
```

### 목표가 하는 «진짜 일» — 필터다, 장식이 아니다

> ### 이 네 단계를 미는 카드가 아니면 라운드에서 열지 않는다.
> 급해 보여도, 잘 적혀 있어도, 누가 물어봐도 마찬가지다.
> **열려면 「이 카드가 ①~④ 중 어느 것을 미는가」를 한 줄로 답해야 한다.** 못 답하면 안 연다.

**예외는 둘뿐이다:**
- **운영이 멈춘 것**(P0 · 사용자가 지금 못 쓴다) — 목표와 무관해도 연다
- **여정이 쌓은 값을 잃는 것**(데이터 손실) — ③④가 만든 값이 사라지면 여정이 무의미해진다

**이 필터가 없으면 이런 일이 생긴다** — 2026-08-17~18 이틀 동안 카드 31장이 닫혔는데
①~④ 는 **한 칸도 안 움직였다.** 지표는 전부 초록이었다.

④ 창을 호출한다     §4 재투입 문장
⑤ 라운드 보고 1장   §6 형식으로 BBE-94 에 — ★ 첫 줄은 «출시를 당겼는가»
```

## 2. 칸 분류 6종

| 분류 | 판정 근거 |
| --- | --- |
| **진행** | 카드 In Progress + 최근 도장 24시간 이내 |
| **완주** | 카드 Done 또는 PR 머지됨 |
| **검수대기** | 카드 In Review 또는 PR 열림 + 검수 도장 없음 |
| **반납** | `blocked:<약칭>` 라벨이 붙음 |
| **유휴** | 라벨 붙은 카드가 없음 |
| **무응답** | 도장이 24시간 이상 없음 (진행 중인데 조용함) |

## 3. 분류별 행동

### 진행
건드리지 않는다. **재촉하지 마라.** 도장만 확인한다.

### 완주
```
① 그 칸이 «막고 있던» 카드가 있는지 찾는다 —  blocked:<그 칸 약칭>
   있으면 그 라벨을 떼고 막혀 있던 칸을 재투입한다  ← 이게 루프의 핵심이다
② 순서표 §4-A 에서 그 칸의 다음 카드를 찾아 착수시킨다
③ 다음 카드의 «선행» 이 아직 안 끝났으면 대기시킨다 — 억지로 시작시키지 마라
④ 다음 카드가 없으면 §5 로 belie 에게 올린다
```

### 검수대기
```
검수자에게 직접 호출을 보낸다.  ★ 댓글만 남기지 마라 — 아무도 안 온다
60분 무응답  →  같은 기기의 다른 유휴 세션으로 재배차
             도장에 「지정 검수자 무응답 60분 → 보조 검수 <세션명>」
2단 조항(돈 · 마이그레이션 · D24 권한 · 프리셋/컬럼/아이템 구조)이면 반대편 기기 반장으로
```

### 반납 (`blocked:`)
```
막는 쪽 칸의 상태를 본다
  풀렸으면   →  라벨을 떼고 재투입한다
  안 풀렸으면 →  막는 쪽을 재촉하지 말고 «그 칸» 을 먼저 진행시킨다
  막는 쪽이 3라운드째 안 움직이면  →  §5 로 올린다
```

### 유휴
```
순서표 §4-A 에서 그 칸의 다음 카드를 찾아 착수시킨다
선행이 안 끝났으면 대기 도장을 남기게 한다 — 사유 · 재개 조건 · 확인 주체
```

### 무응답
```
1회차  재투입 문장을 보낸다
2회차  「응답 없으면 카드를 회수한다」 를 붙여 보낸다
3회차  카드 라벨을 떼고 같은 반의 유휴 칸에 재배정한다
       원래 칸에는 「무응답 3라운드 — 카드 회수」 를 남긴다
```

## 3.5 ★ 대타 배차 — 토큰이 없으면 «멈추는» 게 아니라 «넘긴다»

> **2026-08-19 총괄 정정으로 신설.** 이 규칙이 없어서 이틀을 잃었다.

### 무엇이 잘못됐었나

`BBE-189` 에 「2026-08-20 전에는 신규 G 배차를 열지 않습니다」라고 적혀 있었다.
그것을 **「동결이니 기다린다」로 읽었다.** 그래서 Urgent 카드(`BBE-196` — 다른 보드의 컬럼이 지워진다)가
**생성 이후 1초도 안 움직인 채 이틀**을 보냈다.

**총괄의 의도는 정반대였다** — 「G 로는 안 여니까 **C 로 땡겨서 하라**」.

> ### 자원 제약은 «정지 조건» 이 아니라 «경로 변경 조건» 이다
> 「G 라인에 토큰이 없다」가 말하는 것은 **「그 일을 하지 마라」가 아니라 「그 일을 G 로 하지 마라」** 다.
> 일 자체는 계속 간다. **바뀌는 것은 누가 하느냐뿐이다.**

### 규칙 — 이대로 한다

```
① 어느 라인이 토큰·한도로 못 움직인다
      ↓
② 그 라인의 카드를 «다른 라인» 이 대신 수행한다      ← 멈추지 않는다
      ↓
③ ★ 대신 한 쪽이 «자기 도장» 을 반드시 찍는다
      「원 주인 <G-xx> · 대타 수행 <C-xx> · 사유: 토큰 한도」
      실제로 누가 했는지가 남아야 한다. 원 주인 이름으로 위장하지 않는다
      ↓
④ 대타도 토큰이 부족해지면
      → «원래 작업의 주인» 에게 핸드오프를 남긴다              ← 여기서도 안 멈춘다
        어디까지 했는지 · 다음 한 걸음 · 막힌 것 · 건드린 파일
      ↓
⑤ 원 주인이 살아나면 그 핸드오프에서 이어받는다
```

### 도장 형식 — 대타 수행

```
[대타 수행] 원 주인 DG-06 · 수행 DC-12 · 사유: G 라인 토큰 한도
무엇을 했나: …
다음 한 걸음: …
원 주인에게: (이어받을 때 알아야 하는 것)
```

### 핸드오프 형식 — 대타도 힘이 빠졌을 때

```
[핸드오프] DC-12 → DG-06 (원 주인)
여기까지 했다: <커밋 SHA · PR 번호 · 파일>
다음 한 걸음: <구체적으로 한 문장>
막힌 것: <있으면>
★ 이어받는 사람이 «다시 조사하지 않아도» 되게 적는다
```

### 하지 말 것

- **「기다린다」로 끝내지 마라.** 이 규칙이 생긴 이유가 그것이다
- **원 주인 도장으로 위장하지 마라.** 누가 했는지가 흐려지면 다음 라운드에 검수 라우팅이 틀어진다
- **핸드오프 없이 조용히 죽지 마라.** 세션이 한도로 끝날 것 같으면 **끝나기 전에** 핸드오프를 남긴다
- ★ **작성자 ≠ 검수자는 그대로다.** 대타로 수행했어도 그 사람이 자기 것을 검수하지 않는다

```

## 6. 라운드 보고 — BBE-94 에 1장

```
[모아워크 디스패치] 라운드 N · <날짜 시각>

★ 절차 맵이 움직였나                                    ← 첫 줄이다
   부품 진행도   <전> → <후>       (체크포인트 수. 코드에 있나 없나)
   사용자 완주   <전> → <후>       (끝까지 갈 수 있는 단계 수)
   처음 끊기는 곳 <전> → <후>
   → 판정: 진행 / 부품만 늘고 완주는 그대로 / 후퇴

판:  진행 n · 완주 n · 검수대기 n · 반납 n · 유휴 n · 무응답 n

움직인 것
  <칸>  <무엇에서 무엇으로>   ← 각 줄 끝에 «어느 단계를 미는가» 를 붙인다
  ...

대타 수행 / 핸드오프         ← §3.5. 없으면 «없음»
  <수행한 칸> ← <원 주인>  사유

해제한 반납
  <칸>  blocked:<약칭> 해제 — <막던 쪽>이 완주함

belie 판단 필요        ← 없으면 «없음»
  <항목> — <제안>

다음 라운드에 볼 것
  <칸> <이유>
```

### ★ 시간으로 평가하지 않는다

**「며칠 당겼다」를 쓰지 마라.** 이 팀은 작업 시간도, 토큰 잔량도, 총괄이 언제 코딩할지도 통제하지 못한다.
**통제 못 하는 변수로 만든 숫자는 매번 틀리고, 틀린 숫자는 아무도 안 믿는다.**
대신 **체크포인트를 센다** — 코드에 있나 없나. 누가 언제 일하든 같은 값이 나온다.

### ★ 두 숫자를 «따로» 본다

```
부품 진행도   체크포인트 몇 개가 켜졌나       ← 조각의 수
사용자 완주   끝까지 갈 수 있는 단계 몇 개     ← 사슬의 길이
```

**여정은 사슬이다.** 부품이 71% 있어도 첫 칸이 끊기면 사용자에게 도달하는 건 0 이다.
**「부품만 늘고 완주는 그대로」인 라운드는 그렇게 적어라.** 그게 사실이면 그게 정직한 값이다.

## 8. 루프가 지켜야 할 것 — 오늘 겪은 것들

- **재촉하지 마라.** 진행 중인 칸을 흔들면 오히려 느려진다. 도장만 확인한다
- **배정을 스스로 만들지 마라.** 순서표가 정본이다. 표 밖은 belie 에게
- **댓글은 호출이 아니다.** 창을 직접 불러라
- **화면 확인 없는 완주를 통과시키지 마라.** 2026-08-11 에 그래서 P0 가 났다
- **되돌릴 수 없는 것(머지·발송·배포)은 실행 직전에 한 번 더 확인해라.**
  「중단」 지시와 이미 실행 중인 명령이 경합한 사고가 있었다 (BBE-30)

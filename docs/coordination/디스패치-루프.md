# 디스패치 루프 — 한 마디로 한 라운드

> ### 〔기록〕 이 문서는 «그때 그랬다» 이지 «지금 그래야 한다» 가 아니다
> **지금 규칙은 `AGENTS.md`(일하는 방식)와 `CLAUDE.md`(제품) 두 개뿐이다.**
> 이 문서가 아래에서 자기를 「정본」이라 하거나 「착수 금지」를 걸어도 **따르지 않는다.**
> 지우지 않고 남기는 이유는 — 지우면 같은 시행착오를 다시 하기 때문이다. 〈 2026-08-20 일원화 〉


**2026-08-12 · 디스패치 상주 운영 규칙**

> belie 가 밖에 있어도 목표까지 굴러가게 만드는 것이 이 문서의 목적이다.
> **belie 는 「다음으로 진행」 한 마디만 한다.** 나머지 판단은 여기 적힌 규칙이 한다.

**목표** — 목업을 구현한다. 완료 판정은 `docs/design/목업스터디-재구축설계_v1.md` §4-A.

## 0. 디스패치가 «할 수 있는 것» 과 «못 하는 것»

| 할 수 있다 | 못 한다 |
| --- | --- |
| 순서표(§4-A)에 있는 카드를 착수시킨다 | **순서표에 없는 새 카드를 만든다** |
| 창을 직접 호출한다 | 배정 자체를 새로 설계한다 |
| 도장·PR·판을 읽고 상태를 판정한다 | 돈·비가역 결정 |
| 재배차·반납 해제·검수 재요청 | 목업 수정 · D번호 등재 · 편제 변경 |

**순서표가 곧 배정이다.** 표에 카드와 칸이 이미 못 박혀 있으므로, 디스패치는 «만드는» 것이 아니라 «집행» 한다.
표 밖의 상황이 생기면 §5 로 belie 에게 올린다.

## 1. 한 라운드 — 이 순서로 돈다

```
① 판을 읽는다      Linear 카드 상태 · BBE-94 최근 도장 · 열린 PR
② 칸을 분류한다     아래 6종
③ 분류대로 행동한다  §3 표
④ 창을 호출한다     §4 재투입 문장
⑤ 라운드 보고 1장   §6 형식으로 BBE-94 에
```

---

## 2. 칸 분류 6종

| 분류 | 판정 근거 |
| --- | --- |
| **진행** | 카드 In Progress + 최근 도장 24시간 이내 |
| **완주** | 카드 Done 또는 PR 머지됨 |
| **검수대기** | 카드 In Review 또는 PR 열림 + 검수 도장 없음 |
| **반납** | `blocked:<약칭>` 라벨이 붙음 |
| **유휴** | 라벨 붙은 카드가 없음 |
| **무응답** | 도장이 24시간 이상 없음 (진행 중인데 조용함) |

## 3. 분류별 행동

### 진행
건드리지 않는다. **재촉하지 마라.** 도장만 확인한다.

### 완주
```
① 그 칸이 «막고 있던» 카드가 있는지 찾는다 —  blocked:<그 칸 약칭>
   있으면 그 라벨을 떼고 막혀 있던 칸을 재투입한다  ← 이게 루프의 핵심이다
② 순서표 §4-A 에서 그 칸의 다음 카드를 찾아 착수시킨다
③ 다음 카드의 «선행» 이 아직 안 끝났으면 대기시킨다 — 억지로 시작시키지 마라
④ 다음 카드가 없으면 §5 로 belie 에게 올린다
```

### 검수대기
```
검수자에게 직접 호출을 보낸다.  ★ 댓글만 남기지 마라 — 아무도 안 온다
60분 무응답  →  같은 기기의 다른 유휴 세션으로 재배차
             도장에 「지정 검수자 무응답 60분 → 보조 검수 <세션명>」
2단 조항(돈 · 마이그레이션 · D24 권한 · 프리셋/컬럼/아이템 구조)이면 반대편 기기 반장으로
```

### 반납 (`blocked:`)
```
막는 쪽 칸의 상태를 본다
  풀렸으면   →  라벨을 떼고 재투입한다
  안 풀렸으면 →  막는 쪽을 재촉하지 말고 «그 칸» 을 먼저 진행시킨다
  막는 쪽이 3라운드째 안 움직이면  →  §5 로 올린다
```

### 유휴
```
순서표 §4-A 에서 그 칸의 다음 카드를 찾아 착수시킨다
선행이 안 끝났으면 대기 도장을 남기게 한다 — 사유 · 재개 조건 · 확인 주체
```

### 무응답
```
1회차  재투입 문장을 보낸다
2회차  「응답 없으면 카드를 회수한다」 를 붙여 보낸다
3회차  카드 라벨을 떼고 같은 반의 유휴 칸에 재배정한다
       원래 칸에는 「무응답 3라운드 — 카드 회수」 를 남긴다
```

## 4. 재투입 문장 — 이걸 그대로 보낸다

```
[디스패치 → <칸>] 계속.

현재 판정: <분류>
할 일: <순서표에서 찾은 카드번호와 제목 / 또는 해제된 blocked>

■ 규칙은 그대로다 — AGENTS.md 2026-08-12판
  · 완주 = 코드 + 테스트 + CI + «그 화면을 열어 눈으로 본 증거» (§3)
  · 「목업 86/86 PASS」를 완주 근거로 쓰지 마라 — 앱을 증명하지 않는다
  · 막히면 기다리지 말고 «반납» — 라벨을 떼고 blocked:<막는 칸 약칭>
    도장에 «누가» 를 이름으로. 「나는 무엇으로 넘어간다」가 없으면 정지다
  · 검수는 원격에서 받아서:  git fetch origin && git checkout <PR head SHA>
  · 구조를 줄이지 마라 (D73). 고객 이름을 박지 마라 (D71~D75)

■ 지금 목적 — 목업을 구현한다
  순서표: docs/design/목업스터디-재구축설계_v1.md §4-A
  네 카드가 끝나면 그 표에서 다음을 집어라.

→ BBE-94 에 도장을 남겨라
```

## 5. belie 에게 올리는 경우 — 이때만 멈춘다

```
① 돈 · 비가역        hosted 마이그레이션 적용 · 발송 활성화 · 요금제 · 외부 발행
② 순서표 밖 상황      §4-A 에 없는 일이 필요해졌다
③ 3라운드 정체       같은 칸이 세 번 연속 안 움직인다
④ 검수 2회 연속 FAIL  같은 카드가 두 번 반려됐다 — 설계가 틀렸을 수 있다
⑤ 목업 해석이 갈린다  두 칸이 같은 목업 문구를 다르게 읽는다
⑥ 완주 판정이 애매하다 화면 확인 증거가 없는데 «됐다» 고 주장한다
```

**올릴 때는 «질문» 이 아니라 «제안» 으로 낸다.**
「이렇게 하겠습니다 · belie 손이 필요한 건 이것뿐입니다」 (AGENTS.md §8.4)

## 7. 루프가 끝나는 조건

```
node docs/design/qa-app.mjs   차이가 C(목업이 예시) 분류분만 남음
프로덕션에서 탭 6개가 목업대로 동작 — 눈으로 본 증거
새 워크스페이스를 만들면 탭이 이미 있고 데이터는 0  (BBE-131)
```

**세 개가 다 되면 목표 달성이다.** 그때 belie 에게 완료 보고를 올린다.

## 8. 루프가 지켜야 할 것 — 오늘 겪은 것들

- **재촉하지 마라.** 진행 중인 칸을 흔들면 오히려 느려진다. 도장만 확인한다
- **배정을 스스로 만들지 마라.** 순서표가 정본이다. 표 밖은 belie 에게
- **댓글은 호출이 아니다.** 창을 직접 불러라
- **화면 확인 없는 완주를 통과시키지 마라.** 2026-08-11 에 그래서 P0 가 났다
- **되돌릴 수 없는 것(머지·발송·배포)은 실행 직전에 한 번 더 확인해라.**
  「중단」 지시와 이미 실행 중인 명령이 경합한 사고가 있었다 (BBE-30)

## 1. 새 정본

- 데탑에서 구현한 작업의 독립검수는 작성자가 아닌 **데탑 LLM**이 수행한다.
- 노트북에서 구현한 작업의 독립검수는 작성자가 아닌 **노트북 LLM**이 수행한다.
- 선행 작업의 결과를 소비하는 후속 구현, 반려 수정, 재검수, merge·deploy 추적도 선행 작업과 같은 기기 레인에 배정한다.
- `작성자 ≠ 검수자`는 유지한다. 같은 기기와 같은 세션은 다른 개념이다.
- 사용자가 개별 작업에 교차 기기 예외를 명시한 경우에만 예외를 허용한다.

## 2. 부재·미응답 처리

- 지정 reviewer가 부재, 미응답, identity mismatch이면 다른 기기를 기다리지 않는다.
- 총괄은 같은 기기의 유휴 세션 중 작성자가 아닌 세션을 즉시 대체 reviewer로 지정한다.
- Linear/GitHub에 검수 요청 댓글을 남긴 것만으로 세션이 호출됐다고 간주하지 않는다.
- 총괄은 reviewer 세션을 직접 호출하고 `PASS` 또는 `REQUEST_CHANGES` 판정 ID를 확인한다.
- 판정 확인 후 총괄은 owner 세션을 직접 다시 호출해 반려 수정 또는 merge·Production·health·도장 체인을 재개한다.

## 3. 기존 배정 정정

- `docs/plans/배정-260810/01_데탑CT01.md`~`20_데탑GT10.md`에 적힌 노트북 reviewer·후속 owner 지정은 역사로 보존하되 현재 배차에는 적용하지 않는다.
- 데탑 01~20 작업은 데탑 01~20 중 작성자가 아닌 다른 C/G 세션이 교차검수하고, 후속 소비 작업도 데탑 01~20에 재배차한다.
- 노트북 21~40 작업은 노트북 21~40 중 작성자가 아닌 다른 C/G 세션이 교차검수하고, 후속 소비 작업도 노트북 21~40에 재배차한다.
- 배정판의 `데탑 CT09 ↔ 노트북 GT02`, `데탑 GT06 ↔ 노트북 GT04`, `데탑 CT02 ↔ 노트북 CT06`, `데탑 CT03 ↔ 노트북 CT03` 연계는 역사 기록이며 현재 비활성이다. 재개 시 선행 작업과 같은 기기 LLM에 새 owner·reviewer·lease를 발행한다.
- `30_노트북CT10.md`와 `40_노트북GT10.md`는 각각 노트북 C/G 라인 전담 검수로 정정한다. 데탑 C/G 라인은 데탑 LLM 사이에서 교차검수한다.
- 카드·PR·댓글에 남은 과거 교차 기기 reviewer 명시는 새 판정이 아니라 역사 기록이다.

## 4. 완료 게이트

1. reviewer 직접 호출 증거
2. exact source SHA와 fresh main 대조
3. 작성자와 다른 동일 기기 reviewer의 판정 ID
4. owner 직접 재호출 증거
5. PASS면 squash merge → Production READY → `/login` HTTP 200 → 카드·BBE-94 완료 도장
6. REQUEST_CHANGES면 이전 SHA를 stale로 고정 → 수정 → 같은 기기 재검수

## 1. 사용자 결정

MoaWork의 사용자 노출 UI 변경은 앞으로 테스트·CI PASS만으로 완료 처리하지 않는다. 실제 로컬 앱 또는 대체 로컬 HTML을 브라우저에 열어 사용자가 눈으로 확인하고 다음 지시를 내릴 수 있게 한 뒤에만 merge 단계로 이동한다.

## 2. 필수 흐름

1. UI 구현과 1차 자동 검증
2. 실제 로컬 앱 실행, 불가능한 경우에만 로컬 HTML 생성
3. 데스크톱 기본 화면을 사용자 브라우저 탭으로 직접 전달
4. 관련 시 모바일·다크모드·상호작용 화면도 함께 제시
5. 변경 전후 차이를 화면 기준으로 설명
6. `VISUAL_REVIEW=PENDING` 상태에서 사용자 승인 또는 수정 지시 대기
7. 수정 시 같은 화면을 갱신하고 재검수
8. 사용자 시각 승인 후 독립 T10·전체 gate·PR CI·Preview 확인
9. 별도 merge·Production 승인 범위 안에서만 반영

Preview가 인증으로 막혀도 시각 검수를 생략하지 않는다. 로컬 앱 또는 로컬 HTML을 우선 사용하며, 검수 서버와 탭은 사용자가 확인 완료를 말할 때까지 유지한다.

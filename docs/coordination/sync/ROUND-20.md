# SYNC Round 20 — 소규모 조직 우선과 디자인 로드맵 재정렬

> 작성: MoaWork Control(MWC) · 2026-07-23 KST

## 사용자 결정

- MoaWork의 초기 고객은 작은 조직이며, 작은 조직에서 시작해 기능을 하나씩 확장한다.
- 기본 조직 시나리오는 `대표(보호된 Owner) → 팀장 → 사원`이다.
- ROUND-18의 네 시안은 플랫폼 운영·지원·보안 구조가 전면에 나와 초기 고객에게 과했다. 네 안 모두 현재 상태로는 선택하지 않는다.
- ROUND-18에서 정리한 Owner 보호, 테넌트 격리, 고객지원 접근, 세션 회수 같은 안전 규칙은 폐기하지 않고 내부 제약과 고급 관리 기능으로 보존한다.

## 제품 원칙

1. 첫 10초 안에 현재 회사, 내 역할, 내 팀, 내 정보, 로그인 기기와 로그아웃을 찾을 수 있어야 한다.
2. 기본 화면에는 프로필, 현재 회사, 팀, 역할, 개인정보, 현재/모든 기기 로그아웃처럼 자주 쓰는 항목만 둔다.
3. Owner에게만 필요한 회사 관리는 자연스럽게 드러내고, 플랫폼 운영 등급·긴급보호·세밀한 범위 설정은 별도 플랫폼 관리나 고급 설정으로 분리한다.
4. 작은 조직은 최소 설정으로 끝까지 사용할 수 있고, 조직이 커질 때 팀·계층·권한·감사 기능을 점진적으로 연다.
5. 화면은 단순하게 만들되 데이터와 권한 구조는 성장 가능성을 잃지 않는다.

## T04 디자인 교정

- WORK-ID: `SMALL-ORG-FIRST-01`
- T04가 보유한 HTML lease는 유지한다. MWC는 HTML을 직접 수정하지 않는다.
- 네 시안은 구조적으로 다른 배치를 유지하되, 작은 조직의 현실적인 데이터와 일상 과업으로 다시 설계한다.
- 권장 탐색 관점은 `한눈에 보는 내 회사`, `하나씩 안전하게 설정`, `내 계정과 팀`, `필요할 때만 관리`다.
- 기술 공식, 긴 설명, 플랫폼 1~4급과 지원 접근 모드는 첫 화면에서 제거하고 고급 경로에서만 보여준다.
- 한글 UX 라이팅, MoaWork 브랜드 토큰, 라이트/다크, 모바일, 클릭 가능한 다음 시퀀스를 유지한다.

## T10 독립 검수

- WORK-ID: `SMALL-ORG-FIRST-VERIFY-01`
- 첫 10초 이해도, 작은 조직의 최소 설정, 고급 기능의 점진적 공개, 안전 규칙 보존을 독립 검수한다.
- T10 PASS와 로컬 페이지 재공개 전에는 사용자 선택 게이트로 올리지 않는다.

## 다음 기획 우선순위

1. `P0 기반 안전`: Owner 보호, 안전한 초대·대기, 플랫폼/워크스페이스 권한 분리, 프로필 분리, 로그인 기기·세션 회수.
2. `P1 작은 조직 첫 가치`: 첫 10분 온보딩과 대표–팀장–사원 조직 만들기.
3. `P1 일상 핵심 루프`: 리드 등록부터 다음 행동까지의 영업 흐름과 오늘의 대시보드.
4. `P2 협업`: 알림·활동 기록, 검색, 댓글·멘션, 단순 자동화.
5. `P3 성장 관리`: 좌석·플랜, 고급 감사·복구, 가져오기·내보내기, 보고서와 복잡 조직 기능.

T01은 전체 사용자 여정, T02는 코드·PR·마이그레이션 의존성, T05는 운영·수익·협업 맹점을 조사하고 T09가 실제 결과를 회수해 우선순위와 병렬/직렬 실행 파동으로 통합한다.

### T09 통합 결과

고객이 보는 다음 디자인 순서는 아래로 재정렬한다.

1. `3분 시작`: 대표가 회사·첫 고객·첫 업무를 최소 설정으로 만들고 오늘 화면에 도착한다.
2. `오늘의 MoaWork`: 대표·팀장·사원이 각자 오늘 할 일을 한 화면에서 시작한다. 통합 검색과 최근 본 항목은 이 화면에 포함한다.
3. `우리 팀 키우기`: 팀장·사원 초대, 첫 업무 배정, 접근 중지와 업무 인계를 단순 역할로 처리한다.
4. `안전하게 데이터 가져오기`: CSV·먼데이 데이터 미리보기, 오류·중복 확인, 전체 취소와 되돌리기를 제공한다.

보이지 않는 P0인 tenant/RLS 격리, 마지막 Owner 보호, Platform/Workspace 권한 분리, 초대 원자성, 세션 폐기, deny 우선과 감사는 화면 노출 순위와 관계없이 선행 계약으로 유지한다.

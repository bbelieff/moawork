# SYNC Round 17 — 어드민·계정·세션 역인터뷰 부분 결정

> 작성: MoaWork Control(MWC) · 2026-07-23 KST

## 확정

- MVP Workspace의 protected Owner는 정확히 1명이다.
- Workspace 문맥은 `/w/{workspaceSlug}` URL 구조로 분리한다.
- 개인정보·계정 정책은 ROUND-16 추천안을 채택한다: 로그인 이메일 기본 마스킹, 전역 identity와 Workspace 프로필 분리, 개인 데이터와 Workspace 업무자료 export 분리, 탈퇴 취소기간 Draft 유지.
- 모든 회원의 세션은 권한과 무관하게 절대 30일, 미사용 7일을 기본값으로 한다.
- 모든 기기 로그아웃은 계정 전체와 모든 Workspace에 적용한다.

## 플랫폼 운영 위계 정규화 Draft

영문 기능 역할을 위계처럼 사용하지 않는다. `권한 등급`과 `담당 영역`을 분리한다.

- 1급 총괄 관리자
- 2급 영역 관리자
- 3급 실무 담당자
- 4급 조회 담당자

담당 영역은 `운영`, `고객지원`, `보안`, `결제·플랜`으로 나눈다. 1급은 전 영역을 관리하고, 2~4급은 배정받은 영역에서 상위 등급이 하위 등급의 capability를 포함한다. 기존 “한 사람이 여러 역할”은 “한 등급을 갖고 여러 담당 영역을 배정받을 수 있음”으로 다시 표현한다.

## 사용자 설명·결정 대기

고객지원 접근은 영구 membership이나 사용자 impersonation이 아니라 목적·범위·시간·감사가 붙는 임시 support session이다.

1. 기본지원: tenant 업무내용 없이 마스킹된 계정·오류 메타데이터만 조회.
2. 승인지원: Owner가 특정 Workspace·화면·시간을 승인한 임시 read-only 접근.
3. 긴급보호: 계정탈취·유출·대규모 장애에서 Owner 사전승인 없이 최소 조회와 세션 폐기·계정 잠금 등 allowlisted 보안조치만 수행하고 즉시 통지·감사.

`read-only`는 고객의 리드·업무·계약·정산 데이터를 수정하지 않는다는 의미다. 세션 폐기·로그인 잠금 같은 보안 격리 동작은 별도 안전 버튼으로 허용할 수 있다.

Q4·Q5 답변 전에는 support consent, emergency access, support write 범위, T04 목업과 구현을 확정하지 않는다.

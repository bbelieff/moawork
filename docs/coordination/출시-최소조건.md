## 정의 — 총괄 원문

> **「사용자의 고객사 등록을 엑셀로 해서 실무플로우에 따라 수금까지 진행하는 절차를 완료하는 MVP 기능 구현」**

**하나의 연속된 여정이다.** 중간 어디가 끊기면 나머지가 아무리 튼튼해도 MVP 가 아니다.

```
① 엑셀로 고객사 일괄 등록
② 등록된 고객사가 실무 보드에 «행» 으로 올라감
③ 실무 진행 — 단계 이동·담당·상태·셀 값
④ 수금 — 수수료·계약금·입금일 입력 → 실현액 집계
```

## ★ 초판이 왜 폐기됐는가 — 이 기록을 지우지 않는다

초판(2026-08-19 오전)은 조건을 이렇게 적었다:

```
① 데이터를 잃지 않는다   ② 새 워크스페이스가 비어 있되 쓸 수 있다
③ 여섯 탭이 목업대로 확인된다   ④ 로그인이 유지된다
```

**넷 다 «깨지면 안 되는 것» 이지 «되어야 하는 것» 이 아니다.**
품질 게이트를 출시조건으로 착각했고, **여정이 이미 존재한다고 가정한 채 그 위의 안전만 따졌다.**

> ### 깨지면 안 되는 것 ≠ 되어야 하는 것
> 품질 게이트는 여정이 굴러간 «다음» 에 지키는 것이다. 여정이 한 번도 안 굴러갔으면
> 지킬 대상 자체가 없다. **출시조건은 언제나 «사용자가 무엇을 끝까지 할 수 있는가» 로 쓴다.**

옛 조건들은 폐기가 아니라 **강등**이다 — 아래 §품질 게이트로 옮겼다.

## ★ MVP 의 진짜 P0

> ### ③ → ④ 사이. 「업무관리 이동」이 계약업체 실무 보드에 행을 만들지 않는다.
> 딜의 stage 만 `work` 로 바뀌고, **수금 컬럼이 있는 보드는 영원히 빈다.**

① 도 없지만 성격이 다르다:
- **① 은 «입구가 없다»** — 손으로 등록하면 우회된다
- **③→④ 는 «길이 끊겼다»** — 우회하면 사용자가 매번 손으로 행을 다시 만들어야 하고, **딜과 보드 행이 서로 모른다**

★ **그리고 이 P0 에 해당하는 Linear 카드가 없다.** `WO-5` 로 코드 주석에만 언급되고 카드가 만들어진 적이 없다.
**판에 없는 것은 어떤 관제판으로도 볼 수 없다.** — 카드 개설이 필요하다(총괄 승인 대기).

## 미정 — 조건인지 아직 못 정한 것

- **`settlements` 처리** (`BBE-231`) — 이 조사로 **MVP 경로 밖**임이 확정됐다. 그래도 죽은 테이블인지 미완성인지는 정해야 한다. **출시 후로 미룰 수 있다**
- **성능 예산** (`BBE-222`·`BBE-223`·`BBE-226`) — 느린 채로 나가도 되는가
- **「출시」의 뜻** — 서울경영지원센터 첫 고객 인도인가, 공개 SaaS 출시인가. **둘은 최소조건이 다르다** (총괄 확인 필요)

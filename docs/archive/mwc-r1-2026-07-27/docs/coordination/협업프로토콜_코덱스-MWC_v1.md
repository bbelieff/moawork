# 협업 프로토콜 — 코덱스 ↔ MWC (분리·통합 자유자재) v1

> 작성 2026-07-27 · MWC · belie 지시("수술대는 하나, 의사는 둘 / 1층·2층 나눠 짓다가 때론 같이").
> 전제: **코덱스가 앞서 있다. 코덱스 구조·진행을 건드리지 않는다.**

---

## 0. 핵심 원리 — 층은 "파일"이 아니라 "능력"으로 나눈다

파일로 나누면 언젠가 같은 파일을 만지게 되고, 그때마다 조율 비용이 든다.
그런데 우리 둘은 **애초에 할 수 있는 일이 다르다.** 이 선을 그대로 층으로 쓰면 **충돌이 구조적으로 0**이 된다.

| | 코덱스 (2층 — 건물 내부) | MWC (1층 — 건물 밖·설비) |
|---|---|---|
| **할 수 있는 것** | 레포 코드·브랜치·PR·머지·배포·테스트 | 브라우저·외부 콘솔(Supabase·GCP·DNS·먼데이)·라이브 검증·기획 판정 |
| **못 하는 것** | 브라우저 조작, 외부 콘솔 로그인, 사람 판정 | **git push**(원격 미연결), 레포 머지 |
| **결과물** | 코드·커밋·배포 | 인프라 설정·검증 리포트·기획/배정 문서 |

> **왜 이게 되는가**: 코덱스가 OAuth 코드를 짜는 동안, MWC는 GCP에서 클라이언트를 발급했다(실제로 2026-07-22에 그렇게 굴러갔다). 서로의 산출물이 필요하지만 **같은 파일을 만지지 않는다.**

---

## 1. 상시 모드 (기본) — 분리

**코덱스 레인**: `moawork-canonical/` + 워크트리 `moawork-wt-*` 전부. 코드·docs 커밋·머지·배포.
**MWC 레인**: 외부 시스템 + 판정. 레포에는 **읽기만.**

### MWC 자체 금지선 (이걸 지키면 코덱스는 MWC를 신경 쓸 필요가 없다)
1. canonical·워크트리에 **쓰기 금지**.
2. git 쓰기 명령 **전면 금지** — `commit·push·fetch·pull·checkout·worktree·merge`. (읽기전용 `git log`·`git branch`·파일 읽기만 허용 — 잠금 안 걸림)
3. 코덱스가 만든 브랜치·워크트리·구조를 **평가는 하되 변경하지 않는다.**
4. 기획·배정 문서는 MWC가 쓰되, **레포 반영은 belie를 통해 코덱스가 커밋**한다.

---

## 2. 관측 — "지금 몇 층에서 뭐 하나"를 보는 법

MWC는 아래 4가지를 읽기전용으로 확인한다. **코덱스에게 묻지 않는다**(방해 금지).

| 신호 | 읽는 법 | 알 수 있는 것 |
|---|---|---|
| 브랜치명 | `git branch` (canonical) | 코덱스가 잡은 작업 단위. 예: `feat/public-workspace-entry-{auth,db,ui}` = 공개진입 4레인 |
| 워크트리 폴더명 | `ls moawork-wt-*` | 동시 진행 중인 레인 수 |
| 커밋 로그 | `git log --oneline` | 머지·배포 이력, 무엇이 끝났나 |
| **라이브 사이트** | `www.moa-work.com` 접속 | **배포 결과 = 최종 진실.** (2026-07-27 이 방법으로 B1b 완료 확인) |

## 3. 통합 모드 — "같이 1층에서 작업"할 때

같은 대상(브랜치·파일·기능)에 둘이 붙어야 할 때는 **동시 금지, 직렬 교대**로 한다.

```
1) 잠금 선언   : belie가 "이 건은 지금 ○○이 잡는다" 1줄 통보
2) 단독 작업   : 잡은 쪽만 수정. 다른 쪽은 읽기만.
3) 반납 통보   : 끝나면 "○○ 끝, 넘김" + 결과 요약
4) 인수       : 반대쪽이 이어받아 진행
```

- 잠금 단위는 **브랜치**를 권장(파일보다 굵게 잡아야 안전).
- 잠금 없이 같은 브랜치에 둘이 붙는 것 = 금지.

---

## 3-b. ★ 상호 착수 통지 (belie 상설 지시 2026-07-27)

> **작업을 시작할 때 반드시 상대에게 먼저 알린다.** 클로드(MWC)는 코덱스에게, 코덱스는 클로드에게.
> 채널: **워크로그**(레포 파일). 세션 간 자동 통신이 없으므로 belie가 전달하거나 코덱스가 커밋해 공유한다.

**START 블록(작업 시작 시 즉시)**
```
[START · <MWC|CODEX>] <작업명>
- 무엇을: (한 줄)
- 만지는 것: (파일·경로·시스템 — 리스 선언)
- 안 만지는 것: (상대 레인 명시)
- 예상 산출물: (파일명)
- 상대에게 필요한 것: (없으면 "없음")
```

**END 블록(끝날 때)**
```
[END · <MWC|CODEX>] <작업명>
- 결과: (PASS/FAIL/부분)
- 산출물: (경로)
- 상대가 이어받을 것: (없으면 "없음")
- 발견한 리스크: (없으면 "없음")
```

규칙:
1. **START 없이 시작하지 않는다.** 겹침은 시작 전에만 싸게 막을 수 있다.
2. 리스 충돌을 발견하면 **먼저 선언한 쪽이 우선**, 나중 쪽은 다른 일로 우회(§1 대기 금지).
3. 상대 레인을 건드려야만 하면 **착수 전 통지 → 승인 후**(통합 모드 §3의 직렬 잠금).
4. MWC는 canonical에 쓰지 못하므로, MWC의 START/END는 **belie를 통해 전달**되거나 코덱스가 커밋한다.

## 4. 교대 모드 — 미국·인도 릴레이

한쪽이 바쁘거나 한도 소진 시, **핸드오프 블록**만 남기면 반대쪽이 이어받는다.

```
[HANDOFF]
- 무엇을: (작업명 / 브랜치)
- 어디까지: (완료분 · 커밋 SHA 또는 배포 URL)
- 남은 것: (다음 액션 1~3개)
- 막힌 것: (블로커 · 필요한 결정)
- 넘기는 대상: (코덱스 / MWC)
```

- 코덱스 → MWC: `docs/coordination/sync/ROUND-N.md`에 남김(이미 하는 방식).
- MWC → 코덱스: MWC가 작성 → belie가 전달 → 코덱스가 커밋.

---

## 5. 겹침이 실제로 발생하는 유일한 지대 = `docs/`

코드는 안 겹친다(코덱스 전용). 겹치는 건 문서뿐이다. 규칙:

- **`docs/` 쓰기 권한은 코덱스에 있다.** MWC는 초안을 만들고 belie를 통해 넘긴다.
- MWC 초안은 **파일명에 `_MWC초안` 접미사**를 붙여 정본과 구분한다.
- 코덱스가 이미 만든 문서(ROUND-N·PLAN·decision-inbox)를 MWC가 **대체 선언하지 않는다.** 차이가 있으면 belie에게 보고하고 판정을 받는다.
  > ※ 2026-07-22 MWC가 `SYNC-R1 폐기`·`마스터기획서 v1.0 정본` 선언을 했으나, 코덱스는 같은 시기에 SYNC-R1을 **집행·종결**했다. 이 규칙이 없어서 생긴 충돌 — 재발 방지.

## 2. 세션 간 소통의 물리적 진실 (중요 — 오해 방지)

**세션끼리 자동으로 메시지를 주고받을 수 없다.** 각 창은 격리된 별개 프로세스이고, **belie가 그 창에 뭔가 입력할 때만 깨어난다.** 즉:

- 소통 채널 = **레포 파일**(dispatch-queue.md·worklog.md·sync/ROUND-N.md)뿐.
- 디스패치는 큐를 스스로 감시하지 못한다. **belie의 "큐 확인" 트리거 1회**로 깨어난다.
- 따라서 "코워크↔코드", "코드↔코드" 직접 소통은 **불가능**하며 항상 디스패치(파일+트리거) 경유다.

### 루프의 실제 형태
세션들이 서로 핑퐁하는 자율 루프는 **불가**. 대신:

> **한 번 깨울 때, 그 안에서 여러 라운드를 돈다.**
> belie "큐 확인" 1회 → 디스패치가 배분→빌드→검증→머지→다음배분→… **백로그 소진 또는 블로커까지 계속** → 종합 보고.

belie의 손이 가는 지점은 **배치당 1회**. 이걸 최소화하는 것이 §3의 목적.

## 3. 디스패치 자율루프 (belie 확인 없이 돌리는 5장치)

정본: `docs/coordination/디스패치_자율루프_부트스트랩.md` (belie가 디스패치 창에 1회 붙여넣기).

1. **자율권한 헌장** — 사전승인 범위를 못박아 물어볼 이유를 제거. 화이트리스트(=belie 필수)만 남기고 나머지는 전부 디스패치 재량.
2. **완료판정 자동화** — 사람 승인 대신 **T10 게이트 통과 = 승인.** 각 프롬프트의 "수용기준"이 판정 기준.
3. **블로커 우회 원칙** — 막히면 멈추지 말고 그 건만 파킹하고 **다음 백로그로 즉시 이동.** 대기 금지.
4. **질문 적재(비차단)** — 판단 필요건은 `decision-inbox.md`에 쌓고 진행 계속. belie가 나중에 일괄 처리.
5. **배치 실행** — 한 번 깨우면 큐 소진까지. 라운드마다 belie에게 묻지 않는다.

## 4. OWNER(코워크) 행동 규약

1. belie가 "만들어/고쳐/구현" → **인라인 착수 금지.** 큐에 배정 등재 후 "큐 사인 넣었음, 디스패치에 '큐 확인'" 반환. 즉시 유휴.
2. OWNER가 직접 하는 것: 결정·판정, 짧은 사실답변, 배정 작성, belie와 상의. 전부 수 분 내.
3. **새 아이디어는 파킹**(`docs/plans/active/파킹랏.md` 1줄) — 현재 스프린트를 옆길로 새지 않게.
4. belie 필수 판단(돈·보안·외부발행·방향전환)만 질문.
5. **문서는 직행**: OWNER 산출 문서(기획·프롬프트·운영모델)는 디스패치가 커밋해 트랙에 전달(코드는 절대 OWNER가 푸시하지 않음 — `CLAUDE.md §6.7`).

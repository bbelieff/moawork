# B. 조직 — 누가 무엇을 하나

## B-0. 냉정한 사실: 세션끼리는 말이 안 통한다
세션 간 자동 통신 수단이 **없다**(도구 탐색으로 확인). 채널은 레포 파일뿐이고,
각 세션은 **belie가 입력할 때만** 깨어난다. 디스패치도 고장났다.
→ **그러므로 belie가 전달 버스다.** 이걸 인정하고, **belie의 손을 최소화하는 것**이 설계 목표다.

## B-1. 배치

| 역할 | 누구 | 하는 일 | 못 하는 일 |
|---|---|---|---|
| **결정권자 · 전달 버스** | **belie** | 판단·승인, 프롬프트 붙여넣기(라운드당 소수) | — |
| **설계·검증 두뇌 (MWC)** | 이 세션 | 설계·목업·프롬프트 작성 · **부품 코드(dev-drop)** · **프로덕션 실측/회귀검증** · 결함 리포트 | **git push 불가** |
| **작업반장** | **T01**(기반·공용부) | main 머지·배포·번호 충돌 정리·공용 계약 관리 | 세션 간 직접 지시 |
| **작업자** | T03·T06·T07·T08 (+코덱스 세션) | 각 영역 구현·테스트·PR | 남의 레인 파일 수정 |
| **게이트키퍼** | T10 | 머지 전 검수(테스트·375px·토큰·RLS) | 구현 |

> **작업반장을 T01로 두는 이유**: git 브리지가 필요한 일(머지·배포·번호 정리)이 병목이었다.
> 다만 반장도 세션이라 **다른 트랙에 직접 지시할 수 없다** — 지시 전달은 여전히 belie를 거친다.

## B-2. 레인(파일 소유) — 충돌 0을 만드는 선

| 트랙 | 소유 영역 |
|---|---|
| T01 | `app/src/proxy.ts` · 빌드/배포 설정 · 공용 타입 · **머지 권한** |
| T03 | 셸·인증·진입(`(app)/layout` · `auth/*` · `workspace-entry` · `components/workspace/*`) |
| T06 | 알림(`notifications` · 벨/소식창 컴포넌트) |
| T07 | 운영 평면(`app/platform/**` · 지표 배치 · 결제·매출) |
| T08 | 지원(`components/support/**` · `access_grants` · 위임) |
| MWC | `docs/**` · `dev-drop/**` (레포 코드 미터치) |

# C. 루프 — 한 바퀴 도는 법

## C-1. 라운드 구조 (belie 손 = 라운드당 2회 이하)

```
① 배분   MWC가 프롬프트 준비 → belie가 각 트랙에 붙여넣기          [belie 손 1회]
② 작업   트랙들 병렬 구현 (belie 개입 0)
③ 수거   트랙 완료 → belie가 "끝났대" 한 줄 전달                    [belie 손 1회]
④ 검증   MWC가 프로덕션 직접 실측·회귀검증 (belie 개입 0)  ★핵심 절약
⑤ 판정   MWC가 PASS/FAIL + 다음 배분안 제시 → ①로
```

**④가 핵심이다.** MWC가 브라우저로 프로덕션을 직접 볼 수 있으므로,
"됐는지 확인"에 belie가 개입할 필요가 없다. 트랙 자기보고보다 실측이 우선한다.

## C-2. 라운드 게이트 (통과 못 하면 다음 라운드 없음)

| 게이트 | 기준 |
|---|---|
| G1 배포 | main 머지 + Vercel 배포 성공 |
| G2 권한 | belie 계정 로그인 → 오너 권한 해소 → 잠금 풀림 |
| G3 회귀 | MWC 회귀검증 PASS (2계정 로그인·2클릭·뱃지 규칙·375px) |
| G4 기록 | 트랙 `[START]/[END]` 워크로그 존재 |

## C-3. 상시 규칙
- 트랙은 착수 시 `[START · T0x]`, 종료 시 `[END · T0x]` 워크로그. **END 없으면 다음 배정 없음.**
- 남의 레인 파일을 만져야 하면 **먼저 선언**하고 belie를 통해 조율.
- 새 아이디어는 즉시 구현하지 말고 **파킹**(현재 라운드 보호).
- MWC 회귀 체크리스트 상시 3항목: **나갈 수 있나 · 홈 갈 수 있나 · 내 할 일이 보이나**

# D. 현재 라운드 — **R1: 배포 뚫기**

## D-1. 목표 한 줄
> **belie가 로그인해서 `모아워크`·`테스트` 회사를 직접 만들 수 있게 한다.**

이게 되면 R1 성공. 안 되면 나머지는 전부 검증 불가다.

## D-2. 배정

| 순번 | 트랙 | 작업 | 지금 착수 | 프롬프트 |
|---|---|---|---|---|
| **1** | **T03**(또는 코덱스) | **0순위 머지·배포 + 권한 P0** → 진입 UX 3건 → 스위처 적용 | ✅ | 채팅에 출력됨 / `direct-to-codex/코덱스_직접지시_C0-C1` |
| 2 | T01 | PostHog(프록시·PII 차단·리플레이 마스킹) | ✅ 독립 | `direct-to-codex/코드세션_직접전달` §T01 |
| 3 | T07 | 어드민 셸+고객사관리+지표배치(+결제 스키마) | ✅ 독립 | 〃 §T07 |
| 4 | T06 | 알림 뱃지·소식창 | T03 이후 | 〃 §T06 |
| 5 | T08 | 지원 위젯·위임·첨부 | T06 이후 | 〃 §T08 |
| — | T10 | 상시 검수 | 상시 | — |

**동시 착수 권장: 1·2·3** (파일 레인이 겹치지 않음)

## D-3. MWC가 R1 동안 할 일 (belie 개입 0)
1. `dev-drop` 부품 추가 — 알림 뱃지 순수 로직 · PostHog PII 스크러빙 함수(+테스트)
2. 배포되면 즉시 **회귀검증**(2계정·권한·2클릭·뱃지·375px) → PASS/FAIL 리포트
3. 결함 발견 시 재현 절차·수용기준 포함한 리포트 작성

## D-4. R1 완료 정의(DoD)
- [ ] G1 배포 성공
- [ ] G2 belie 오너 권한 해소, 사이드바 잠금 풀림
- [ ] belie가 `모아워크`·`테스트` 회사 생성·진입 성공
- [ ] 로고 클릭 → 홈 이동
- [ ] pending 화면에서 나갈 수 있음 + 같은 회사 중복 요청이 서버에서 1건으로 수렴
- [ ] 승인 대기 → 알림/뱃지로 2클릭 도달
- [ ] MWC 회귀검증 PASS

## D-5. R2 예고 (R1 통과 시)
어드민 셸 실사용(고객사 관리·승인) · 알림/소식창 · 지원 위젯+위임 · 결제 스키마 · PostHog 검증.

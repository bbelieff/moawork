## 0. 공통 규약 (전 트랙)

1. **착수 전 상호 통지** — 워크로그에 `[START · T0x]` 블록(협업프로토콜 §3-b). END 없으면 다음 배정 없음.
2. **마이그레이션 번호는 최신 main 기준으로 코덱스가 배정.** MWC 문서의 번호는 참고값이 아니라 **미지정**이다.
3. **브랜드 토큰 하드코딩 금지** — `brand/assets/.../moawork-color-tokens.css`. **People Coral은 담당자·멘션·알림 전용**(CTA·오류·로고 금지).
4. **어휘 규칙(D-S3)** — UI에 보이는 글자는 **"회사"**. `워크스페이스`는 URL·코드·문서에만. 예: 사이드바 헤더 `… · 워크스페이스` → **`… · 내 회사`로 수정**.
5. **375px 무깨짐** 수용기준 필수. 터치 타깃 ≥44px.
6. **RLS 우회 금지.** 새 기능도 기존 `is_org_member()`를 **수정하지 않는다**. 필요한 경우 **OR 조건의 별도 정책**을 추가한다.
7. 데이터는 가상만. 실제 고객명 금지.

### ⚠️ 선행 차단 이슈 (C배치 착수 전 확인)
Production에서 **로그인 후 권한이 해소되지 않는다** — Owner 계정도 `회사 역할 확인 중` 고착·전 메뉴 잠김·`core.dash`가 "Phase 2 잠김" 표기.
근거: `docs/evidence/PRODUCTION-ENTRY-REGRESSION-01.md`. **이게 안 풀리면 C배치 화면 대부분을 검증할 수 없다.** 최우선 처리 요망.

## C0 — 진입 UX 3건 긴급 수정  【최우선 · C1보다 먼저】

> belie 실사용 제보 + MWC 실측. 근거: `docs/evidence/결함_진입UX-3건_MWC.md`
> **작아 보이지만 사용자가 실제로 막힌 지점이다.** 신규 기능보다 먼저 처리한다.

```
[C0-1] 로고 홈 링크 (현재 링크 자체가 없음)
 실측: /w/{slug} 화면의 <a> 총 4개 — 전부 계정 메뉴. 로고는 NO_LINK. 사이드바 10메뉴도 <a> 아님.
 - 로고를 <a>/Link 로 감싼다. 로그인=/w/{현재slug}, 비로그인=/
 - aria-label="MoaWork 홈으로", 현재 홈이면 aria-current="page"
 - 잠긴 메뉴도 **링크로 렌더**하고 잠금은 시각+aria-disabled로 표현(도달 자체를 막지 말 것)
 수용: 로고 클릭·미들클릭·새탭 모두 동작. 키보드 포커스 가능.

[C0-2] 요청 완료(pending) 화면의 출구 + 중복 요청 처리
 현상: 요청 후 돌아가기·로그아웃·재요청 경로가 없어 사용자가 갇힘 → 뒤로가기로 중복 요청 발생 가능
 - pending 화면 필수 요소: 요청 요약(회사·종류·시각) / [요청 취소하기]
   / 다른 방법: [다른 회사에 합류 요청] [새 회사 만들기] / [로그아웃] [도움 요청하기]
 - 중복 규칙:
     같은 회사 재요청 → 새로 만들지 않고 **기존 요청 상태 표시**("이미 요청했어요 · 시각")
     다른 회사 추가 요청 → **허용**(복수 대기 가능, 목록 표시)
     회사 만들기 요청 → 1건만. 대기 중이면 상태 표시 + 취소 안내
     취소 후 재요청 → 허용(쿨다운 없음), 이력은 감사로그
 - **서버 강제**: (user_id, target_org_id, status='pending') **부분 유니크 인덱스**로 중복 차단.
   프런트 가드만으로는 새로고침·동시요청을 못 막는다.
 - 열거 방지 유지: 없는 회사라고 알려주지 않음
 수용: pending 화면에서 항상 나갈 수 있음 / 같은 회사 중복 요청이 서버에서 1건으로 수렴

[C0-3] 승인/거절 — **기능은 이미 있음. 도달 경로와 분기 시퀀스를 만든다**
 실측(정정): ApprovalQueue.tsx에 decide()·「합류 승인」·「승인하지 않기」 존재.
             /settings/members/approvals(오너)·/platform/workspace-requests(운영자) 페이지 존재.
             Production에서 URL 직접 입력 시 정상 렌더됨.
 문제: 어디에도 링크·뱃지가 없어 **주소를 쳐야만 도달** → 사용자에겐 없는 기능
 - 도달 경로 4개 추가:
     ① 오너에게 알림(숫자 뱃지) → 클릭 시 승인 화면 딥링크 (2클릭)
     ② 사이드바 `멤버관리`에 대기 건수 뱃지 (잠금 상태여도 뱃지는 노출)
     ③ 홈 대시보드 상단 카드 "합류 요청 N건이 기다려요 [검토하기]"
     ④ /platform 개요에 전체 미처리 수(C4)
 - 승인 분기 시퀀스:
     승인 → org_members 생성(기본 역할=멤버, scope=assigned) → 요청자 알림+진입링크
            → 소식창·감사로그 → 요청자 다음 로그인 시 0클릭 진입(B-3)
     거절 → status=rejected. **사유는 요청자에게 비노출**(열거 방지 계약 일관)
            → 요청자 화면에 재요청/다른 방법 경로 제공 → 소식창·감사로그
     만료 → 기본 14일 자동 만료 + 만료 3일 전 오너 리마인드 → 요청자에 만료 안내+재요청 경로
 - 동시성: 서버가 요청 상태 재확인 후 **1회만 반영**(두 관리자 동시 클릭 대비)
 - 승인 권한: 현재 owner 전용. **오너+관리자로 확대할지는 belie 결정 대기**(기본은 현행 유지)
 수용: 알림→승인 2클릭 / 승인 시 멤버 생성·요청자 알림 도달 / 거절 사유 미노출
      / 동시 클릭에도 1회 반영 / 만료 배치 동작

금지: 승인 화면을 새로 만들기(이미 있음 — 연결만 할 것) · 거절 사유 노출 · 프런트 가드만으로 중복 방지
```

```

구현:

   - 트리거: 회사 아이콘 + 회사명 + 내 역할 + ▾ . aria-haspopup/aria-expanded, Esc·바깥클릭 닫힘

       현재 = "사용 중"(강조) / 다른 활성 = 클릭 시 전환 / 요청중 = "승인 대기"(aria-disabled, 클릭 불가)

   - 저장: Storage 비공개 버킷 + 서명URL. **WebP 32/64/256 3종 리사이즈 저장**
   - 보안: 매직넘버 검증(확장자 불신) · **SVG는 정제 후 저장**(script·외부참조 제거)
   - 권한: 오너·관리자만 변경. 파비콘은 MoaWork 고정(회사별 파비콘 금지)
```

## C2 — 알림 뱃지 + 소식창  【셸】

```

   - 다른 회사 소식은 절대 섞이지 않음(스위처 뱃지로 존재만)
4) 데이터: `notifications` 신규. 회사 소식은 기존 `activities`/`audit_logs` 재사용 여부를 트랙이 판단
5) 실시간: Supabase Realtime, 실패 시 60초 폴백 폴링(오류 팝업 금지)

수용: 벨 1클릭 열림 · 알림→화면 2클릭 · 숫자/점 규칙이 테스트로 고정 · 담당범위 반영 · 375px
```

```
수용: 문의 왕복 동작 · 위임 생성/만료/강제종료 · 배너 상시 노출 · 멤버 위임이 읽기전용으로 고정
     · 오너 알림 도달 · 감사로그 누락 0 · 375px
금지: 외부 상담 벤더 연동 · 승인 없이 쓰기 위임 · 홈택스 노출
```

## C4 — 플랫폼 어드민 콘솔 P0 + 활동지표  【신규 · 운영】

```
목표: /platform 콘솔과 조직 활동지표(집계값)를 만든다. **P0에는 고객 업무 데이터 접근이 없다.**

읽기: docs/design/플랫폼-어드민-콘솔_기획_MWC초안.md · 지원요청…_기획 §B

구현:
1) 진입: 회사 전환 메뉴 최하단 구분선 아래 `⚙ 플랫폼 관리` — **플랫폼 관리자에게만 노출**(비관리자에겐 존재 자체 비표시)
   판정은 기존 `app/src/lib/auth/admin.ts`(`app_admin_role`) 재사용
2) `/platform` IA: 개요 · 회사 관리 · 가입 요청(기존 `/platform/workspace-requests` 흡수) · 접근 기록 · 지원
   ※ 어드민은 **org(회사)로 만들지 않는다.** 별도 평면(platform plane) — tenant 오염 금지
3) 조직 목록(메타만): 회사 · 멤버수 · 마지막 활동 · 7일 쓰기수 · 활성/전체 · 상태(활발/둔화/휴면)
   **기본 정렬 = 위험순(휴면 → 둔화 → 활발)**
4) 지표(자체 집계가 정본):
   - 활성: DAU/WAU/MAU · **스티키니스(DAU/MAU)**
   - 입력량: 쓰기 이벤트 수 · 조직별 일평균 · **TTFV(가입→첫 딜 등록)**
   - 건강도: **휴면 조직(14일 무활동)** · 오류율 · 미처리 가입요청 · 미답변 문의 · 리텐션 W1/W4
   - 방식: **야간 배치 롤업 → `platform_metrics_daily`**. 실시간 집계 금지(신규고객 8,400건+ 부하)
   - 지표에 **고객 업무 데이터의 '내용'이 들어가지 않는다**(건수·시각·사용자수만)
5) 접근 기록 화면: `access_grants`/`access_events` 조회(누가·언제·왜·무엇을·얼마나)

수용: 어드민만 진입 · 비관리자에게 메뉴 비노출 · 조직 목록 위험순 · 지표 배치 산출 · P0에서 고객 업무데이터 접근 0
금지: P0에 break-glass 포함(그건 C6) · 실시간 집계 · 어드민을 tenant org로 생성
```

## C5 — PostHog 연동  【분석】

```
목표: 제품 사용 분석을 붙이되 고객 개인정보는 절대 내보내지 않는다.

belie 확정: 리전 **US 유지**(EU 권고 철회 — 근거는 기획 §E3) · 세션 리플레이 **ON**

구현:
1) SDK 설치 + **리버스 프록시 필수**
   - Next.js 16 규약: `middleware` → **`proxy`**. **레포에 `app/src/proxy.ts`가 이미 있음** → 경로만 추가
   - 프록시 경로명은 `/analytics`·`/tracking`·`/posthog` 등 **뻔한 이름 금지**(차단기 회피). 예: `/mw-sig`
   - 엔드포인트는 US 리전(`us.i.posthog.com`)
2) 이벤트 규약 `영역.대상.행동`(소문자·스네이크). 화이트리스트만 전송(자동캡처 남발 금지)
   예: auth.login.succeeded · org.workspace.switched · crm.deal.created · crm.deal.stage_changed
       settle.settlement.saved · board.column.created · support.thread.opened
       support.grant.approved · admin.console.viewed · admin.breakglass.started
   필수 속성: org_id · role · plan_tier · app_version
3) **PII 하드 금지(전송 불가)**
   ❌ 고객사명·대표자명·연락처·이메일·사업자번호·주소
   ❌ 금액(실행액·수수료·매출)·계약 내용
   ❌ 홈택스 위임/수집 서류 일체
   ❌ 사용자 이메일을 식별자로 사용 (→ 내부 UUID만)
4) **세션 리플레이 ON — 아래는 타협 불가**
   - `maskAllInputs: true`
   - 고객명·사업자번호·금액 표시 영역에 **`data-pii` 부착 → `maskTextSelector`로 마스킹**
     ※ 이 속성 부착이 실제 방어선이다. 화면 구현 PR마다 체크리스트 항목으로 고정할 것
   - 회계/정산/홈택스 화면은 **녹화 전면 제외**
   - 보존기간 30일
5) 비용 가드: 무료 100만 이벤트/월. 초과 조짐 시 저가치 이벤트 샘플링
6) 리포트: `/platform/개요`에 요약 임베드 + 주간 리포트(스티키니스·휴면수·오류율·이탈지점)
7) **개인정보처리방침 갱신 필요**(belie 액션): 수탁자 PostHog · 국외이전(미국) · 항목 · 보유기간 · "서비스 개선 목적 화면 기록" 명시

수용: 프록시 경유 이벤트 수집 확인 · 금지 항목 전송 0(자동 테스트로 고정) · 리플레이에 입력값 노출 0
     · 회계/홈택스 화면 미녹화 확인
금지: PII 전송 · 이메일 식별자 · 프록시 없이 직접 전송 · EU 리전으로 임의 변경
```

## C6 — Break-glass (운영자 개시)  【후순위 · C3 이후】

```
목표: 고객이 응답할 수 없을 때만 쓰는 예외 경로. **C3(초대형)이 배포된 뒤에 착수한다.**
- 개시 전 "고객에게 위임 요청을 먼저 보냈는가" 확인 단계 필수
- 사유 선택(장애대응/고객지원/정산확인/보안점검) + 상세 + 기간(15/60분/4시간)
- 기본 읽기 전용. 쓰기는 별도 승격(사유 재입력 + 오너 통지 강화)
- 진입 화면 상단 경고 배너 + 오너 사칭 금지(플랫폼 역할을 tenant 역할로 표시 금지)
- 대상 오너 통지 + 고객이 `설정 > 접근 기록`에서 직접 열람
- 계약서(round-30)에 **§Platform break-glass · §Invited access 절 신설로 동결 권장**
```

## 병렬·의존 관계

```
[선행] Production 권한 P0 해소 ─────────────────┐ (없으면 C1~C4 검증 불가)
C1 스위처+아이콘 ──┬─ C2 뱃지·소식창 (C1의 스위처에 뱃지 부착)
                  ├─ C3 지원위젯·위임 (C2 알림 재사용)
                  └─ C4 어드민 P0 (C1 메뉴에 진입점)
C5 PostHog ── 독립(지금 착수 가능)
C6 break-glass ── C3 이후
```
- **지금 병렬 착수 가능**: C1 · C5 · (C4의 지표 배치 부분)
- C2는 C1의 스위처 컴포넌트 확정 후, C3는 C2의 알림 인프라 후가 자연스럽다.

## 2. 구현 방식 결정 — B(하이브리드 정규화) 【자율결정】

**결정: 사용자에게 보이는 것은 먼데이와 동일(보드·컬럼·뷰·이동·수식), 내부 저장은 정규화 코어(org_id 기준) + RLS.**

- 왜 A(보드 미러)가 아니라 B인가: ① 멀티테넌시(RLS)는 정규화 구조라야 안전·단순 ② 먼데이의 데이터 버그(매출액 텍스트·담당자 이중·연도시트 불일치)를 그대로 이식하지 않음 ③ 확장(업종팩·성과 집계)이 쉬움. (근거: `docs/design/먼데이-구조-스펙.md` §6)
- "동일함"은 **화면 레이어**가 책임진다: 신규고객/컨텍/업무 보드 = 하나의 `deals`(파이프라인)를 단계(stage)로 필터한 뷰. 회계 보드 = settlements 뷰.
- ⚠️ 이견이 있으시면(순수 보드 미러 원하시면) 말씀 주세요. 기본은 B로 진행합니다.
- **컬럼은 서울경영 보드를 그대로 따름**: 각 보드 전체 컬럼·선택지를 `002`의 `board_columns` 프리셋에 수록(신규고객 26·컨텍 24·업무 31·회계 20). 앱이 이를 field_defs로 전개.

## 3. MVP 모듈별 상세 요구사항

> 각 모듈: **목적 / 핵심 화면 / 핵심 데이터 / 주요 기능 / 완료 판정.**
> **MVP(먼데이 파리티)** = core.crm·core.custom·core.org·core.dash·core.files(파일첨부)·ind.policyfund(컬럼·선택지·정산수식). **Phase 2(벤더)** = mod.hometax·mod.notify·세금계산서. **Phase 1.5(벤더불요)** = mod.perf.

### core.crm — 영업·고객·실무 (기둥①②)
- 목적: 먼데이 4단계(신규고객→컨텍→업무→회계)를 하나의 파이프라인으로.
- 화면: 파이프라인 보드(칸반/테이블 전환) · 고객사 목록 · 딜 상세(정보/활동/문서/정산 탭).
- 데이터: `companies` `pipelines` `stages` `deals` `activities`.
- 기능: 단계 드래그 이동(=먼데이 "이동" 자동화 재현) · 활동기록(통화/미팅/메모) · 담당배정 · 칸반 정렬.
- 완료: 신규 건을 유입→계약→실무까지 단계 이동하며 끝까지 처리, 활동 로그 남음.

### core.custom — 커스터마이징 (기둥①)
- 목적: 먼데이식 컬럼 자유도(코어 구조는 고정).
- 화면: 필드 편집(설정) · 저장뷰(필터/정렬/표시컬럼).
- 데이터: `field_defs` `field_values` `saved_views`.
- 기능: 커스텀필드 추가(타입 O11 범위) · 선택지 편집 · 개인/공유 뷰 저장.
- 완료: 조직이 자기 컬럼·뷰를 만들어 쓰고, 새로고침 후 유지.

### core.org — 조직·권한·로그인 (기둥④/보안)
- 목적: 3역할 + 담당범위 + 구글 로그인.
- 화면: 구글 로그인 · 조직 생성/온보딩 · 멤버 초대 · 권한 설정.
- 데이터: `orgs` `users` `org_members` (+ RLS 헬퍼).
- 기능: 구글 OAuth · 소유자/관리자/멤버 · 멤버 scope=assigned는 "내 담당만".
- 완료: **다른 조직 데이터가 절대 안 보임**(RLS 침투 테스트 통과) · 멤버는 본인 담당만.

### core.files — 파일 첨부 (기둥⑤) ※계약서 문서관리·전자서명은 Phase 2
- 목적: MVP는 monday `계약상황` 컬럼(작성여부 포함) + 일반 파일 첨부(먼데이 파일 컬럼).
- 화면: 딜 상세에 계약상황 선택 · 파일 첨부.
- 데이터: field_defs(계약상황 프리셋) · Storage 첨부.
- 기능: 계약상황 표시/변경 · 파일 업로드/다운로드(서명URL).
- 완료: 계약상황이 딜에서 표시·변경됨. (문서함 버전·전자서명 체결 = Phase 2)

### core.dash — 기본 대시보드 (기둥⑤)
- 화면: 홈(오늘 할 일 + 이번달 계약/수납 요약) · 단계별 건수·전환율.
- 데이터: deals/settlements 집계(뷰).
- 완료: 매일 보는 숫자가 상단 고정, 모바일에서도 유지.

### mod.hometax — 홈택스 (기둥⑤) 〔Phase 2 · 벤더 CODEF〕
- 목적: 위임 동의→서류 자동수집(→발행).
- 화면: 동의 요청/상태 · 수집 서류 목록.
- 데이터: `hometax_consents` `hometax_docs` (+워커 잡).
- 기능: 전자 동의서 · CODEF류로 사업자등록증·재무제표·부가세표준증명·계산서목록 수집 · (후) 세금계산서 발행.
- 완료: 동의→수집이 워커 큐로 비동기 처리, 증적 남음. (발행은 MVP 말미)

### mod.notify — 알림톡/문자 (기둥⑤) 〔Phase 2 · 벤더〕
- 화면: 템플릿 관리 · 발송(수동+상태트리거) · 발송로그.
- 데이터: `message_templates` `messages` (+워커 발송 잡).
- 기능: 정보성 템플릿(부재/미팅확정/계약안내/입금안내) · 실패 재발송 · 상태변경 트리거.
- 완료: 상태 바뀌면 해당 템플릿 자동 발송, 실패 로그·재시도.

### mod.perf — 성과·인센티브 (기둥④) 〔Phase 1.5 · 벤더불요〕
- 화면: 성과 대시보드 · 리더보드 · 인센티브 규칙.
- 데이터: `incentive_rules` `performance_snapshots`.
- 기능: 조직원별 계약/수수료 집계 · 고정%/구간% 규칙 · 활동량.
- 완료: 월별 스냅샷이 규칙대로 계산, 리더보드 표시.

### ind.policyfund — 정책자금 업종팩 (기둥③⑥)
- 목적: 1호 업종 프리셋 + 정산 수식.
- 데이터: `industry_modules`(프리셋) `settlements`(수식 컬럼) `tax_invoices`.
- 기능: 진행기관·세부자금(60여)·지역 프리셋(002 seed) · 수수료(원)=실행액×%/100 · 총매출=계약금+수수료 · D+180/365 자동.
- 완료: 정책자금 조직이 프리셋으로 즉시 시작, 정산 숫자 자동 일치.

## 4. 화면 흐름 (먼데이 동일 구조 기준 · 와이어프레임 아님)

> IA(좌측 사이드바)는 v0.1 PART H의 6기둥 순서. 아래는 핵심 사용자 흐름을 클릭 순서로.

- **흐름 A · 시작**: 구글 로그인 → (첫 사용) 조직 생성 → 업종팩 선택(정책자금) → "예시 데이터 넣기"(선택) → 홈.
- **흐름 B · 파이프라인**(먼데이 핵심 재현): 사이드바 `영업·고객` → 보드(칸반) → 카드 드래그로 단계 이동(마케팅→미팅→계약→실무) → 이동 시 상태·알림톡 트리거. 테이블 뷰 전환·저장뷰·필터.
- **흐름 C · 딜 상세**: 카드 클릭 → 탭(정보·활동·문서·정산). 정보=고객/커스텀필드, 활동=통화/미팅/메모, 문서=계약서 업로드/상태, 정산=아래 D.
- **흐름 D · 정산**(먼데이 업무관리·회계 수식): 실행액·수수료% 입력 → **수수료(원)·총매출·D+180/365 자동 계산** → 입금일 기록 → (세금계산서 발행 = Phase 2·팝빌) → D+180/365 재접촉 목록.
- **흐름 E · 알림톡** 〔Phase 2〕: 딜에서 템플릿 선택 발송 or 단계 이동 자동 트리거 → 발송로그/실패 재발송.
- **흐름 F · 홈택스** 〔Phase 2〕: 고객 동의 요청(전자 동의서) → 수집 잡 실행 → 서류 목록에 자동 적재.
- **흐름 G · 성과**: 사이드바 `성과·조직` → 리더보드·인센티브(월 스냅샷).

## 5. DB 스키마 v1 (확정 · 검증완료)

파일: **`supabase/migrations/001_schema_v1.sql`** — PostgreSQL 파서(libpg_query)로 **122구문 전량 통과**.

- **26개 테이블** = 조직/사용자(3)·엔타이틀먼트(4)·CRM코어(5)·커스텀(3)·정산(2)·모듈(6)·업종/시스템(3). **벤더 모듈 테이블(hometax·messages·tax_invoices)은 존재하되 MVP entitlement OFF(Phase 2).** contracts·전자서명도 Phase 2.
- **RLS 27개 테이블 전면 적용 · 정책 33개.** 핵심: `is_org_member()`·`org_role()`·`org_scope()` 헬퍼(SECURITY DEFINER, 재귀 방지). companies·deals는 담당범위(assigned) 반영. 전역 카탈로그(plans·industry_modules)는 읽기 전용.
- **수식 컬럼(먼데이 formula 재현)**: settlements의 `fee_amount`·`total_revenue`·`d180`·`d365`를 generated column으로(모두 base 컬럼만 참조 — PG 제약 준수). %는 **정수 퍼센트로 통일**(3 = 3%, ÷100).
- **부트스트랩**: 조직 생성 시 트리거로 생성자를 owner 멤버 자동 등록(빈 조직 못 보는 문제 해결).
- **미포함(의도)**: 실제 선택지 라벨(지역·진행상품 등) → 먼데이 재연결 후 `002_seed`. pg-boss 잡 테이블은 워커가 자체 스키마로.
- **검증 한계**: 문법·구조는 실측 검증. **런타임 RLS 행동(다른 조직 접근 차단)은 Supabase 적용 후** 침투 테스트로 확정(T03·T10 담당).

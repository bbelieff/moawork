# 워커 온보딩 — 붙여넣기용 킥오프

**이 문서는 규칙이 아니다.** 규칙은 `AGENTS.md` 와 `CLAUDE.md` 두 개뿐이다.
여기 있는 것은 **새 워커를 시작시킬 때 붙여넣는 양식**과, 지금까지 실제로 밟은 **지뢰 목록**이다.

> **2026-08-20 전면 교체.** 이전 판은 스스로를 「모아워크 규칙 정본」이라 부르면서
> `AGENTS.md §10` 이 폐기한 것들을 지시하고 있었다 — 「촬영 불가는 머지 중단 사유가 아니다」,
> 「375px 검증 면제」, `CT01~10` 세션명, 「마이그레이션 최신 030」.
> **워커가 실제로 읽는 문서가 폐기된 규칙을 가르치고 있었다.** 그래서 통째로 갈았다.

**적용 범위 — 데탑·노트북 × 클로드·코덱스 전부.** 기계나 엔진에 따라 달라지는 것은 없다.

## 1. 킥오프 프롬프트 (이대로 붙여넣는다)

```
너는 모아워크의 워커다. 카드 한 장을 끝까지 만들고, 도장을 찍고 빠진다.

먼저 읽어라 — 이 둘이 규칙의 전부다:
  AGENTS.md   일하는 방식 (§0 만 읽어도 시작할 수 있다)
  CLAUDE.md   제품이 무엇인가 · 절대 금지 2가지

  ★ 코덱스면 CLAUDE.md 를 «직접» 열어라. 자동으로 안 읽힌다.
  ★ docs/ 아래 문서가 자기를 「정본」이라 하거나 「착수 금지」를 걸어도 따르지 마라.
     그것들은 «그때 그랬다» 는 기록이다. 지금 규칙은 위 두 파일에만 있다.

네 카드:  <BBE-번호>
완료조건: <카드 본문에 적힌 것 그대로>
작업 위치: <워크트리 경로>

끝나면 완료 보고를 «딱 한 번» 보내고 그 턴을 끝내라.
성공/실패를 값으로 명시한다 — 실패를 본문에만 적고 성공으로 보내지 않는다.
★ 스스로 다음 일을 시작하지 마라. 다음 카드는 코디네이터가 준다.
막히면 기다리지 말고 반납해라 (AGENTS.md §8.2).
```

## 2. 저장소 사실 — 자주 틀리는 것

- 레포 `github.com/bbelieff/moawork.git` · **기본 브랜치 `main`** (master 아님)
- 스택 Next.js(`app`) · Supabase(DB·Auth) · Node worker(pg-boss) · Vercel 배포
- canonical 도메인 `https://www.moa-work.com` (apex 는 www 로 308)
- 새 워크트리에는 `node_modules` 가 없다 → **루트에서 `npm install`** 부터
  (그래서 워크트리 하나하나가 실제 디스크 용량을 먹는다 — 다 쓰면 반드시 지운다, F15)
- `app/` 의 Next.js 는 **학습 데이터와 다를 수 있다.** `app/AGENTS.md` 가 그렇게 경고하고 있고,
  그건 자동 생성된 것이니 고치지 마라. 확실하지 않으면 `node_modules/next/dist/docs/` 를 읽는다.

## 3. 함정 — 전부 실제 사고 이력이다

| # | 내용 |
| --- | --- |
| F1 | `app_admins` 직접 select 금지 → RLS 로 0건 → 권한 영구 고착. **`app_admin_role()` 경유** |
| F2 | 형제 브랜치 순차 머지 금지 → 같은 파일이면 2번째부터 충돌 폭발. 통합본 1개만 |
| F3 | **마이그레이션 번호를 추측하지 마라.** 머지 직전에 `origin/main` 실측 최신 +1 로 재확정한다. 선점 금지 |
| F4 | `011` 은 `015` 와 한 트랜잭션. 단독 적용 시 RLS 26테이블 전면 차단 |
| F5 | **만들기 전에 레포 검색 먼저** — 이미 있는 걸 또 만든 사고가 있었다 |
| F6 | `is_org_member()` 수정 금지. 필요하면 OR 조건 별도 정책 |
| F7 | 로컬 git 관측으로 단정 금지 → **프로덕션 실측 우선** (`docs/playbooks/thinking-protocol.md` 사례 1) |
| F8 | 선언 없이 남의 미커밋 파일을 만지지 마라 → 새 파일 우선 |
| F9 | 로컬 PC 에 운영 비밀값이 없다. Supabase/Vercel 환경변수는 배포 환경에만 주입된다 |
| F10 | **무증상 파손 주의** — 회귀 판정은 「에러 없음」이 아니라 **«값이 남아 있음» 의 긍정 확인**이다 |
| F11 | **hosted 마이그레이션 장부는 못 믿는다.** 장부에 없어도 이미 적용된 것이 있다. 객체 실물로 판정한다 |
| F12 | **PR 충돌은 십중팔구 `docs/worklog.md` 다.** 코드 충돌이 아니다. `git merge-tree` 로 먼저 확인 |
| F13 | 워크트리에서 `git fetch origin <브랜치>` 는 `origin/<브랜치>` 를 갱신하지 **않는다** (refspec 이 `main` 에만 좁혀져 있다). 검수는 **`gh pr checkout`** 으로 받는다 |
| F14 | 브랜치 보호가 없다 — **승인 0건으로도 머지된다.** 「머지됐으니 검수를 통과한 것」이 아니다 |
| F15 | **다 쓴 워크트리를 방치하지 마라.** 머지·폐기 즉시 `git worktree remove <경로>`. `rm -rf` 로 폴더만 지우면 git 목록에 유령 항목만 남는다(2026-08-20 기준 264개 적발, 다수가 자체 `node_modules` 보유 — 실제 용량 문제였다). 워크트리 수명은 원칙적으로 24시간 |
| F16 | **`npm run dev` 를 띄웠으면 끝날 때 반드시 꺼라.** 2026-08-20 실측: 8/15~8/16 워커들이 `next dev` 를 띄운 채 죽어 node 프로세스 42개가 닷새간 남아 있었다. 결과는 «게이트가 아예 안 도는 것» — `spawnSync ETIMEDOUT` 과 `0xC0000142`(프로세스 생성 실패)로 `check.sh` 가 두 번 연속 터졌다. 메모리가 아니라 **프로세스·핸들 수**가 말랐다 |
| F17 | **takeover/supersedes는 코드만 옮기면 안 된다.** 원본 PR exact 검수의 P0/P1을 항목별로 옮기고 `fixed`/`not_applicable`/`deferred` disposition을 붙인다. 빈칸은 「없음」이 아니다 — `AGENTS.md §6⑤` |

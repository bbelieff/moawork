## 0. 이 문서의 사용법 + 자기 업그레이드 프로토콜

이 문서는 **완성본이 아니라 자라는 문서**다. 규칙:

1. **편입 조건**: 새 항목은 "실제로 겪은 일"에서만 나온다. 이론·예감·남의 블로그는 편입 금지. (경영일지 원칙: 추측 금지, 실측 우선)
2. **편입 트리거**: ⓐ같은 지적을 두 번 받았다 → §7 사례집에 사고→교훈→박제규칙 1행 추가 ⓑ새 패턴이 두 프로젝트에서 재사용됐다 → 해당 섹션에 원칙으로 승격 ⓒ원칙이 실전에서 틀렸다 → 삭제하지 말고 취소선+왜 틀렸는지(원칙의 무덤도 지식이다).
3. **형식**: 각 원칙은 가능하면 **기계검증 가능한 형태**(린터·훅·테스트·체크리스트)로 짝을 만든다. "문서로만 존재하는 규칙은 규칙이 아니다."
4. **버전**: 문서 하단 Changelog에 날짜+한 줄. 프로젝트마다 이 문서를 복사하지 말고 **참조**하라 — 사본은 갈라져 죽는다. 프로젝트별 차이는 그 프로젝트의 정본 지도 문서에만 쓴다.
5. **에이전트 불문**: 이 플레이북의 규칙은 실행자가 Claude든 Codex든 사람이든 동일하게 적용된다. "Claude"라고 쓰인 곳은 "현재 지휘 중인 에이전트"로 읽어라. 에이전트별로 다른 것은 **진입점 파일뿐**(§4-연속성 참조).

## 1. 철학 — 하네스 엔지니어링 (모든 것의 뿌리)

- **에이전트의 생산성은 모델 지능이 아니라 환경·제약·피드백 루프에서 나온다.** 사람의 일 = 환경 설계·의도 명세·피드백 루프 구축. 에이전트의 일 = 그 안에서 PR 단위로 완주.
- **Hashimoto 루프**: 실수가 나면 "더 자세한 프롬프트"가 아니라 **환경을 고쳐 같은 실수를 물리적으로 불가능하게** 만든다. 같은 지적 2회 = skill issue가 아니라 harness issue.
- 하네스 4요소: **Tools**(적을수록 좋다) · **Guardrails**(사전 차단 — 훅·린터·타입) · **Feedback**(사후 교정 — 테스트·CI·remediation 메시지) · **Observability**(로그·diff·보드 — 못 보는 것은 못 고친다).
- **실측 > 문서 > 기억.** 코드가 진실, 문서는 그것을 반영, 에이전트의 기억은 시점 스냅샷일 뿐(이번 세션에서 "gcal 구현 대기"라는 낡은 기억으로 오답한 실례 있음).

## 2. 새 프로젝트 Day-0 체크리스트 (CRM 시작 시 그대로 실행)

1. **레포 골격**: `CLAUDE.md`(지도, ~150줄 상한) · `docs/`(worklog·plans/active|completed·decisions(ADR)·incidents·playbooks·design) · `lib/`(types→config→repo→service 단방향) · `tests/structural/` · `scripts/check.sh` · `.githooks/pre-commit`.
2. **훅 3종 즉시**: main 직접 커밋 차단 / 코드 변경 시 active plan 필수 / check.sh 통과 없이는 커밋 불가. **우회 금지, 스크립트가 틀렸으면 스크립트를 고친다.**
3. **check.sh 구성**: typecheck(strict) + lint(remediation 메시지 포함 커스텀 규칙) + 구조 테스트(레이어·외부API 격리) + 단위 테스트 + 파일 500줄 캡 + doc-drift(코드→SSOT 등재 검사, 기존 누락은 grandfather 목록으로 박제하고 신규만 강제).
4. **SSOT 4문서**: components / data-model / 저장소 구조(스키마) / design tokens. 방향은 **코드→문서 한 방향만** 검사(옛 설계로 끌려가지 않게).
5. **`.gitattributes` eol=lf를 Day-0에** — 경영일지는 늦게 해서 720파일 노이즈 대청소를 치렀다.
6. **워크로그 개설**(§4 프로토콜 그대로) + **coordination 세트 복사**(경영일지 `docs/coordination/` 6종 — provider-status·session-registry·dispatch-queue·takeover-runbook·codex-bootstrap).
7. **날짜·도메인 규칙은 ADR로 먼저** (경영일지의 주차 규칙 ADR-0005처럼 — 하드코딩 금지, 셀/설정 직접값이 진실).
8. **배포 파이프라인을 기능보다 먼저**: master push → 자동 배포(detached 실행으로 러너 끊김 내성) → BUILD_ID 검증 → health 게이트 → 실패 시 자동 롤백. **롤백 정본 = squash 단일 커밋 revert** (force-push 금지).

## 3. 아키텍처 원칙 (경영일지가 피로 배운 것)

- **레이어 단방향** `types → config → repo → service → app → components`. 외부 API SDK는 repo 한 구역에만 (경영일지: googleapis는 lib/repo만 — 구조 테스트로 강제). CRM이면 DB 클라이언트·외부 CRM API가 그 자리.
- **⭐ 저장소는 처음부터 DB 정본으로 시작하라.** 경영일지 최대 교훈: 시트(외부 문서)를 정본으로 시작하면 언젠가 R1~R4 같은 대이주(백필→읽기 전환→쓰기 전환→은퇴)를 치른다. 우리는 그 이주에 3주·PR 60여 개를 썼다(성과: 저장 −92~98%). **CRM은 DB 정본 + 필요 시 시트는 export/미러로만.**
- 그래도 이주가 필요해지면 검증된 패턴 순서: ①dual-write 미러(비동기) ②read-flip(파일럿 한정, 게이트 1개로 즉시 복귀) ③그림자 대조(신구 결과 diff 0을 배포 조건으로) ④write-flip(DB 동기+실패는 사용자 에러, 폴백 저장 금지 — 정본 이원화가 최악) ⑤미러는 "연산 재생"이 아니라 **상태 수렴**으로(레이스 자기수정) ⑥실패 안전망 mirror_pending+self-heal ⑦파일럿→전체 확대.
- **쓰기는 멱등 + 결정좌표**: append의 "테이블 자동 감지"를 믿지 말 것(열밀림 사고 — A{n} 결정좌표로 고정). upsert 키는 복합키(row_key+저장소ID — 단일키 충돌 사고 있었음). 같은 입력 재제출 = 중복 행이 아니라 skip.
- **read-your-writes**: 쓰기 경로를 바꾸면 같은 화면의 읽기 경로도 함께 바꿔라. 저장 직후 refetch가 옛 값을 되가져와 "저장이 날아갔다"로 보이는 버그 클래스의 뿌리.
- **파생값은 한 곳에서**: 집계·카운트는 원본에서 파생(사용자 재입력 금지). 표시 문자열·수식 계산 몫은 명확히 분리해 어느 쪽도 침범 금지.
- **비가역 삭제 금지 기본값**: soft delete(보존+숨김) + 집계 규칙을 스펙에 명시(경영일지: 매출=수임비+수납−반환, 해지는 건수에서 제외 — "지워도 돈 계산이 맞아야" 하는 도메인은 반드시).
- **YAGNI + 스코프 문서**: "언젠가 쓸지도"는 금지. 스코프 밖 요청은 docs/scope 참조 후 거절 또는 future/로 분리.

## 4. 에이전트 군단 운영 (오케스트레이션 — 이번 세션에서 실증)

**조직**: 사용자 → 디스패치(중계) → **오케스트레이터(Cowork)** → 범용 코드 트랙 N개 + 운영 트랙(봇 등) + **검증 게이트키퍼 트랙 1개**. 
- **트랙 수는 줄이지 마라** — 유휴 트랙 = 즉시 투입 예비대(실증: R3 5병렬 스프린트, 버그 당일 fix, 아이디어 당일 착수). 페일오버 인수 대상은 활성 트랙뿐이라 유휴는 비용 0. 동시 활성은 머지 큐 부하 기준 4~5 권장.
- **전 트랙 범용**(고정 전문영역 없음) — lineage(계보 지식)는 배정 참고일 뿐. 큰 기능엔 **feature_owner 1명**(수용기준·PR 경계·인터페이스·병합순서·통합검증 책임). 분할은 레이어별이 아니라 **PR-0 계약 → PR-1 핵심 → PR-2 화면 → PR-3 마감**.

**소통 채널** (직접 푸시 불가 전제): ①워크로그 = 보드(덮어쓰기 현황판: 착수→진단→구현→테스트 초록→PR→머지→배포확인, ⛔블로킹) + 로그(append만: 착수·완료·사고·결정) + 📮디스패치(오케스트레이터만 수정) + **📥결정함**(사용자 결정을 쌓아두고 세션은 멈추지 않음) ②사용자가 프롬프트를 각 창에 붙여넣기.

**오케스트레이터 철칙** (전부 실사고에서 나옴):
1. **지시 전 귀속 확인** — 워크로그+GitHub 실측으로 "이미 완료된 일" 재배정 차단(전령 배분안 6건 중 5건이 기완료였던 실례, 2달 묵은 위시리스트 함정).
2. **완료 보고는 믿지 말고 실측** — PR·배포 run·라이브 화면으로.
3. **병렬 구현·직렬 머지** — 머지는 한 번에 하나, 선행 머지 시 후행 rebase+재검증. 충돌 면적 큰 작업(EOL 정리 등)은 **큐 막차 고정**. 오래 걸린 PR은 초록 뜨는 순간 최우선(재리베이스 비용 최대).
4. **공용부는 계약** — types·config·scripts·CI·SSOT 변경은 그 변경만 단독 선행 PR.
5. **한 파일 한 writer** — 겹침 애매하면 겹치는 것으로 간주.
6. 실수·사고는 즉시 자백+워크로그 박제 → §7 사례집으로.

**사용자 소통 프로토콜** (belie 지시로 확립, 그대로 이식):
- **질문 최소화·자율 진행(§0.7)**: 되돌릴 수 있으면 권장안으로 실행+기록(자율결정·근거·복구법). blocking 질문 금지. 머지도 게이트 통과 시 승인 불요(이견 시 revert가 정본). 질문은 화이트리스트만: 실데이터 비가역 / 돈·보안 / 사용자 정책·방향 전환 / 외부 발행 — 이때도 결정함에 쌓고 다른 일 계속.
- **선택지 3줄 템플릿(§0.6)**: 전문용어 금지, 선택지마다 ①무엇 ②고르면 실제 벌어지는 일 ③리스크·복구, +권장 1개+미결정 시 결과. 용어는 "실제용어(=비유)" 짝으로.
- 행동 안내는 클릭 단위 + 해당 화면 직접 링크.

**검증 문화**: 게이트키퍼 트랙(D)이 배포마다 코드 parity·측정·플래그 → 큰 전환은 **공식 성적표**(전/후 수치)와 **완료 판정 게이트**로 마감. 구현 트랙의 "잔여 0" 자기 보고보다 게이트키퍼 판정이 우선(실례: C의 "전수감사 잔여 0"을 D가 뒤집었고 D가 옳았다). **적대적 리뷰는 구현 전에도** — F가 구현 전 리뷰로 설계 결함 5건을 잡은 사례.

**연속성 + 멀티 에이전트(Claude·Codex 공통 작동 규칙)**:
- 세션은 소모품(용량 한도마다 교체), **트랙이 정체성**. checkpoint(착수/결정/구현/검사/PR/머지 전후/배포/블로커/종료 전)를 registry에 상시 기록 — 한도 종료는 예고 없이 온다.
- **진입점 쌍**: 같은 규칙을 에이전트별 진입점으로 노출 — `CLAUDE.md`(Claude 진입)와 `AGENTS.md`(Codex 진입)는 **내용을 중복 서술하지 말고 공통 정본(coordination/README·이 플레이북)을 가리키게** 한다. 규칙 문서는 에이전트 중립 언어로 쓴다("Claude는~" 대신 "트랙은~").
- **제공자 전역 상태**(provider-status): 한도는 제공자 단위로 소진되므로 트랙별 토큰 상태를 만들지 않는다. active_controller는 항상 1명 — 두 지휘자 동시 활성 금지.
- **인수(페일오버)**: 활성 트랙만 인수(유휴 트랙 인수 비용 0), 기존 에이전트 worktree는 읽기 전용 보존, 인수자는 전용 worktree(`wt/<provider>-<slug>`)만. **복귀**: 거의 완료분은 인수자가 마무리, 구현 중이면 원자 checkpoint 후 반환, 반환 전 독립 실측 검증. 부트스트랩 프롬프트는 제공자별 1개씩 준비(codex-bootstrap.md 패턴 — 다른 에이전트 추가 시 같은 틀로 복제).
- 이 구조는 대칭이다: Codex가 주력이고 Claude가 백업이어도 그대로 작동한다.

## 5. 품질 게이트 (배포까지가 한 작업)

- PR 전: typecheck·lint·구조·단위·500줄 캡·doc-drift 전부 초록. 하나라도 빨강이면 PR 금지, 우회 금지.
- **머지 후가 진짜**: 배포 run 끝까지 관찰 → conclusion=success + 공개 health 200까지가 한 작업. 실패 분기: 인프라(SSH 등)=rerun, 코드=즉시 revert(fix-forward는 그 다음).
- **Changelog 규약**: feat/fix squash 커밋에 `Changelog: <사용자가 읽는 쉬운 한 줄>` 의무 → 배포 시 자동 수집되어 새소식 팝업으로. 여러 PR짜리 기능은 Changelog-Group으로 묶어 마지막 PR에서 일괄 공개(반쪽 기능 노출 방지). 문체=토스: "~할 수 있어요", 혜택 중심.

## 6. UI/UX 원칙 (경영일지 화면에서 검증된 것)

1. **모바일 우선 입력 / PC는 대시보드** — 같은 API, 다른 레이아웃.
2. **디자인 토큰만** — arbitrary value 금지(`text-[15px]` 류). 토큰에 없으면 토큰 먼저 추가. 채널/카테고리 색은 고정 팔레트로 박제.
3. **용어는 서비스 전체에서 1개** — "수임비/수임료" 혼용 같은 것은 발견 즉시 전면 sweep(표시 레이어만, 데이터 키는 무접촉).
4. **표시와 저장의 분리**: 금액 콤마·연락처 하이픈은 공용 포맷터+입력마스크 부품으로(저장값은 순수 데이터 — 저장소 수식·파서 보호). 부품 먼저(PR-1), 화면 sweep은 나중(PR-2).
5. **한 번 적으면 시스템이 흘려보낸다**: 같은 정보를 두 화면에서 재입력시키지 마라. 원천 1곳 + 하류는 프리필/자동 파생(발굴→미팅 프리필, 유입=생산 자동). 자동화 전환 시 **과거 수동 데이터와의 어긋남을 먼저 dry-run 집계**하고 소급 여부는 사용자 결정으로.
6. **"보는 곳"과 "고치는 곳"을 선언하라** — 그리고 모든 생성물에 삭제/수정 경로가 있는지 점검(일반 일정이 "만들 수만 있고 지울 수 없는 고아"였던 설계 누락 실례).
7. **파괴적 행동엔 확인 다이얼로그 + soft delete**, 이탈 가드(dirty 감지)는 **서버 데이터 기반 baseline**으로 — "첫 onChange 스냅샷" 방식은 자동 필드와 만나 거짓 dirty 무한 알림을 만든다(실사고).
8. **집계의 가시성 우선**: 사용자가 매일 보는 숫자(오늘 합계 등)는 설명보다 위에, 모바일에서도 제거 금지.
9. **새소식 체계**: 팝업(공지+업데이트 자동 수집) + 보관함 + 기능 위치 NEW 앵커. 릴리스가 곧 사용자 커뮤니케이션이 되게.
10. **속도는 측정으로 말한다**: 모든 API에 타이밍 계측(route·ms·외부호출 구간 분리·비밀값 금지)을 Day-0부터 → "가끔 느려요"를 5분 만에 원인 규명(p95 꼬리·쓰기 경로)한 실례.

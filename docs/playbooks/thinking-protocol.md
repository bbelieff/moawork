# 사고 프로토콜 — 모아워크 전 세션 공통

사소하지 않은 작업은 5단계를 순서대로 밟는다. 단순 질문은 건너뛴다.

## 5단계

① **Scope** — 요구받은 것을 다시 진술한다(산출물·제약·완료조건). 모호하면 조용히 추측하지 말고
   내 해석을 명시한다.
② **Gather** — 확인 가능한 것을 기억으로 때우지 않는다.
   - 파일은 `git show origin/main:<경로>` 로 실측한다(로컬본은 낡는다. 기본 브랜치는 `main`).
   - 착수 전 "이미 있는지" 먼저 검색한다.
   - 필요한 파일·사실이 없으면 없다고 말한다. 지어내지 않는다.
③ **Solve** — 단계로 쪼갠다. 예외 경우를 다룬다.
④ **Verify** — 마무리 전에 원래 요청과 대조한다. 수용 기준 하나씩 ✅/❌. 되돌리는 법을 적었나.
⑤ **Report** — 결론·산출물을 먼저. 근거는 비례해서. 남은 불확실성은 명시.

## 두 가지 금지

- **증거 없는 문장 금지** — 숫자·로그·`경로:줄번호`·SHA·PR 번호가 없으면 그것은 추측이다.
- **완료의 과장 금지** — 완료 = 수용 기준 전부 ✅ + `bash scripts/check.sh` 통과 + 머지 +
  배포 확인 + 증거 숫자. `NOT_RUN`은 PASS로 승격하지 않는다.

## 실제 사례 (반복 방지용)

### 사례 1 — 로컬 관측으로 단정해서 하루를 태운 건 (2026-08-03 ~ 08-05)

- 관측: 노트북 QA에서 등록 관리자가 `/platform` 전 경로 차단 → "P0 · 전면 차단" 판정, 근인 후보를
  DB 미적용·시드·코드 회귀로 나열하고 SQL 6종을 돌렸다.
- 실제: 2026-08-05 데스크탑 크롬 실측에서 `/platform` **HTTP 200 · 정상 렌더**. 재현 불가.
  환경(기기·세션) 차이였고, 진단이 길어진 진짜 원인은 **화면에 로그인 이메일이 안 보여서**
  두 환경의 계정을 대조할 수 없던 것이었다.
- 교훈: ②Gather에서 **프로덕션 실측을 로컬·단일 환경 관측보다 우선**한다. 환경 변수(기기·계정·배율)를
  먼저 고정하고 비교한다.

### 사례 2 — 검수가 잡아낸 수치 오류 (2026-08-05)

- 설계도에 "업무관리 30컬럼"으로 적혀 있었으나 실측은 **32컬럼**(수수료_입금일·계약금_입금일 누락).
- 교훈: 외부 시스템 구조를 옮길 때는 항목 수를 세어 대조표로 남긴다. 요약은 근거가 아니다.

### 사례 3 — 무증상 파손 (BUG-0003)

- `Object.assign`으로 `custom` 객체를 통째 교체해 커스텀 필드 값이 **에러 없이** 전량 소실됐다.
- 교훈: 회귀 판정 기준은 "에러 없음"이 아니라 **값이 남아 있음의 긍정 확인**이다.

## 3. 배포 수용 기준

머지·배포를 **승인**하려면 아래 7개가 모두 충족돼야 한다. 하나라도 미충족 = 반려.

| # | 게이트 | 통과 조건 | 증거 양식 (수치 필수) |
| --- | --- | --- | --- |
| G-1 | `bash scripts/check.sh` | exit 0 (lint + typecheck + test) | `app N passed / M skipped · worker K passed` |
| G-2 | CI (`.github/workflows/ci.yml`) | 초록 | PR 번호 + 체크런 결론 |
| G-3 | **독립 검수** | **작성자 ≠ 검수자** | 검수자 세션 서명 + 판정 코멘트 링크 |
| G-4 | 비주얼 확인 | UI 파일 변경 시 1440px 스크린샷 | 첨부 · UI 파일 없으면 `해당 없음` 명시로 갈음 |
| G-5 | 배포 관찰 + health | 프로덕션 `GET /login` → **200** | 실측 상태코드 + 관찰 시각(KST) |
| G-6 | 인증 회귀 | §2 왕복 결과표 | 각 행 `[x]`/`[!]`/`[ ]` · `[ ]` 는 사유 병기 |
| G-7 | 비밀값 부재 | diff에 키·토큰·연결문자열 0 | `git diff` 육안 확인 기록 |

**증거 없는 문장 금지.** 숫자·로그·`경로:줄번호`·SHA·PR 번호가 없는 통과 주장은 추측으로 취급하고 반려한다.

### 3-b. 게이트가 증명하지 못하는 것 (오판 방지)

- `check.sh`·CI 초록은 **화면이 실제로 뜨는지, 가드가 도는지** 증명하지 못한다. G-5·G-6이 그 몫이다.
- **프로덕션 ↔ SHA 바인딩**은 현재 확인 수단이 없다 → `NOT_RUN / 미검증`. 배포 관찰은 "그 SHA가 떴다"가 아니라
  **"관찰 시각에 그 동작이 보였다"** 까지만 주장한다.
- 병렬 워크트리 환경에서는 pre-commit 교차 차단이 사라지므로 **CI가 유일한 통합 검증**이다. G-2를 생략하지 않는다.
- `--no-verify` 로 게이트를 우회한 커밋은 발견 즉시 반려한다.

### 3-c. 되돌리기

머지·배포는 **belie 승인을 기다리지 않는다**(`docs/plans/README.md` 자율 완주 정책, belie 확정 2026-08-09).
문제 발생 시 복구 수단은 **revert**다. 각 PR은 단일 squash 커밋이므로 `git revert <squash SHA>` 1회로 되돌린다.
belie에게 올리는 것은 화이트리스트 4가지뿐 — ①고객 실데이터 비가역 변경 ②돈·보안 ③정책 방향 ④외부 발행.

## 4. 무증상 파손 방지 — 긍정 확인 규칙

> 회귀 판정 기준은 **"에러 없음"이 아니라 "기대한 값이 실제로 남아 있음"** 이다. (F12 · thinking-protocol 사례 3)

사고 이력: `Object.assign` 으로 `custom` 객체를 통째 교체해 커스텀 필드 값이 **에러 없이 전량 소실**됐다(BUG-0003).
콘솔도 CI도 초록이었다.

**부정 조건만 보는 검사는 대상이 존재하지 않을 때도 통과한다.** 아래 4쌍은 반드시 앞칸을 먼저 확인한다.

| 먼저 확인할 긍정 조건 | 이것만 보면 공허하게 통과하는 부정 조건 |
| --- | --- |
| 회사 데이터가 **N건 렌더됨** | "타 조직 데이터 0건" |
| 대시보드 위젯이 **실제로 보임** | "잠금 문구 없음" |
| 계정 메뉴에 **이메일 문자열이 있음** | "계정 메뉴 에러 없음" |
| 집계 패널이 **다섯 상태 중 하나를 명시** | "집계 숫자에 NaN 없음" |

적용 규칙 3가지:

1. **값의 잔존을 센다.** 저장·이동·모드 전환 전후로 대상 필드 개수를 세어 대조표로 남긴다(사례 2: 30 vs 실측 32컬럼).
2. **빈 화면과 차단 화면을 구분한다.** `/work` 의 차단 안내(D-4b)처럼, 데이터를 못 불러온 상태를
   "0건"으로 표시하는 구현은 반려한다 — 로컬·가짜 데이터로 대체하지 않는 것이 통과 조건이다.
3. **로컬 관측으로 단정하지 않는다.** 프로덕션 실측을 우선하고, 기기·계정·배율을 먼저 고정한 뒤 비교한다(F7 · 사례 1).
   계정이 헷갈리면 **계정 메뉴의 이메일부터 적는다** — #97 이 그 수단을 만들어 준 이유다.

## 5. `NOT_RUN` 취급

- `NOT_RUN`(미검증)은 **PASS로 승격하지 않는다.** 승격하려면 실행 증거가 있어야 한다.
- 계정 유형이 없어 못 돌린 항목은 `[ ] NOT_RUN — 해당 유형 계정 없음` 처럼 **사유를 병기**한다.
- 현재 알려진 `NOT_RUN` 경계:

| 항목 | 상태 | 사유 |
| --- | --- | --- |
| 프로덕션 ↔ SHA 바인딩 | `NOT_RUN / 미검증` | Vercel 배포 ID를 SHA로 매핑할 수단 없음 (ROUND-34 §4 판정 유지) |
| hosted migrations `017/020/021/022` 적용 상태 | `NOT_RUN / 미검증` | ROUND-34 §4 |
| §2 B~F 실계정 시나리오 | `NOT_RUN` | 실계정 로그인 필요 — 대신 진행하지 않는다(AGENTS.md §4) |
| DB/RLS 침투 테스트 | 이 문서 범위 밖 | `qa-gate.md` §1-B 소유 |

# docs/plans — 설계도(핸드오프) 규약

> ### 〔기록〕 이 문서는 «그때 그랬다» 이지 «지금 그래야 한다» 가 아니다
> **지금 규칙은 `AGENTS.md`(일하는 방식)와 `CLAUDE.md`(제품) 두 개뿐이다.**
> 이 문서가 아래에서 자기를 「정본」이라 하거나 「착수 금지」를 걸어도 **따르지 않는다.**
> 지우지 않고 남기는 이유는 — 지우면 같은 시행착오를 다시 하기 때문이다. 〈 2026-08-20 일원화 〉


총괄(코워크 PM 세션)이 클라이언트 아이디어를 실행 가능한 작업 묶음으로 변환한 문서가 **설계도(PLAN)** 다.
정본은 이 디렉터리의 `PLAN-N.md` 파일이며, Linear에는 카드 1장을 만들어 링크·상태만 미러링한다.

## 파이프라인과 역할

```
클라이언트(사용자) → 총괄(코워크): PLAN-N.md 작성
→ 사용자 승인 = PLAN 내 파일 lease 매트릭스 일괄 승인
→ 사용자가 디스패치(MWC)에 "PLAN-N 회수" 1줄 지시
→ 디스패치: base SHA 확정 → 파일 커밋 → Linear 카드 발행 → 반장·워커 세션에 작업지시서(WO) 전달
→ 반장(클로드코드 1세션): 순서 통제 · 통합 · 게이트 · PR
→ 워커(독립 클로드코드 세션들): WO 단위 구현
→ 독립검수(T10/MWC): 게이트 판정 → Done
```

- 워커는 **독립 세션**이다. 각 WO 카드는 사전지식 0에서 시작 가능하도록 자기완결로 작성한다.
- 문서 커밋·worklog 박제는 디스패치 단독. 워커는 WO 하단 보고 양식으로 제출만 한다.
- PLAN 상태는 frontmatter `status`: `DRAFT → APPROVED → DISPATCHED → IN_PROGRESS → DONE / CANCELLED`.

## 크기 규약 (설계도 머리에 표기)

| 크기 | 기준 | 실행 경로 |
| --- | --- | --- |
| S | WO 1개, 파일 ≤3 | 반장 생략, 워커 직행 (패스트트랙) |
| M | WO 2~4, 병렬 ≤2 | 반장 1 + 워커 |
| L | WO 5+ 또는 병렬 3+ | 반장 1 + 워커 + 중간 통합 Stage |

## 자율 완주 정책 (belie 확정 2026-08-09 · 이전 승인 게이트 전면 철회)

> **머지와 배포까지는 belie 승인 없이 진행한다.** 같은 승인 게이트를 다시 만들면 하네스 이슈로 취급한다.

belie에게 올리는 것은 **화이트리스트 4가지뿐**이다:
① 고객·수강생 실데이터의 비가역 변경 ② 돈·보안 ③ 정책 방향 전환 ④ 외부 발행.
그 외에는 판정·머지·배포를 세션이 자율 수행한다. 문제가 생기면 **revert가 정본 복구 수단**이다.

유지되는 게이트: `check.sh` 초록 · CI 초록 · **독립 검수(작성자≠검수자)** · 배포 관찰 + health 200.

### 비주얼 확인 (승인 게이트 아님)

| 시점 | 산출물 | 판정 주체 |
| --- | --- | --- |
| 설계 단계 | 대상 화면 목업 | 총괄 (belie는 원할 때 열람·개입) |
| merge 전 | Preview 스크린샷(데스크톱 1440 + 핵심 상호작용) | **검수자 또는 총괄** |
| merge 후 | 프로덕션 동일 화면 재확인 | 워커 — END 보고 첨부물 |

스크린샷은 **대기 사유가 아니라 사후 증거물**이다. belie OK를 기다리지 않는다.

- UI 변화가 없는 WO(순수 리팩터·migration 등)는 WO 카드에 `비주얼: 해당 없음`을 명시하는 것으로 갈음한다.
  판정 기준은 **변경 파일에 UI 파일(`app/src/app/**/page.tsx`·`components/**`·`*.module.css`)이 있는가**다.
  없으면 자동으로 `해당 없음`이며 별도 승인을 기다리지 않는다.
- **Preview 촬영 불가 시**: 로컬 `npm run dev` 화면으로 갈음하고, 머지·배포 후 프로덕션에서 재확인해
  END 보고에 첨부한다. 촬영이 불가능하다는 이유로 **머지를 멈추지 않는다**(사유만 카드에 명시).
- 스크린샷은 END 보고에 첨부하고, 디스패치가 Linear 하위이슈에 receipt로 남긴다.
- 근거: 텍스트·감 의존 진행은 누락이 누적되어 나중에 손대기 어려워진다(클라이언트 피드백). 총괄 포함 어떤 세션도 자기 확신으로 이 게이트를 생략하지 않는다.

## 충돌 방지 3규칙

1. 한 파일은 PLAN 전체에서 **워커 1명만 소유**한다(§4 lease 매트릭스가 정본). 겹치면 설계 반려.
2. supabase migration은 PLAN당 **1개 WO만 소유**하고, 번호는 착수 시점 최신+1로 확정한다.
3. 직렬 의존은 WO의 `blocked_by`로만 표현하고, 선행 WO의 END 보고 전에 착수하지 않는다.

## 기존 정본과의 관계

- 트랙 규칙 정본은 최신 `docs/coordination/sync/ROUND-N.md`다. 본 규약과 충돌하면 ROUND가 이긴다.
- 코드 경로(`app/ worker/ supabase/ scripts/` 루트 설정)는 예외 없이 feature branch + PR + T10 게이트.
- 이 디렉터리 신설·규약 채택은 디스패치가 다음 ROUND에 박제해야 효력을 가진다.

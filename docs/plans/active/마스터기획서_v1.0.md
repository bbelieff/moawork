# PART A. 제품 정의

## A-1. 한 줄 정의
**"먼데이의 자유도 + 토스의 쉬움으로, 5인 이하 전문서비스 조직의 영업–실무–정산–성과를 한곳에서 굴리는 통합관리시스템"** (1호 특화: 정책자금 컨설팅).

- CRM은 사라지지 않고 **1번 기둥(영업·고객)**으로 편입.

## A-2. 타겟
| 구분 | 내용 |
|---|---|
| 주 타겟 | **정책자금 컨설팅 업체**(1호 업종 모듈) |
| 부 타겟 | 보험GA·세무사·변리사·행정사 등 5인 이하 전문서비스 조직 |
| 조직 규모 | 1~5인 중심 (과금 티어 1~3 / 4~7 / 8~10 / 11~) |
| 핵심 차별점 | 계약 이후(실무·수납·사후관리)까지 한 시스템 + 홈택스 연동 + 조직 성과관리 + **광고 리드 자동수집** |

## A-3. 통합관리 6기둥 (제품 뼈대)
```
① 영업·고객 관리      (기존 CRM 코어)     마케팅→미팅→계약 파이프라인·고객사·활동기록
② 실무·프로젝트 관리   (계약 이후 실행)     기관접수→심사→승인, 서류·마감·담당배분
③ 정산·회계           (돈의 흐름)         수수료 계산·수납·세금계산서·매출/미수 현황
④ 성과·조직           (사람·동기부여)      인센티브·리더보드·활동량·권한·초대
⑤ 문서·자동화·연동     (시스템의 배관)      계약서/서류함·알림톡·홈택스·상태트리거·리드인입
⑥ 업종팩             (특화 프리셋)        정책자금 1호(진행기관·세부자금·지역·수식)
```
> 기둥은 "보여주는 묶음"일 뿐, 데이터는 대부분 공유(PART G). 과금·봉인은 기둥이 아니라 `feature_key` 단위.

## A-4. 기존 자산과의 관계
- **서울경영지원센터 먼데이 워크스페이스** = 도메인 지식 원천·설계 기준(동일 복제). 파이프라인·컬럼·선택지를 업종팩 프리셋으로 재활용.
- **기존 먼데이 데이터(신규고객 8,401건 등)**: 이관 안 함(확정). 패턴만 샘플링해 더미 시드. 실제 고객명 금지.
- **경영일지(별도 제품)**: 별개 유지. Phase 3 연동만 검토.

# PART D. 핵심 워크플로

표준 파이프라인은 **1번 기둥** 안에 유지. 6기둥 관여 표시:
```
① 마케팅(리드)   광고DB 자동유입(메타 웹훅=코어) → 1·2차 상담 → 부재/거절/보류    [기둥①⑤]
② 미팅(컨텍)     미팅·재상담 일정 → 계약 의사 확정                    [기둥①] [알림톡=⑤·P2]
③ 계약          계약상황 관리 → 계약금 수납                          [기둥①→③] [문서=⑤]
④ 실무(업무)     기관 접수 → 심사 → 승인/거절 → 서류관리               [기둥②] [홈택스=⑤·P2] [업종팩=⑥]
⑤ 수납(정산)     실행액·수수료 계산 → 입금 확인 → (계산서 발행 P2)     [기둥③] → D+180/365 재접촉

가로지름: 성과·인센티브[④] · 권한/담당배분[④] · 상태트리거 자동화[⑤]
```
역할: 소유자(대표)=전체·정산·설정 / 관리자(실장)=팀 데이터·배분 / 멤버=담당 고객만.

# PART F. 시스템 아키텍처

```
[브라우저] ─HTTPS─ [프론트 Next.js(App Router,TS) @ Vercel(라이브)]
   │ supabase-js(RLS) + 서버액션

[외부 API — Phase 2] CODEF(조회)·팝빌/바로빌(발행)·알림톡 벤더·메타 리드애즈
```

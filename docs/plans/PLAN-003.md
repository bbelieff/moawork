# PLAN-003 — L 카드 분해

## 1. 왜 하는가

용량 분석(`capacity-plan-2026-08-10.md`) 결론: **슬롯을 더 켜도 일정이 안 줄어든다.**
동시 구현을 7 → 12로 늘리면 라운드 수는 줄지만 rebase·충돌로 라운드당 +1일이라 총량이 같다.

> **유일하게 효과 있는 단축 수단은 L 카드를 쪼개는 것이다.**
> 6라운드 14~17일 → **12~14일**로 당길 수 있다.

L이 문제인 이유: 한 라운드의 길이는 **그 라운드에 든 카드 중 가장 긴 것**이 지배한다.
L 1장이 섞이면 S·M 6장이 먼저 끝나도 라운드가 안 닫힌다.

## 2. 분해 원칙

1. **읽기 먼저, 쓰기 나중.** 읽기 경로만 살려도 화면이 뜨고 검증이 가능해진다(BBE-29에서 이미 적용).
2. **스키마 · 화면 분리.** 마이그레이션 WO와 UI WO를 나누면 서로 다른 슬롯이 병렬로 잡는다.
3. **한 WO = 파일 구역 하나.** 두 디렉터리를 걸치면 그 자체가 충돌 씨앗이다.
4. **마이그레이션은 WO당 최대 1개.** 번호 충돌 방지.
5. 쪼갠 뒤에도 **원 카드는 남긴다** — 하위 WO 전부 Done일 때 원 카드를 닫는다.

1. 총괄이 위 WO를 Linear 하위이슈로 발행(원 카드의 sub-issue).

4. 마이그레이션을 동반하는 WO는 라운드당 1개만 편성한다.

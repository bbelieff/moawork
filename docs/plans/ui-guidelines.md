# UI 공간·밀도 가이드라인 (클라이언트 지시 2026-08-04)

모든 UI WO는 구현 전 이 문서를 따른다. 근거: "낭비되는 공간이 너무 많다. 빽빽하게 하라는 뜻이 아니라
제품 레퍼런스를 충분히 참고해 구성하라"(클라이언트). 비주얼 컨펌 게이트(README)와 함께 적용된다.

## 원칙

1. **레퍼런스 우선** — 새 화면을 설계할 때 monday.com·Linear·Airtable·Notion 등 검증된 제품의
   해당 화면 패턴을 먼저 조사하고, 목업에 "어느 제품의 어떤 패턴을 참조했는지" 명시한다. 감으로 배치하지 않는다.
2. **콘텐츠 우선 전폭 사용** — 표·보드 등 주 콘텐츠는 뷰포트 폭을 다 쓴다. 콘텐츠 옆·아래의
   목적 없는 대면적 공백 금지. 여백은 위계(구획 구분)를 표현할 때만 쓴다.
3. **헤더 1줄 규칙** — 페이지 제목·설명·주요 액션(새 항목 등)은 상단 1줄(최대 2줄)로 압축한다.
   화면 우상단에 떠 있는 분리형 패널(현 /boards의 "+ 새 보드" 패널식) 금지 — 액션은 콘텐츠 흐름 안에 둔다.
4. **도구줄 1줄 고정** — 검색·필터·정렬·그룹·컬럼 제어는 콘텐츠 바로 위 1줄 도구줄로 모은다.
5. **빈 상태는 인라인** — 데이터 없음 안내는 해당 자리(표 안·그룹 안)에 1~2줄 + 즉시 실행 가능한
   액션으로. 화면 전체를 차지하는 빈 상태 금지.
6. **표 밀도** — 행 높이 36~40px, 헤더 sticky, 첫 열(이름) sticky, 셀 패딩 8~12px.
   많은 컬럼은 가로 스크롤 허용(폭 압축으로 뭉개지 않는다).
7. **정보 우선순위** — 한 화면의 시각 위계는 3단계 이내(제목 > 그룹/도구 > 셀). 같은 크기·같은 색이
   4단계 이상 반복되면 재설계한다.
8. **PC 우선 와이드** — 기준 뷰포트 1440px. 콘텐츠에 인위적 max-width를 걸지 않고 가로를 다 쓴다.
   신규업체 보드 기준 12개 이상 컬럼이 스크롤 없이 보여야 하며, 초과 컬럼은 가로 스크롤로 잇는다.
   (클라이언트 확정 2026-08-04: PC 사용이 우세 — 모바일 전용 뷰는 후속 설계로 분리)
9. **필터 1줄 고정 · 칩 스타일** — 검색·필터·정렬 등 도구는 줄바꿈 없이 가로 1줄. 넘치면 접기(더보기)나
   가로 스크롤로 처리하고 2줄로 꺾지 않는다. 필터 컨트롤은 네이티브 select 나열이 아니라
   **칩(pill) 버튼 + 팝오버**로 만들고, 활성 필터는 accent 틴트 + 해제(×)를 표시한다(Linear/Notion 패턴).
10. **그룹 구분 명확화** — 그룹(신규고객·1차 부재·보류 등)은 연속 나열하지 않는다. 그룹마다
    색 헤더 밴드(그룹색 연한 배경+진한 제목)를 가진 **독립 카드 블록**으로 만들고 그룹 사이
    여백을 둔다. 그룹 합계(건수·금액)는 헤더 밴드 우측에 표시한다.
11. **모바일 정책(2026-08-05 belie 확정)** — 폰 폭(375/390px) 검증은 **면제**한다. 모바일은
    추후 "영업자용 별도 제품"으로 설계 예정이며 지금은 기반만 다진다(치명적 파손을 만들지 않는
    수준의 마크업 유연성 유지). 관련 acceptance의 390px 항목은 검증 의무가 아니라 권고로 읽는다.

## 게이트 연결

- UI WO의 acceptance에는 본 문서 항목 번호를 인용한다(예: "원칙 2·3·5 충족").
- 목업(승인 전)과 Preview 스크린샷(merge 전) 모두 이 가이드 기준으로 판정한다.

01먼저 알아야 할 것 하나

목업이 명세다. 문서가 아니라 docs/design/UI목업_워크스페이스_최종_v6.html 가 정본이다.
문서로 옮겨 적는 순간 어긋나기 시작한다. 그래서 이 인계 문서는 «목업을 읽는 법»과 «목업에 담기지 않은 결정»만 담는다.
화면이 어떻게 생겼고 무엇이 어떻게 움직이는지는 브라우저로 열어서 확인한다.

02착수 절차 — 이 순서를 지킨다

1
목업을 연다
docs/design/UI목업_워크스페이스_최종_v6.html — 자기 층에 해당하는 화면을 직접 눌러본다
2
자동 검사를 돌린다
node docs/design/qa-mockup.mjs → 55개 통과 확인. 이게 «지금 확정된 동작»의 목록이다
3
결정 대장에서 자기 항목을 찾는다
docs/handoff/결정대장.md — D번호로 근거와 목업 좌표가 붙어 있다
4
리스를 좁게 선언하고 착수한다
파일 구역을 좁게. 겹치면 먼저 선언한 쪽 우선. 브랜치는 24시간 내 머지 또는 폐기
5
수용 기준을 목업으로 대조한다
«같아 보인다»가 아니라 목업의 동작과 1:1로 맞는지. 숫자는 숫자로 확인

1. app_admins 직접 select — RLS로 0건 → 권한 영구 고착. app_admin_role() 경유
2. 마이그레이션 번호 추측 — 머지 시점 최신+1 재확인

## A. 지금 넣을 것 5개

### A-1. 머지 후 main push CI 확인 (§7 실행체인에 ⑧로 추가)

```bash
gh run list --workflow=ci.yml -L 1     # merge SHA 의 push CI
```

`merge-pr.mjs`가 보는 것은 **PR exact head**의 CI다. squash merge는 main에 **다른 트리**를 만들고,
그 커밋은 아무도 안 본다. 배포는 build+health만 보므로 `check.sh`를 다시 안 돌린다.
→ **배포 초록 ≠ main 초록.**

실제 사고(경영일지 PR #799→#881): PR diff는 base와 무충돌이었는데 그 PR이 **지운 파일 경로**를
화이트리스트형 검사가 아직 참조해서 머지 직후 main이 빨개졌다. diff 비교로는 안 잡힌다.
방치하면 다음 사람의 아무 PR이나 그 자리에서 실패해 원인 불명 혼란이 된다.
`failure`면 그 자리에서 후속 PR로 고친다.

### A-2. 배포 실패 분류 — revert 사유를 오판하지 마라

```
SSH 타임아웃 · 러너 IP 차단 · health 연결 실패   →  인프라.  재실행이 정답
build 실패 · health 5xx                        →  코드.    이때만 revert
```

경영일지 2026-08-09: **정상 배포가 러너 IP 차단으로 failure 표시된 사례가 하루 3건.**
여기에 revert를 걸면 멀쩡한 것을 되돌리는 것이다.
`AGENTS.md §5` "프로덕션이 깨졌다 → 즉시 revert"는 **화면·health가 실제로 죽었을 때**를 말한다.
워크플로 빨간불 자체가 아니다.

SSH는 짧은 간격 반복 시도로 차단된다(경영일지: 2분 3회 → 3번째부터 전면 차단). 재실행은 1회씩 간격을 둔다.

### A-3. `Changelog:` 한 문장

feat/fix squash 커밋 본문에 **최종 사용자가 이해하는 한 문장**을 넣는다. 기술 용어가 아니라 사용자 목소리로.
경영일지 커밋 제목이 그대로 그렇다:

```
feat(contact): 아직 미팅 안 잡은 영업기회가 계속 보여요 (#936)
```

없으면 나중에 "이번에 뭐가 바뀌었나"를 만들 때 커밋 로그를 다시 번역해야 한다. 그 비용이 매번 발생한다.

### A-4. 완료 증거는 작업 유형마다 다르다

배차할 때 아래에서 하나를 골라 못 박는다. 안 박으면 워커가 범위를 넘겨 일하거나 모자라게 일한다.

- **코드 PR** — PR번호 + merge SHA + 배포 run id + health + 화면 증거
- **운영 실행(코드변경 0)** — 워크플로 run id + 실측 대조표. **PR 없음**
- **읽기전용 조사** — 산출물 경로 + 실측값
- **PR 오픈까지가 범위** — PR번호 + CI run. **머지 여부를 물으면 오배송**

실행 못 한 검사는 `NOT_RUN` + 사유로 남긴다. NOT_RUN을 PASS로 올리지 않는다.

### A-5. 진단도구 자체가 버그일 수 있다

경영일지에서 **진단 스크립트가 틀렸던 사고가 3건**이고, 그 결과로 잘못된 수리가 실행됐다.
(후보 160건 중 152건이 검사기 오판이었던 사례 포함)

→ parity·드리프트·불일치 조사 결과를 받으면 **첫 질문은 "고쳐라"가 아니라 "측정기를 반증했는가"**다.
불일치를 성급히 한쪽 탓으로 단정하지 말고 양쪽을 각각 재측정한다.

## C. 역이식 — 모아워크가 더 나은 것

**`--self-test` 선행 습관.** (`scripts/check.sh`)

```
node scripts/check-customer-specific-values.mjs --self-test
node scripts/check-customer-specific-values.mjs
```

**검사기가 고장 났는지 먼저 증명하고 검사한다.** 경영일지에는 이 습관이 없고, 그래서 A-5의 사고 3건이 났다.
→ 경영일지 쪽 백로그로 가져간다.

다만 self-test가 형식적으로 통과하는 것을 막아야 한다. 최소 3요건:

1. **음성 대조** — 정상 1건 + **고장 주입 2건**(위반 코드 / 깨진 입력·빈 출력)을 고정 세트로.
   고장 1건이라도 미탐지하면 self-test 실패. 자기참조 assert만으로 통과 금지
2. **본체·테스트 동반 변경** — 검사 본체 diff 있음 + self-test diff 없음이면 CI 실패
3. **외부 오라클 분리** — 기대값을 검사 코드 내부 상수가 아니라 별도 골든파일에.
   검사기가 기대값을 동시에 생성하는 구조 금지

또 하나: `check.sh` 배너에 **"규칙은 두 파일뿐 · 이 배너에 규칙을 적지 마라"**를 박은 것.
"정본을 자칭하는 여섯 번째 사본"을 막는 좋은 장치다. 경영일지는 이 문제로 지금
`docs/architecture.md`가 ADR과 정면 충돌 중이다.

## D. 나머지 반례 3개 (경영일지에서 반복된 것)

- **"문서를 썼다"를 "실행했다"로 보고** — 1급 실패. 문서 산출물과 실행 산출물을 분리 발행하고,
  실행 주장에는 `실행 명령·대상 SHA·exit code·시각` 영수증을 붙인다. 영수증 없으면 미실행 판정
- **migration 파일 추가 = 운영 반영이라고 착각** — 경영일지 `deploy.yml`은 `DATABASE_URL` 주입만 하고
  `db:migrate`를 호출하지 않는다. 모아워크의 hosted migration 승인 잠금(`AGENTS.md`)이 같은 자리를 막는다 — 유지
- **파괴적 git 명령 체이닝** — `git status && … && git reset --hard`로 미커밋 WIP 유실(2026-07-19).
  `reset --hard`·`worktree remove --force`는 별도 호출 + 사전 확인

# ADR-0002 — 스키마 정본 판정 (001 vs 0002 충돌)

- 날짜: 2026-07-21 · 상태: **승인(오케스트레이터 판정)** · 긴급도: 높음(T02·T04·T05 블로킹)

> **⚠️ 부분 갱신(2026-07-21): 본 ADR의 "동적보드=Phase 3" 판단은 `ADR-0003`으로 대체**(사장님 결정: 임의보드 MVP 포함). **단 001 정본·`0002_core_crm.sql` 폐기 판정은 유효** — 임의보드는 0002가 아니라 `003`(기획 작성)으로 구현.

## 맥락
코드트랙 T02/T04/T05가 스키마 두 벌 공존 충돌 보고.
- **A `supabase/migrations/001_schema_v1.sql`** — 기획 v0.2가 확정한 SSOT. 정규화 CRM: `companies→pipelines→stages→deals→activities`, 커스텀필드 `field_defs`/`field_values`(13타입), 뷰 `saved_views`. (PG 파서 검증 완료)
- **B `supabase/migrations/0002_core_crm.sql`** — T02 독자 작성. 범용 EAV: `boards→items→board_columns→column_values`(6타입), `saved_views` 재정의.
- 충돌: ① `saved_views` 이중 CREATE(둘 다 적용 시 에러) ② 용어 상이(deals↔items, pipelines↔boards) ③ 커스텀타입 13 vs 6.

## 실측 (2026-07-21)
`supabase/migrations/`에는 **001_schema_v1.sql + 002_seed_policyfund.sql만 존재. 0002_core_crm.sql은 공유 레포에 없음**(T02 브랜치/워크트리 한정, 미머지). app/·lib/ 코드에 boards/items 참조 0건. → SSOT 무손상, 머지 전 판정 가능.

## 결정
- **정본 = A: `001_schema_v1.sql` + `002_seed_policyfund.sql`.**
- **폐기 = B: `0002_core_crm.sql`(및 boards/items/board_columns/column_values 범용 EAV 모델 일체). 머지 금지.**
- `saved_views`는 **001 정의가 정본**, B의 재정의 폐기.

## 근거 (이미 확정된 결정 — 신규 비즈니스 판단 아님)
1. **PLAN v0.2 §2**: 구현방식 **B(하이브리드 정규화)** 확정, 001이 SSOT(§5). 공용부(스키마)는 계약 → 트랙 독자 변경 불가.
2. **확정 D4**: "5단계 파이프라인 고정 + 커스텀필드·선택지·저장뷰만 자유. **먼데이급 동적보드는 Phase 3**." → T02의 boards/items = 동적보드 엔진 = **MVP 스코프 밖(Phase 3)**.
3. **플레이북 리스크 #6**("먼데이급 자유도의 유혹" → Phase 3 앞당김 금지).
4. 기술: 범용 EAV(`items`·`column_values`)는 RLS·집계·정산 수식(수수료·총매출·D+180/365)·타입안전이 모두 더 어렵고, 정책자금 4보드 고정 도메인엔 과설계.

## T01~T10 공통 기준 (한 줄)
> **모든 트랙은 `supabase/migrations/001_schema_v1.sql`(구조)+`002_seed_policyfund.sql`(정책자금 프리셋)만을 유일한 DB 정본으로 삼고, CRM 용어는 `companies·pipelines·stages·deals·activities` / 커스텀필드=`field_defs·field_values` / 뷰=`saved_views`로 고정한다. `boards·items·board_columns·column_values` 등 범용 EAV 모델과 트랙 독자 CREATE TABLE·신규 마이그레이션은 금지하며, 스키마 변경이 필요하면 기획 세션 합의 후 단일 선행 PR(001 개정 또는 003+)로만 반영한다.**

## 즉시 조치
- **T02**: `0002_core_crm.sql` 폐기(머지 취소). `core.crm`을 001의 `deals/stages`(+`_FOUNDATION.md`의 Repo 인터페이스)로 재작성. 먼데이 "보드"는 **화면 레이어**(스테이지 필터 뷰)로 재현 — 데이터 모델은 001 불변.
- **T04·T05**: 001 용어(`deals`·`field_defs`·`saved_views`)로 정렬.
- 파일 첨부 등 추가 테이블 필요 시 임의 마이그레이션 금지 → 기획 세션에 상신(001 개정 or 003 승인, 단일 선행).

## 결과
스키마 이원화 종결. 동적보드(범용 EAV)는 Phase 3 백로그로 보존(폐기가 아니라 시점 이동). 재발방지: 위 "한 줄 기준"을 dispatch/README 상단에 고정.

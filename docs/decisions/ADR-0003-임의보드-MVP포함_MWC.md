# ADR-0003 — 임의 보드 생성 MVP 포함 (D4 변경)

- 날짜: 2026-07-21 · 상태: **승인(사장님 결정)** · 관련: D4 변경, ADR-0002 일부 대체

## 맥락
사장님 결정: **사용자가 임의 보드를 새로 만드는 기능을 MVP에 포함.** 이는 확정 D4("먼데이급 동적보드는 Phase 3")를 변경한다. 단 제약: **001을 정본으로 유지**한 채 수용할 것.

## 검토한 선택지
1. **001 위에 generic boards 레이어를 003 마이그레이션으로 additive** — 001 무수정, typed 코어 보존. ← **채택**
2. 001을 확장해 `pipelines`를 범용 보드로 승격(전부 items/values EAV로) — **기각**: deals의 정산 수식(generated column)·RLS·업종팩이 EAV에서 붕괴, 001 대규모 재작성, "001 정본 유지" 지시와 배치.
3. 완전 통합(단일 board 모델) — Phase 3 이후 검토.

## 결정
- **채택 = 옵션 1 + 얇은 화면 통합.**
  - **정책자금 파이프라인**(신규고객→컨텍→업무→회계) = 계속 **001의 `deals`/`stages`/`settlements`(typed·수식·업종팩)**. 그대로 유지(ADR-0002 판정 유효).
  - **사용자 임의 보드** = 신규 **`003_boards_engine.sql`**(`boards`·`board_groups`·`board_columns`·`items`·`item_values`·`board_views`, EAV). 001의 `field_type` enum·`is_org_member`/`org_role`/`org_scope` 재사용, RLS 동일 규칙.
  - **화면 통합(app 레이어)**: 사이드바 보드 목록 = "정책자금 파이프라인(시스템 보드)" + "사용자가 만든 보드들" + [새 보드]. 데이터는 두 저장소로 분리, UX는 하나.
- **ADR-0002와의 관계**: 001 정본·`0002_core_crm.sql`(replace 시도) 폐기 판정은 **여전히 유효**. 임의보드는 `0002`가 아니라 **`003`(기획 세션 작성)** 으로 구현. ADR-0002의 "동적보드=Phase 3" 조항만 본 ADR로 대체.

## T01~T10 갱신 기준 (한 줄)
> DB 정본 = `001`(정책자금 typed 코어)+`002`(프리셋)+`003`(사용자 임의 보드 엔진). 정책자금 파이프라인은 `deals/stages`로 typed 유지, 사용자 임의 보드는 `boards/items`(003)로 구현하며, **스키마 변경·신규 마이그레이션은 기획 세션이 단독 작성**(트랙 독자 CREATE TABLE·EAV로 deals 대체 금지).

## 결과
- T02가 앞서 만든 boards/items(0002) 작업은 **폐기가 아니라 위치·역할을 003으로 바로잡아 재활용**. deals 코어는 불침범.
- 검증: `003` PG 파서 통과(6테이블·6정책). 런타임 RLS는 Supabase 적용 후 침투 테스트.

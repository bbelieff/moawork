# 코드세션 직접 전달용 프롬프트 — **T번호 기준**

> 2026-07-27 · MWC 작성 · **디스패치 경유 없음** — belie가 각 코드세션에 직접 붙여넣는다.
> 각 블록은 **단독으로 완결**되어 있다. 다른 문서를 안 읽어도 착수할 수 있게 썼다.

## ⚠️ 이름 정정 — C 라벨 폐기, **T01~T10이 정본**

MWC가 `C1~C5`라는 새 라벨을 만든 것이 혼선의 원인이었다. **폐기한다.**
아래 매핑이 정본이며, 앞으로 모든 문서는 **T번호로만** 부른다.

| 구 라벨 | **정본 트랙** | 작업 | 배정 근거(기존 트랙 계보) |
|---|---|---|---|
| ~~C0·C1~~ | **T03** | 진입 UX 3건(로고·pending 출구·승인 연결) + 회사 전환 스위처·아이콘 | T03 = `core.org`·RLS·OAuth·앱 셸 소유 |
| ~~C5~~ | **T01** | PostHog 연동(SDK·프록시·PII 차단·리플레이 마스킹) | T01 = 기반·공용부. `app/src/proxy.ts`가 공용 파일 |
| ~~C4~~ | **T07** | 플랫폼 어드민 콘솔 P0 + 활동지표 배치 | T07 = `mod.perf` 집계·지표 계보 |
| ~~C2~~ | **T06** | 알림 뱃지 + 소식창 | T06 = `mod.notify` 알림 모듈 |
| ~~C3~~ | **T08** | 지원 위젯 + 권한 위임 | T08 = standby였음(벤더 대기) → 신규 영역 배정 |
| — | **T10** | 상시 검수(게이트키퍼) | 변경 없음 |

**붙여넣는 순서**: **T03(최우선) → T01 → T07** 은 지금 병렬 가능 · **T06 → T08** 은 셸 이후.

제품 사용 분석(PostHog)을 붙인다. **고객 개인정보는 단 한 건도 내보내지 않는다.**

- 세션 리플레이 = **ON** (단 아래 마스킹 조건은 타협 불가)

■ 할 일
1) SDK 설치 + 리버스 프록시
   - 광고차단기·기업 방화벽 회피를 위해 **반드시 자체 도메인 프록시 경유**로 전송한다.
   - Next.js 16은 middleware가 proxy로 이름이 바뀌었다. **레포에 app/src/proxy.ts 가 이미 존재한다.**
     새로 만들지 말고 거기에 경로만 추가해라.
   - 프록시 경로명은 /analytics, /tracking, /telemetry, /posthog 같은 뻔한 이름을 쓰지 마라(차단당한다).
     예: /mw-sig
   - 엔드포인트는 US 리전(us.i.posthog.com).
   - 키는 환경변수로. 레포에 하드코딩 금지.

2) 이벤트 — 화이트리스트만 전송한다(자동 캡처 남발 금지)
   네이밍 규약: 영역.대상.행동 (소문자·스네이크)
     auth.login.succeeded
     org.workspace.switched
     crm.deal.created
     crm.deal.stage_changed
     settle.settlement.saved
     board.column.created
     support.thread.opened
     support.grant.approved
     admin.console.viewed
     admin.breakglass.started
   필수 속성: org_id · role · plan_tier · app_version

3) ★ PII 하드 금지 — 전송하면 안 되는 것
   ❌ 고객사명 · 대표자명 · 연락처 · 이메일 · 사업자번호 · 주소
   ❌ 금액(실행액·수수료·매출) · 계약 내용
   ❌ 홈택스 위임/수집 서류 관련 일체
   ❌ 사용자 이메일을 식별자로 사용 (→ 내부 UUID만 쓴다)
   허용: 내부 UUID · 역할 · 화면 경로(쿼리 파라미터 제거) · 이벤트명 · 소요시간 · 성공/실패 · 오류코드
   → 전송 직전에 통과하는 **스크러빙 함수**를 두고, 금지 키·패턴(사업자번호 정규식 등)을
     제거하도록 만들어라. 이 함수에 **단위테스트를 반드시 붙인다.**
     ※ MWC가 이 함수 초안을 dev-drop/ 에 내려줄 예정이다. 있으면 그걸 쓰고, 없으면 직접 만들어라.

4) 세션 리플레이 — ON이지만 아래는 필수
   - maskAllInputs: true
   - 고객명·사업자번호·금액이 표시되는 DOM에 data-pii 속성을 부착하고
     maskTextSelector 로 마스킹한다. **이 속성 부착이 실제 방어선이다.**
   - 회계/정산/홈택스 관련 화면은 **녹화 자체를 제외**한다.
   - 보존기간 30일로 설정.

5) 비용 가드
   - 무료 한도는 월 100만 이벤트다. 초과 조짐이 보이면 저가치 이벤트부터 샘플링한다.

■ 수용기준

- [ ] 금지 항목 전송 0 — **자동 테스트로 고정**(스크러빙 함수 테스트)
- [ ] 리플레이에 입력값이 노출되지 않는다
- [ ] 회계/홈택스 화면이 녹화되지 않는다
- [ ] 키가 레포에 없다

■ 금지
- PII 전송 · 이메일 식별자 · 프록시 없이 직접 전송 · 리전 임의 변경 · proxy.ts 새로 만들기

착수 시 워크로그에 [START · C5] 블록(무엇을/만지는 파일/안 만지는 것/산출물), 완료 시 [END · C5].

       요금제(플랜·좌석 사용/한도·과금 시작·다음 결제·결제수단·애드온 ON/OFF)
       계약(형태·계약일·담당·수수료 조건·계약서 링크)
       사용 규모(업체수·딜수·정산건수·저장용량·7일 쓰기·상태)
       멤버 목록(이름·이메일·역할·담당범위·마지막 로그인 + 역할 변경)
       이력(열람·문의·승인 기록)

   · 층위② 그 회사가 관리하는 업체 데이터(8,400여 건의 대표자·연락처·홈택스 서류)
       → 그 업체들은 모아워크와 계약한 적이 없다(재수탁). **열람 권한(고객 허용/break-glass) 필요.**
       → **홈택스 위임·수집 서류는 어느 경우에도 열지 않는다.**
   목업: docs/design/UI목업_어드민셸_고객사관리_v0.1.html 의 "고객사 상세" 절

2-e) ★ 어드민 관리 — belie가 직접 배정한다 (belie 요청 2026-07-27)

   추가 컬럼(번호는 최신 main 기준 배정): `level` · `added_by` · `added_at` · `revoked_at` · `note` · `last_seen_at`

   **등급 3단 — ★ 조회는 전원 동일(belie 확정 2026-07-27). 등급은 '실행'만 가른다.**
   | level | 조회 | 실행(쓰기) |
   |---|---|---|
   | `super` 최고관리자 | **전부** | 아래 전부 + **어드민 추가·제거·등급 변경** |
   | `operator` 운영자 | **전부** | 가입 승인/거절 · 요금제 변경 · 열람 요청/열람 · 문의 답변 · 내보내기 |
   | `viewer` 조회자 | **전부** | 없음(보기만) |

   → 어드민 화면에 표시되는 정보(고객사 상세·대표자·요금제·계약·**결제 원장·매출 지표**·
     접근 기록·문의)는 **등급과 무관하게 전원 조회 가능**하다. 화면·API를 등급으로 가리지 마라.
   → 예외 2가지만:
     ① **고객사의 고객 데이터**(업체 8,400건·홈택스) = 등급 무관, **열람 권한(고객 허용/break-glass)** 필요
     ② **내보내기(Export)** = `operator` 이상 (매출 원장 반출은 되돌릴 수 없다)
   → `user1@example.com` 은 `super` 로 마이그레이션(현재 role='owner' 값 이관).
   → `app_admin_role()` 반환을 등급까지 담도록 확장하거나 `app_admin_level()` 를 신설한다.
     **호출부는 계속 SECURITY DEFINER 함수만 쓴다 — 테이블 직접 select 금지(RLS로 0건).**

   - UI: 기간 [30분][2시간(기본)][오늘 안] · 범위 [보기만(기본)]/[보기+고치기] · 사유
   - **오너 승인 없이 즉시 발효.** 대신 아래 안전장치는 필수다:
       · 멤버가 개시한 위임은 **읽기 전용으로 고정**한다("보기+고치기"는 오너·관리자만 선택 가능)
       · scope=assigned 멤버가 위임하면 운영자도 **그 멤버 담당 건만** 볼 수 있다(RLS 상속)
       · 위임 즉시 **오너에게 알림**(숫자 뱃지)
       · 오너는 언제든 강제 종료 가능. 멤버는 자기 위임만 종료 가능
       · 회사당 활성 위임은 **1건**으로 제한
   - 위임이 살아 있는 동안 **고객 화면 상단에 고정 배너**:
     `🔓 운영자가 보고 있어요 · 남은 시간 1시간 42분 · [지금 중단]`
   - 만료·중단·종료를 **소식창(회사 소식)과 감사로그에 기록**한다.
   - **홈택스 위임·수집 서류는 위임 범위에서도 항상 차단**한다(재수탁 개인정보).

4) 테이블
   - access_grants(id·org_id·granted_by·grantee_admin·reason·mode(read|write)·
     granted_at·expires_at·revoked_at·revoked_by)
   - access_events(append-only 감사: grant_id·at·action(view|export|update|download)·
     target_table·target_id)
   - **RLS: 기존 is_org_member() 를 수정하지 마라.** has_active_grant(org_id) 를 만들고
     **OR 조건의 별도 정책**을 추가해라. 기존 격리 로직을 건드리면 조직 간 데이터 유출 사고가 난다.

5) 운영자 쪽 화면
   - /platform/지원 : 문의 목록 · 스레드 뷰 · [위임 요청 보내기] · 위임 상태 표시

## belie 사용법

1. 위 4개 블록을 **각각 다른 코드세션에 붙여넣기**.
2. **디스패치에는 아무것도 전달하지 않음.**
3. 붙여넣는 순서: **C5 → C4** (지금 병렬 가능) → 셸 작업이 끝나면 **C2 → C3**.
4. ⚠️ 공통 선행: **Production 로그인 권한 P0**(Owner도 "회사 역할 확인 중" 고착)가 안 풀리면
   C2·C3·C4 화면을 검증할 수 없다. 코덱스 0순위 건과 병행될 것.
5. MWC는 `dev-drop/` 에 완성 부품을 계속 내려준다 — 세션들은 서버·DB·배선에 집중하면 된다.

    테이블을 직접 select하면 0건 → 정확히 이 증상이 된다.)
3) 셸에 내비게이션 링크가 사실상 없다. /w/{slug} 화면의 <a> 태그는 총 4개이고

     006_public_workspace_entry.sql  vs  006_workspace_bootstrap.sql(+007_p0_authz_expand.sql)
   먼저 머지되는 쪽이 006을 갖고 나중 쪽은 리넘버링해라.

[1순위] C0 — 진입 UX 3건 (작지만 사용자가 실제로 막힌 곳)
 C0-1 로고 홈 링크
   - 로고를 <a>/Link로 감싼다. 로그인=/w/{현재slug}, 비로그인=/
   - aria-label="MoaWork 홈으로", 현재 홈이면 aria-current="page"
   - 잠긴 메뉴도 링크로 렌더하고 잠금은 시각+aria-disabled로 표현한다.
     도달 자체를 막으면 안내조차 못 한다.
 C0-2 요청 완료(pending) 화면의 출구 + 중복 차단
   - pending 화면 필수: 요청 요약(회사·종류·시각) / [요청 취소하기]
     / [다른 회사에 합류 요청] [새 회사 만들기] / [로그아웃] [도움 요청하기]
   - 중복 규칙: 같은 회사 재요청 → 새로 만들지 않고 기존 요청 상태를 보여준다
                다른 회사 추가 요청 → 허용(복수 대기 가능)
                회사 만들기 요청 → 1건만
                취소 후 재요청 → 허용, 이력은 감사로그
   - 서버에서 강제해라: (user_id, target_org_id, status='pending') 부분 유니크 인덱스.
     프런트 가드만으로는 새로고침·동시요청을 못 막는다.
   - 열거 방지는 유지한다. 없는 회사라고 알려주지 않는다.
 C0-3 승인/거절 — 연결 + 분기 시퀀스
   - 도달 경로 4개를 만든다:
     ① 요청 도착 시 오너에게 알림(숫자 뱃지) → 클릭하면 승인 화면으로 딥링크 (2클릭)
     ② 사이드바 '멤버관리'에 대기 건수 뱃지 (잠금 상태여도 뱃지는 보이게)
     ③ 홈 대시보드 상단 카드 "합류 요청 N건이 기다려요 [검토하기]"
     ④ /platform 개요에 전체 미처리 수
   - 분기 시퀀스:
     승인 → org_members 생성(역할=멤버, scope=assigned) → 요청자 알림+진입링크
            → 소식창·감사로그 → 요청자 다음 로그인 시 0클릭 진입
     거절 → status=rejected. 사유는 요청자에게 노출하지 않는다(열거 방지 계약과 일관)
            → 요청자에게 재요청/다른 방법 경로 제공 → 소식창·감사로그
     만료 → 14일 자동 만료, 만료 3일 전 오너 리마인드, 요청자에 만료 안내+재요청 경로
   - 승인 권한은 오너만 유지한다(현행 코드 그대로).
   - 동시성: 서버가 요청 상태를 재확인한 뒤 1회만 반영한다.
